## 1 · 背景

模板评估页（`gui/pages/prompt_eval_page.py`）下表「报告明细」已经有了双击跳题材页 + 单报告打分按钮，但**没有删除报告的入口**。主人在以下场景需要直接删：

1. **跑回测跑偏了**：参数选错，想清掉这份 backtest 重跑
2. **误生成报告**：模板调试期间产生的"垃圾"报告污染评估视图
3. **真实日常报告需要 redo**：换 prompt 后想删旧的真实日常报告

之前唯一的删除路径是手动 SQL 或者 `backtest_prompt.py --overwrite`（仅限同 prompt+date backtest），粒度粗、易误伤。本期补足 **按 `ai_reports.id` 精准删** 的链路。

## 2 · 需求与决策

主人 3 个关键决策（`ask_question` 确认）：

| 决策点 | 主人选择 | 理由 |
|--------|---------|------|
| 删除粒度 | **删整份报告**（ai_reports + theme_predictions(+CASCADE) + .md） | 与 backtest overwrite 行为对齐，DRY |
| 真实日常保护 | **双重确认**（弹窗 + 输入 id 末 4 位） | 不可逆操作，必须强保护 |
| 是否做 CLI | **新增** `tools/delete_report.py` | CLI-first 原则 + 远程 SSH 可用 |

## 3 · 架构与调用链

### 3.1 三层架构

```
┌──────────────────────────────────────────────────────────────┐
│ GUI 层  PromptEvalPage._on_delete_clicked                    │
│         ↓ 弹窗确认（backtest 单确认 / real 双重确认）            │
│         ↓ DeleteReportWorker(QThread, allow_real=...)        │
├──────────────────────────────────────────────────────────────┤
│ CLI 层  tools/delete_report.py                               │
│         ↓ --report-id  --allow-real  --dry-run  --no-md      │
├──────────────────────────────────────────────────────────────┤
│ 服务层  services/storage/ai_reports_store.delete_report      │
│         ↓ 1. SELECT 拿 file_path/is_backtest/prompt_id       │
│         ↓ 2. 防误删：is_backtest=0 且 allow_real=False → 抛   │
│         ↓ 3. DELETE theme_predictions WHERE report_path=?     │
│         │     (CASCADE → theme_stocks/news/scores/stock_scores) │
│         ↓ 4. DELETE ai_reports WHERE id=?                     │
│         ↓ 5. 物理 unlink data/AI_analysis/{file_path}.md      │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 调用关系（链条形式）

```
GUI 触发：
  PromptEvalPage._render_report_table (每行)
    └── _build_delete_button(data)          # 按 is_backtest 切样式/文字
         └── 点击 → _on_delete_clicked(rid, is_bt, data)
              ├── QMessageBox.question (第一道关)
              ├── (is_bt=0) QInputDialog.getText (第二道关)
              └── DeleteReportWorker.start()
                   └── delete_report(rid, allow_real=...) → DeleteResult
                        └── finished_result.emit({...}) → _on_delete_done
                             └── refresh()   # 重查表

CLI 触发：
  tools/delete_report.py
    └── _delete_one(rid)
         └── delete_report(rid, allow_real=..., dry_run=...) → DeleteResult
              └── _print_result(res)

回测 overwrite（DRY 复用）：
  backtest_one(overwrite=True)
    └── _delete_existing_backtest(template_id, trade_date)
         └── for each candidate rid: delete_report(rid, allow_real=False)
              # WHERE is_backtest=1 已过滤，allow_real=False 安全
```

## 4 · 关键实现

### 4.1 服务层 `delete_report`

`services/storage/ai_reports_store.py` 新增：

```python
@dataclass
class DeleteResult:
    ok: bool
    report_id: int
    file_path: str = ""
    is_backtest: int = 0
    prompt_id: Optional[str] = None
    report_date: Optional[str] = None
    ai_reports_deleted: int = 0
    theme_predictions_deleted: int = 0
    md_file_deleted: bool = False
    dry_run: bool = False
    error: Optional[str] = None


def delete_report(
    report_id: int,
    *,
    allow_real: bool = False,
    delete_md: bool = True,
    dry_run: bool = False,
) -> DeleteResult: ...
```

**输入 / 输出 / 用途**：

| 参数 | 类型 | 用途 |
|------|------|------|
| `report_id` | `int` >0 | `ai_reports.id`，必填 |
| `allow_real` | `bool` | 是否允许删 `is_backtest=0` 的真实日常报告（默认拒绝） |
| `delete_md` | `bool` | 是否同步 unlink `.md` 物理文件（默认 True） |
| `dry_run` | `bool` | 预演模式：只查会删什么，不动 DB / FS |

**异常合约**：
- `ValueError`：`report_id` 不存在 / ≤ 0
- `PermissionError`：`is_backtest=0` 且 `allow_real=False`

**关键 SQL 顺序**：

```sql
-- 1) 必须先删 theme_predictions（theme_predictions 没 FK 到 ai_reports，
--    只能靠 report_path 软关联；删了它才能 CASCADE 到 4 张子表）
DELETE FROM theme_predictions WHERE report_path = ?;
-- 自动级联：theme_stocks / theme_news /
--          theme_prediction_scores / theme_stock_scores

-- 2) 再删 ai_reports 本体
DELETE FROM ai_reports WHERE id = ?;

-- 3) 事务外物理删 md 文件（失败只 warning 不回滚 DB）
abs_path.unlink()
```

### 4.2 `backtest_prompt._delete_existing_backtest` 重构（DRY）

原本是 60 行直接写 SQL + 物理删 md，现在变成 30 行薄包装：

```python
def _delete_existing_backtest(template_id: str, trade_date: str) -> dict:
    # 1. SELECT 命中的 backtest 报告 id 列表
    candidates = [...WHERE is_backtest=1 AND prompt_id=? AND report_date=?]
    # 2. 循环调通用 API
    for rid, fp in candidates:
        res = delete_report(rid, allow_real=False, delete_md=True)
        # 累加 ar_n / tp_n / md_n
    return {"ai_reports": ar_n, "theme_predictions": tp_n, ...}
```

**好处**：删除策略**只有一处实现**（`delete_report`），GUI 单删 / CLI 单删 / 回测 overwrite 三个入口共享同一份 SQL 顺序 + 防误删逻辑 + 日志格式。

### 4.3 GUI 层（评估页下表）

**列变更**（`_REPORT_COLS`）：

| 旧布局 (15 列) | 新布局 (16 列) |
|---------------|----------------|
| ... 命中率(70) \| 打分(130) \| 文件名(stretch) | ... 命中率(70) \| **打分(110)** \| **删除(95)** \| 文件名(stretch) |

打分按钮缩窄 20px 给删除腾位置，文件名列依然 stretch。

**按钮样式（两态）**：

| `is_backtest` | 按钮文字 | 配色 | 二次确认 |
|---------------|---------|------|---------|
| `1` (回测) | `🗑 删除` | `#ff7875` 浅红 | **单次**确认弹窗 |
| `0` (真实) | `⚠ 删真实` | `#a8071a` 深红 | **双重**：弹窗 + 输入 id 末 4 位 |

**双重确认逻辑**（`_on_delete_clicked`）：

```python
# 第一道关：QMessageBox 列出 prompt/date/file/themes
reply = QMessageBox.question(...)
if reply != Yes: return

# 第二道关（仅真实日常）：QInputDialog 要求输入末 4 位
if not is_backtest:
    expected = str(report_id)[-4:]
    text, ok = QInputDialog.getText(...)
    if text.strip() != expected:
        QMessageBox.warning(... "输入不一致，已取消") ; return

# 启动后台 worker
DeleteReportWorker(report_id, allow_real=not is_backtest)
```

### 4.4 CLI 层 `tools/delete_report.py`

```bash
# 列出全部报告找 ID
python tools/delete_report.py --list

# 删 backtest 报告（默认）
python tools/delete_report.py --report-id 96

# 预演（不动数据）
python tools/delete_report.py --report-id 96 --dry-run

# 删真实日常（需显式 --allow-real）
python tools/delete_report.py --report-id 11 --allow-real

# 批量删
python tools/delete_report.py --report-id 96,97,98 --yes

# 只删 DB 行，保留 md
python tools/delete_report.py --report-id 96 --no-md

# JSON 输出（机器可读）
python tools/delete_report.py --report-id 96 --json
```

**退出码**：
- `0` 全部成功
- `1` 至少一项失败（含 PermissionError 拒绝）
- `2` 参数错误 / report_id 解析失败

**交互安全**：
- 非 `--dry-run` 默认进交互确认（脚本/CI 用 `--yes` 跳过）
- 真实日常被拒时会**结构化打印**错误（CLI 仍 exit 1，但其他成功项不受影响）

## 6 · 防误删设计要点

| 风险 | 防护层 |
|------|--------|
| **删错 backtest** | 弹窗列出 prompt/date/file/themes 详情 + Yes/No 默认 No |
| **误删真实日常** | 服务层 `PermissionError` 兜底 → CLI 必须 `--allow-real` → GUI 必须输入 id 末 4 位 |
| **批量误操作** | GUI 单次一个、CLI 批量需 `--yes` 跳过交互 |
| **md 文件丢失** | DB 删成功后才 unlink，且 unlink 失败仅 warning 不回滚 DB（不会出现"DB 有索引但文件没了" 的二次混乱） |
| **事务一致性** | `theme_predictions` + `ai_reports` 删除在同一个事务内（with conn 块），失败自动回滚 |
| **worker 并发** | GUI 内置 `_delete_worker.isRunning()` 检查，防止主人狂点 |

## 7 · 与回测 overwrite 的关系

| 行为 | 旧 (Phase 6 v3) | 新（本期） |
|------|----------------|-----------|
| `backtest_one(overwrite=True)` 删旧记录 | 60 行直接 SQL | 30 行循环调 `delete_report` |
| 删除粒度 | 按 `(prompt, date)` 一次过 | 按 `report_id` 一次一份 |
| 防误删 | WHERE `is_backtest=1` | WHERE + `allow_real=False` 双保险 |
| 日志格式 | `_delete_existing_backtest:` | 每份 `delete_report:` + 汇总 |
| 单元测试 | `test_backtest_e2e case_07/08` | + `test_scoring_eval case_14/15/16` |

回测 overwrite 的对外 API 行为**完全兼容**（`test_backtest_e2e 8/8` 全绿验证），只是内部实现下沉到了通用 API。

## 9 · 已知限制 & 未来工作

1. **批量删除 GUI 暂未做**：当前 GUI 一行一删，CLI 支持 `--report-id 96,97,98`。若主人需要 GUI 批量删（多选 checkbox），可单独提需求
2. **删除后未做"撤销"**：彻底物理删，主人三思（已有双重确认 + dry-run 兜底）
3. **真实日常报告"末 4 位"识别强度**：当 id < 1000 时退化为完整 id；并非完全防自动化脚本，但已能拦住手抖。如需更强可改 captcha 文本（如 prompt_id 后 6 字符）
