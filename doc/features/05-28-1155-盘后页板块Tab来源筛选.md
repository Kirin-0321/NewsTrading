**日期**：2026-05-28 11:55
**触发**：[2026-05-28 11:45 题材打分逻辑 v2 改造](../updates/05-28-1145-题材打分逻辑改造上线.md) 把 `fact_sector_daily` 从 ~480 行（单源 dc 概念）扩展到 ~1489 行（5 源），原"全部板块" Tab 一锅炖看不出门道，主人要求加分类筛选。

## 一、用户能看到什么

打开盘后数据页 → 板块 Tab，左上角"视图"下拉菜单从 **2 项**扩展为 **7 项**：

| 选项 | mode key | 行数 |
|------|---------|------|
| 📈 涨幅 Top 20 + 📉 跌幅 Top 10 | `split` | 上下分屏（不变） |
| 📋 全部 ~1489 个 | `all` | 5 源合并 |
| 🔵 dc 概念 ~486 个 | `src_dc_concept` | 仅东财概念板块 |
| 🔵 dc 行业 ~496 个 | `src_dc_industry` | 仅东财行业板块 |
| 🔵 dc 地域 ~31 个 | `src_dc_region` | 仅东财地域板块 |
| 🟢 ths 行业 ~90 个 | `src_ths_industry` | 仅同花顺行业 |
| 🟢 ths 概念 ~386 个 | `src_ths_concept` | 仅同花顺概念 |

数字会**按当日真实数据**动态刷新（不是写死），切换日期时自动同步；当日无数据时显示 `~0 个`。

### 2.3 CLI 层（`tools/query_all_sectors.py`）

按 `cli-first-development.mdc` 规则同步扩展：


## 四、决策记录

- **为什么不做双 ComboBox**（视图 × 来源两层下拉）：split 模式下"来源"无意义（Top 20/Bottom 10 本就跨源），双 ComboBox 会有非法组合，UI 复杂度抬升一档；KISS 派一个 ComboBox 7 选项最干净。
- **为什么数字是动态而非写死**：板块字典每月可能微变（Tushare 偶尔加新概念），写死会和实际显示行数不一致引发主人疑惑；动态查询单次 < 50ms，不值得为这 50ms 牺牲准确性。
- **为什么用 idx_type 不用 src**：`src` 取值仅 `dc/ths` 二元（粒度太粗），`idx_type` 是 5 元（粒度刚好对应 5 个 Tushare 接口），主人想看"dc 概念 vs ths 概念"差异时 src 拆不出来。
