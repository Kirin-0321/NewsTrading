# AI 分析页面 · 盘后总结自动填入

> 时间：2026-05-27 00:20
> 触发：主人指令「现在 AI 分析页面中盘后总结改成能自动填写上一个交易日的数据」
> 涉及：`gui/utils/market_db_helper.py`（新工具函数）+ `gui/pages/ai_analysis_page.py`（showEvent 触发）

---

## 一、需求

主人在 AI 分析页面手填「盘后总结」太啰嗦。新行为：

1. **进入页面时**自动填入「最近一个已收盘交易日」的盘后总结 MD
2. 仅在 `summary_input` 为空时填（不覆盖主人手动输入）
3. 边界规则：
   - 每天下午 4 点（16:00）为分界线
   - **< 16:00** → 候选日 = 昨天（今天数据未收盘）
   - **≥ 16:00** → 候选日 = 今天（已收盘）
   - 周六 / 周日 / 节假日 → 自动回退到上一个开市日
   - 举例：5-27 凌晨 → 取 5-26；5-30（周六） → 取 5-29 周五

## 二、设计决策（与主人确认）

| 问题 | 选项 | 主人选择 |
|------|------|---------|
| 触发时机 | A 进入页面 / B 点击开始分析 / C 双保险 | **A**（直观可见可修改）|
| 找不到目标日数据时 | 向前回退到最近有数据的日 / 保持空 + 提示 | **保持空 + placeholder 提示**（主人决定回退路径）|
| 自动填入后是否加标记行 | 加 `# 自动填入：xxx` / 不加 | **不加**（保持 summary_md 原貌，避免污染 AI prompt）|

## 三、实现

### 工具函数 · `gui/utils/market_db_helper.py`

**`last_settled_trade_date(now=None) -> Optional[str]`**

- 输入：可注入的 `datetime`（测试用），省略则取 `datetime.now()`
- 算法：
  1. `candidate = now if now.hour >= 16 else now - timedelta(days=1)`
  2. SQL: `SELECT trade_date FROM dim_trade_calendar WHERE trade_date <= candidate AND is_open=1 ORDER BY trade_date DESC LIMIT 1`
- 输出：`YYYYMMDD` 或 `None`（dim_trade_calendar 表为空）

**`get_cached_summary_md(trade_date) -> Optional[str]`**

- SQL: `SELECT summary_md FROM market_summaries WHERE trade_date = ?`
- 输出：完整 compact Markdown 或 `None`（该日还没跑 market_fetch）

### UI · `gui/pages/ai_analysis_page.py`

- `__init__`：加状态标志 `_summary_auto_filled_with_data = False`
- `showEvent`：尾部追加 `self._auto_fill_market_summary()`
- 新方法 `_auto_fill_market_summary()`：
  - 状态守卫 1：已成功填过 → 跳过（避免每次切 tab 都覆盖）
  - 状态守卫 2：summary_input 当前有内容 → 跳过（不覆盖主人手输）
  - 算出 `td = last_settled_trade_date()`，None 则更新 placeholder
  - 取 `md = get_cached_summary_md(td)`，有则 `setPlainText` 并置 `_summary_auto_filled_with_data = True`
  - 无则更新 placeholder 提示主人去跑 `python tools/market_fetch.py {td}`

## 四、边界 case 验证

在 5-26 23:00 实际环境跑（dim_trade_calendar 覆盖到 20260526）：

| 模拟时间 | 候选日 | 表里命中 | 实际返回 | 符合预期 |
|----------|--------|---------|---------|---------|
| 现在（5-26 实时夜里）| 5-26 | 5-26 开市 | **20260526** | ✅ |
| 5-27 02:00 周三凌晨 | 5-26 | 5-26 开市 | **20260526** | ✅ |
| 5-27 09:30 周三上午 | 5-26 | 同上 | **20260526** | ✅ |
| 5-27 15:59 周三下午 4 点前 | 5-26 | 同上 | **20260526** | ✅ |
| 5-27 16:00 周三下午 4 点 | 5-27 | 5-27 暂未在表 → 回退 5-26 | **20260526** | ✅ |
| 5-27 22:00 周三晚 | 5-27 | 同上 | **20260526** | ✅ |
| 5-25 09:00 周一上午 | 5-24（周日）| 非开市 → 回退到 5-22 周五 | **20260522** | ✅ |
| 5-25 20:00 周一晚 | 5-25 周一 | 5-25 开市 | **20260525** | ✅ |
| 5-30 11:00 周六 | 5-29 周五 | 测试环境 5-29 暂未拉 → 回退 5-26 | **20260526** | ⚠️ 测试环境特性 |

> ⚠️ 最后一条：dim_trade_calendar 是按需扩展的，5-27 之后还没人调 resolve_trade_date 拉新一周。**生产路径**没问题：主人在 5-27 跑过 market_fetch 后，日历会自动刷到 5-27，下次 GUI 打开就能正确回退到 5-29 周五。

## 五、failure mode 对照

| 状态 | placeholder 行为 |
|------|------------------|
| `dim_trade_calendar` 表完全空 | 「未找到交易日历缓存，请先打开【盘后数据】页面…」|
| 日历有，但目标日 market_summaries 无缓存 | 「未找到 20260527 的盘后总结缓存。请先执行：python tools/market_fetch.py 20260527」|
| 主人删空 summary_input 后切 tab 回来 | 不重填（`_summary_auto_filled_with_data` 已 True），主人可继续手输 |
| 主人想强制刷新自动填入 | 重启 GUI（或下次首次进入页面）|
