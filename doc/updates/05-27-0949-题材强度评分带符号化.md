# 题材强度评分带符号化（v3 schema）

> 时间：2026-05-27 09:49  
> 起因：主人讨论题材回测打分算法时，发现现有 `strength_score` (0-100) + `sentiment` (利好/利空/中性) 两个字段语义重叠，决定合并为带符号的统一评分。  
> 状态：主人已决策，待辉夜按施工文档（[.huiye/_施工_题材强度带符号化.md](../../.huiye/_施工_题材强度带符号化.md)）落地。

---

## 一、为什么要改

现有 `theme_predictions` 表里有两个字段表达"题材属性"：

| 字段 | 表达内容 | 取值 |
|------|---------|------|
| `strength_score` | 强度（多大影响） | 0 ~ 100 |
| `sentiment` | 方向（看多/看空） | 利好 / 利空 / 中性 |

存在三个明显问题：

1. **下游打分公式啰嗦**：要先看 `sentiment` 决定正负号，再乘 `strength_score`
2. **AI 容易自相矛盾**：可能输出 `strength_score=85` + `sentiment="利空"`，下游不知道是"利空兑现概率高"还是"利好程度高"
3. **排序混乱**：题材列表按 `strength_score` 排序时，强利好和强利空挤在一起

**改用带符号方案后**：一个字段表达「方向 + 强度」两层含义，简单直接。

---

## 二、新规范

### 1. `strength_score` 取值范围与语义

| 区间 | 含义 | 等级标签 | emoji |
|------|------|---------|-------|
| +80 ~ +100 | 极强利好 | 极强利好 | 🔴 |
| +60 ~ +79 | 强利好 | 强利好 | 🟠 |
| +40 ~ +59 | 中等利好 | 中等利好 | 🟡 |
| +20 ~ +39 | 弱利好 | 弱利好 | 🟢 |
| -19 ~ +19 | 中性 / 钝化题材 | 中性 | ⚪ |
| -20 ~ -39 | 弱利空 | 弱利空 | 🟢 |
| -40 ~ -59 | 中等利空 | 中等利空 | 🟡 |
| -60 ~ -79 | 强利空 | 强利空 | 🟠 |
| -80 ~ -100 | 极强利空 | 极强利空 | 🔵 |

> 利空也用同一套阶梯（🟢🟡🟠），但最强一档用 🔵 与 🔴 形成"红利好 / 蓝利空"的视觉对照。

### 2. 字段去重决策

| 字段 | 处理 | 理由 |
|------|------|------|
| `strength_score` | 改范围 -100 ~ +100 | 主信号 |
| `strength_level` | 保留，扩展 9 档枚举 | UI 友好（带 emoji） |
| `sentiment` | **彻底删除** | 与 `strength_score` 正负号完全重复 |
| `is_cold` | 保留 | 「钝化」是状态属性，独立于方向+强度 |

### 3. 钝化题材（`is_cold=1`）举例

`is_cold` 与 `strength_score` 是两个维度，不冲突：

- 黄金题材 `is_cold=1, strength_score=+30`：弱利好但已发酵过，不期待大幅上涨
- 中东冲突 `is_cold=1, strength_score=-30`：弱利空但已经反应过

## 三、对下游打分系统的简化

主人之前的设想（plan M3.2 里的方案）：

```
directional_pct = pct_chg × (+1 利好 / -1 利空 / 0 中性)
weight = (strength_score / 100) × DCG(rank)
```

**改后简化为**（单行公式）：

```
贡献度 = pct_chg × (strength_score / 100) × DCG(rank)
```

举例验证：

| 题材 | strength | 实际涨跌 | 贡献度 |
|------|----------|---------|--------|
| 强利好预测 + 实际上涨 | +85 | +5% | `+5% × 0.85` = +4.25%（重奖） |
| 强利空预测 + 实际下跌 | -70 | -3% | `-3% × -0.70` = +2.10%（兑现，奖正分） |
| 强利好预测 + 实际下跌 | +85 | -5% | `-5% × 0.85` = -4.25%（重罚） |
| 中性预测 + 任意涨跌 | +10 | ±5% | `±5% × 0.10` ≈ 0.5%（影响极小） |

逻辑天然自洽：方向准 → 加分，方向错 → 减分，中性 → 影响极小。

## 五、历史数据处理

**决策：清空 theme_predictions / theme_stocks / theme_news 三张表**。

理由：

1. 现有题材数据量小（5/26 之前积累的几份报告，估计 < 50 个题材）
2. 旧数据是按旧 prompt（`strength_score` 0-100）抽的，质量与新规范不对齐
3. SQL 迁移容易留隐性 bug（如部分 sentiment="利好" 但 score 较低的题材，转完不知该归到哪档）
4. 借助 schema 指纹机制自动 DROP 重建，零迁移代码

**实现方式**：升级 `_THEME_V2_COLUMNS` → `_THEME_V3_COLUMNS`（去掉 `sentiment`）。  
现有 [services/storage/database.py:175-200](../../services/storage/database.py) 的指纹比对逻辑会自动检测列差异 → DROP TABLE → 按新 schema 重建。三张表（theme_predictions / theme_stocks / theme_news）受同一个机制保护。

## 六、给 AI 的新 prompt 说明文（草稿）

替换 [prompts/theme_extraction/extract_themes.md](../../prompts/theme_extraction/extract_themes.md) 第 23 行附近：

```
"strength_score": -100 到 +100 整数（必填）。符号表示方向，绝对值表示强度：
    正数（+1 ~ +100） = 利好题材，数字越大利好越强
    负数（-1 ~ -100） = 利空题材，绝对值越大利空越强
    接近 0（-19 ~ +19）= 中性 / 钝化题材，方向不明显或已发酵过

    打分参考（按绝对值）：
        🔴 极强 80-100：明确主线、龙头连板、政策催化重大
        🟠 强   60-79：板块明显异动、有龙头标的
        🟡 中   40-59：有催化但未形成主线
        🟢 弱   20-39：边缘机会或防御方向
        ⚪ 中性 -19 ~ +19：钝化或无明确方向
```

同时**删除** `"sentiment"` 字段的所有说明（schema 表、抽取规则第 5 条都要清）。
