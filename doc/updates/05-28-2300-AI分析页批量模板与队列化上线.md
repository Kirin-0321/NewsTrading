## 四、关键技术决策

### 4.1 `finished_result` 替代 `finished`

旧版 `AIAnalysisWorker.finished = pyqtSignal(dict)` 与 `QThread.finished()`（无参）**同名重载**。在 PyQt5 中，子类 `pyqtSignal` 会**覆盖** QThread 自带的同名无参信号。

后果：

- 业务 finished 只在 `result.ok=True` 时 emit；失败/取消时根本不 emit
- manager 用 `worker.finished` 接调度信号将永远收不到失败任务的「线程结束」通知
- `_running` 集合永远不摘除该 task_id，达到 max_concurrent 后队列死锁

**修复**：worker 改名 `finished_result`（仿 `ManualBacktestWorker`），且**所有终态**（成功/失败/取消）都 emit；`QThread.finished()` 由 manager 独占用于调度。

### 4.2 task_finished 信号去重

worker 失败路径会**同步 emit** `error` + `finished_result` 两个信号，对应 manager 两个槽都想 emit `task_finished`。GUI 收两次不致命但浪费。

**修复**：`AnalysisTask._finished_emitted: bool` 守护 + `_emit_finished_once` helper，保证每个 task 恰好 emit 一次。case_13 专门回归此场景。

### 4.3 默认时间范围 = 上一收盘日 14:00 至今

`range_preset_combo` 把「上一收盘日 14:00 至今」放第一位 + 默认选中；`showEvent` 时若仍是默认选项，主动调一次 `_on_range_preset_changed()` 让起止时间立刻应用主人语义（避免主人首次进入页面看到陈旧的初始化时间）。

`_last_trading_close_14()` helper 保持旧版规则：

- 今天是交易日且当前 ≥ 14:00 → 今天 14:00
- 否则回溯最近一个早于今天的交易日 14:00（自动跳过周末）

### 4.4 默认盘后总结

保留旧版 `_auto_fill_market_summary` + `_summary_auto_filled_with_data` 守护逻辑：

- `showEvent` 时若 `summary_input` 为空 → 调 `last_settled_trade_date()` + `get_cached_summary_md()` 自动填入
- 主人手动输入后不再覆盖

## 六、信号链

```
AIAnalysisWorker (子线程)
    progress.emit(msg)        ─┐
    streaming.emit(chunk)     ─┤
    finished_result.emit(dict)─┼─→ AnalysisTaskManager (主线程)
    error.emit(err)           ─┤      relay signal (QueuedConnection)
    cancelled.emit()          ─┘      → _on_worker_xxx 槽
    QThread.finished()        ─→ _relay_qthread_done → _pump 下一个 PENDING

AnalysisTaskManager (主线程)
    task_added(int)           ─┐
    task_started(int)         ─┤
    task_progress(int, str)   ─┼─→ AIAnalysisPage 槽
    task_streaming(int, str)  ─┤      （仅当 task_id == _current_task_id
    task_finished(int)        ─┘       才刷下方进度/结果区）
    task_removed(int)         ─→ 删 task_table 行
```
