## 算法层变化

### 1. 利空 / 中性题材完全跳过

* **入口**：`services.scoring.script_scorer.score_theme_on_date` 对 `strength_score ≤ 0` 题材 raise `SkippedTheme` 异常
* **service 层**：`scoring_service` 静默捕获 `SkippedTheme`，不计入失败统计
* **聚合层防御**：4 处聚合 SQL 在 WHERE 子句保留 `strength_score > 0` 防御性过滤

### 2. 命中率新公式（α 自适应阈值 + 4 层金字塔）

```
标的级 is_hit = 1  iff  (pct_chg − zz1000_pct) > strength_score / 20
标的命中率 = 命中天数 / 有效天数     ← 有效天数 = is_hit IS NOT NULL 的天数
题材命中率 = 题材内所有标的命中率均值
报告命中率 = 报告内 strength>0 题材命中率均值
模板命中率 = 模板下所有报告命中率均值
```

### 3. 方向准确性新公式（累乘累计判定）

```
累计数 = ∏ (1 + theme_pct_i / 100)   对该题材从 D+1 累乘到当前 score_date
题材方向 = 1 iff 累计数 > 1，否则 0
（NULL theme_pct 行视为因子 1 跳过；全 NULL 时 = NULL）

报告方向 = 报告内 strength>0 题材累计方向（1/0）均值
模板方向 = 模板下所有报告方向均值
```

* `theme_prediction_scores.direction_correct` 字段语义切换：原"strength 与 sector_pct 同号"，新"D+1..D+N 累乘 > 1"
* **二阶段写入**：score_theme_on_date 先 INSERT 当前 D+N 行（direction=NULL），再读取 D+1..D+N 全部 theme_pct 累乘判定，再 UPDATE 当前行的 direction_correct

### 4. 题材排序

`get_theme_eval_for_report` 新排序：

```sql
ORDER BY tp.strength_score DESC,
         (priority_rank IS NULL) ASC,
         tp.priority_rank ASC,
         tp.id ASC
```

GUI 表头点击换列排序能力保留。

## 主人手动操作步骤（必读）

⚠️ **本次改动是非破坏性 schema 改动**：字段不增不删，仅语义切换。但**旧打分行**（按旧口径写入的）需要清空避免新旧口径混算。

```powershell
# 1. 先干跑看数量
python tools\purge_scoring_data.py --dry-run

# 2. 真删（自动备份到 data/backups/）
python tools\purge_scoring_data.py
#    输入 yes 确认

# 3. 立即重打全部历史数据（可选；不跑也可，下次调度 17:00 会自动跑）
python tools\rescore_unfinished.py
```

清空后下次调度会自动按新口径填回。GUI 打开评估页即可看到新口径数据。
