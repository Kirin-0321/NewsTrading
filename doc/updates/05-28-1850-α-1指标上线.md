## 一、需求与动机

| 项 | 内容 |
|---|---|
| 痛点 | 报告 D 日发布后，**D+1 易因开盘竞价被挂高/挂低**，导致首日 α 失真 |
| 解决思路 | 新增 α-1 指标：**剔除 D+1 后**对 D+2~D+5 的 α 求均值，并把基准从上证综指换成**中证1000**（更贴小盘股题材） |
| 与原 α 关系 | **并列展示，不替换**——原 α（上证综指、5 天均值）保留 |

---

## 二、口径定义

### 单日基准列（落库）

新增字段 `theme_prediction_scores.benchmark_zz1000_pct`：每日中证1000（`000852.SH`）当日 `pct_chg`。
原始数据，**不存衍生 α**。

### 衍生 α-1（聚合层 SQL 推导）

```
题材级：
    α-1(theme) = AVG over D+2..D+5 of (theme_pct - benchmark_zz1000_pct)

模板级 / 报告级：
    α-1(prompt) = AVG over themes of α-1(theme)
    α-1(report) = AVG over themes of α-1(theme)
```

**`AVG` SQLite 语义自动忽略 NULL**，所以：
- D+1 行的 CASE 整体返回 NULL → 不参与
- benchmark_zz1000_pct 缺数据 → 不参与
- theme_pct 缺数据 → 不参与

口径与现有 `alpha_avg`（5 天均值、上证综指、外层简单 AVG）完全平行，方便对比。

## 五、对主人的操作建议

**当前环境 `theme_prediction_scores` 为空**（48 份 ai_reports 但还未抽题材打分），因此：

1. ✅ 新打分会自动写 `benchmark_zz1000_pct`，无需任何动作
2. ⚪ 若未来从其他环境同步数据库带入了**老的打分行**（zz1000 列为 NULL），跑：
   ```bash
   python tools/backfill_benchmark_zz1000.py --dry-run   # 先看影响范围
   python tools/backfill_benchmark_zz1000.py             # 真回填
   ```
3. ⚠ 若 backfill 报 `missing_dates` 非空，先跑 `python tools/market_fetch.py <YYYYMMDD>` 把对应日的中证1000 行情同步过来（`tushare_fetcher` 已配置 `000852.SH`），再重跑回填
