# 手动回测·批量模板 × 批量交易日 + 并发可调上线

**日期**：2026-05-28 17:40
**影响范围**：`gui/pages/manual_backtest_page.py`、`gui/workers/manual_backtest_manager.py`、`tools/test_manual_backtest_queue.py`
**主人原话**：「手动回测页面添加批量选择模板，再批量选择交易日进行回测。最终回测数量就是模板数x天数。另外增加并发数量，还有去掉8000字限制」

---

## 一、动机

之前手动回测页只能 **1 模板 × 1 交易日** 单跑，主人想批量造样本、横评模板时得连点 N 次。
评估页又老抱怨样本太少，看了眼 `tools/backfill_backtest_samples.py` 已经有"M 模板 × N 天笛卡尔积"能力，但走 CLI 不直观，主人用 GUI 不顺手。

→ 直接把 CLI 的批量能力搬到 GUI 上，顺便把 8 路并发的硬编码暴露成可调 spinbox，再去掉 md 预览的 8000 字截断。

## 二、变更点

### 1. UI 重构（`manual_backtest_page.py`）

| 旧 | 新 |
|---|---|
| 模板 `QComboBox` 单选 | `QListWidget` 多选（复选框模式）+ 全选/全不选按钮 + "已选 N / 共 M" 计数 |
| 交易日 `QDateEdit` 单选 | (开始 ~ 结束) 两个 `QDateEdit`；自动调 `trade_dates_between` 算交易日数（自动排除今天）；显示 "（N 个交易日: 起~止）" |
| 时间窗永远可调 | 单日时可微调；多日批量时灰掉，提示"强制默认窗" |
| 并发数硬编码 8 | 第 4 行加 `QSpinBox`（1~64，默认 8），运行时联动 manager |
| md 预览截断 8000 字 | 完整显示 |
| run 按钮 = 入队 1 个 | run 按钮 = 笛卡尔积 N 个；任务数 ≥ 5 弹确认框 |

### 2. Manager 加运行时调并发能力（`manual_backtest_manager.py`）

新增 3 个对外 API：

```python
class BacktestTaskManager(QObject):
    MAX_CONCURRENT_HARD_CAP: int = 64        # 新：硬上限常量（17:55 hotfix 16 → 64）

    def get_max_concurrent(self) -> int: ...   # 读当前并发数
    def set_max_concurrent(self, n: int) -> int:
        """运行时调整并发上限。
        - 调大 → 立即 _pump 拉 PENDING 上 RUNNING
        - 调小 → 不强杀 RUNNING，等自然结束后停止派新单
        - 入参超出 [1, HARD_CAP] 自动 clamp，返回实际生效值
        """
```

对应回归测试 3 个新用例：

- `case_12_set_max_concurrent_grow`：max=2 / 5 任务 → 调到 5 → 立即全部 RUNNING
- `case_13_set_max_concurrent_shrink`：max=4 / 4 RUNNING → 调到 1 → 4 个不强杀 + 新加的 PENDING 不被派
- `case_14_set_max_concurrent_clamp`：clamp(0/-100/cap+50) → 1/1/cap

## 四、已知约束

- **并发硬上限 16**：超过没意义（DeepSeek 限频 / SQLite WAL / `backtest_one` 内部市场缓存争用），spinbox 直接拦死
- **多日批量强制默认窗**：每个交易日的 `next_open` 不同，让主人逐日微调时间窗 UI 会爆炸；要逐日精调请用 `tools/backtest_prompt.py` 单跑
- **今天会被自动排除**：`next_open 09:00` 必然在未来 → backtest_one 会拒掉，提前过滤更干净
- **md 完整渲染**：超长报告（10w+ 字）QTextBrowser 会卡，但常规一份 backtest md 在 5w 字以下，实测无压力
