## 一、起因

主人发现：评估页顶栏只有「🔁 重打分（按筛选范围）」一个**重型按钮**——
它会调 `rescore_range` 无差别覆盖范围内**所有题材**（含已 `full` 的报告），
日常仅仅想「补齐没打完那几份」时，重打全集既浪费市场 API 配额、又会
对算法/字段没变的旧数据做无用 INSERT OR REPLACE。

而下表行内的「⚡ 初次打分 / 🔄 续打」按钮虽然语义精准（仅动该 report
对应的题材），但每次只能点一份；当一周累积十几份未打完报告时，主人
得手动一份份点，烦。

需要一个「一键全部续打/初次打分」按钮：扫当前筛选范围，挑出
`score_status ∈ {none, partial}` 的报告，逐个调 `rescore_one_report`
增量补齐；已 `full` 的完全不动。

## 二、主人 3 项决策（已锁）

| Q | 决策 |
|---|---|
| Q1 作用范围 | **始终扫当前时间范围全部模板**，不受上表选中模板影响（更通用） |
| Q2 按钮位置 & 文案 | 放在「🔁 重打分」**左侧**，绿色 SUCCESS，文案「⚡ 一键打分未完成」 |
| Q3 无题材报告处理 | **静默跳过**（行内按钮原本就是禁用态，CLI/GUI 一致） |

## 三、改动清单

### 1. service 层 · `services/scoring/scoring_service.py`

* 新增 dataclass `BatchUnfinishedResult(BatchScoringResult)`，加 3 个
  报告维度计数：`reports_targeted` / `reports_done` / `reports_skipped`。
  其中 `reports_skipped` 包含两种情况——预查时 `report_id` 异常的、
  执行 `rescore_one_report` 时被异常跳过或返回 `themes_scored=0` 的。
* 新增公开函数 `rescore_unfinished_reports(*, days, time_dim,
  is_backtest_filter, days_back, hit_threshold_pct, benchmark_ts_code,
  score_date_override)` →
  - 调 `get_report_eval(prompt_id=None, ...)` 拿候选名单
  - 过滤 `score_status ∈ {none, partial}` 且 `themes_count > 0`
  - 逐个调 `rescore_one_report`，单报告异常不阻断后续
  - 跨报告累计 themes / pairs / days_covered / errors
  - 返回 `BatchUnfinishedResult`

### 2. CLI 入口 · `tools/rescore_unfinished.py` 【新增】

薄壳：argparse 解析 `--days / --time-dim / --is-backtest / --days-back /
--hit-threshold-pct / --benchmark / --score-date-override / --json` →
调 `rescore_unfinished_reports` → 打印或 JSON 输出。
退出码：0 全绿 / 1 有 errors / 2 参数错误。

满足 `cli-first-development.mdc` 强制要求：service 公开方法必须有
对应 CLI 入口。这个 CLI 同时给后续凌晨补齐定时任务用。

### 3. GUI worker · `gui/workers/rescore_worker.py`

* 三模式互斥（之前 2 模式）：构造参数 `report_id` /
  `unfinished_filter` / `(report_date_start, report_date_end)`
  恰好传一个，否则 `ValueError`。
* 新增 `_run_unfinished()` 方法：透传 filter 给
  `rescore_unfinished_reports`，把 `BatchUnfinishedResult` 全部字段
  转成 dict（含 mode='unfinished' / reports_targeted/done/skipped）
  发 `finished_result`。

### 4. GUI 页面 · `gui/pages/prompt_eval_page.py`

* 控制条 row2 加 `batch_score_btn`：「⚡ 一键打分未完成」绿色，
  位置在 `rescore_btn`（红色重打分）**左侧**。
* 新增 `_on_batch_score_unfinished()` 处理函数：
  1. 互斥：已有打分线程 → MessageBox 提示
  2. 预扫一次 `get_report_eval` 算候选数 / 题材合计 / none/partial 拆分
  3. 候选 = 0 → 提示"无需补齐"直接返回，不弹确认
  4. 弹 question 弹窗带 候选数 + 涉及题材合计 + 真/回测 label
  5. 启动 `RescoreWorker(unfinished_filter=...)`，挂 stage / finish / error
* `_set_buttons_busy(busy)` 加 `batch_score_btn`。
* `_on_rescore_done(res)` 加 `mode == "unfinished"` 分支：
  状态栏显示 `✅ 一键打分未完成完成: 报告 N/M（跳过 K）: 题材 X / 对 Y/Z ...`。
* 顶部 docstring 同步更新：UI 布局图加新按钮、新增「按钮区分」段
  说明绿/红两按钮的语义差异、调用链补 `_on_batch_score_unfinished()` 路径。

## 五、风险登记

| 风险 | 概率 | 缓解 |
|------|------|------|
| 一键扫到几十份报告耗时较长 UI 卡住 | 低 | QThread 异步 + stage 实时回报 + busy 状态封锁所有交互按钮 |
| 单报告异常导致整批中断 | 低 | service 层每个 report 独立 try/except，errors 累加但不抛出 |
| `themes_count=0` 报告被误打 | 已规避 | 候选过滤显式 `themes_count > 0` |
| 已 `full` 报告被误重打 | 已规避 | 候选过滤显式 `status ∈ {none, partial}`；UI 也表现为该 report 不被纳入候选数 |
