## 一、本次解决的痛点

主人 21:30 反馈截图：评估页 5 月 26~27 日的回测报告满屏「✗ 无题材」灰色禁用按钮，每份报告要切到预测题材页手选 .md 单文件抽取——14 份报告 = 14 次切页 + 14 次选文件 + 14 次串行等待。

**改造目标**：把评估页从"只读清单"升级为"调度台"，并把预测题材页升级为"队列化抽取流水线"。

## 三、关键技术决策（来自施工方案 §二）

### 3.1 新造 manager 不抽公共基类

`BacktestTask` / `ThemeExtractTask` 字段差异大（前者 8 字段含 trade_date / news 时间窗 / dry_run，后者 4 字段仅 path/provider/model/result），强行抽公共基类反而模糊语义。两套 manager 的纯通用部分（5 态机 + 并发池 + relay 信号）**完全照抄**而非抽象，可读性高于"未来可能复用"的虚设需求。

### 3.2 跨页 manager 单例：MainWindow 持有 + 显式注入

- `MainWindow.__init__` 在 pages 创建完成后 `self.theme_extract_manager = ThemeExtractTaskManager(self)`
- 评估页 / 预测题材页都暴露 `set_theme_extract_manager(mgr)` 方法
- MainWindow 主动调 setter 注入（page `__init__` 阶段 `self.window()` 还拿不到 mainwindow，懒读不可行）
- `closeEvent` 调 `manager.shutdown()` 取消所有 PENDING，RUNNING 自然结束

### 3.3 0 新增 service 接口 / 0 新增 CLI

- 题材抽取本体：复用 `core.theme_extractor.ThemeExtractor.extract_from_file`
- 批量删除：复用 `services.scoring.scoring_service.delete_report`（GUI 串行 loop 调用）
- 未抽题材报告查询：复用 `get_report_eval` 返回的 `themes_count`（前端 `== 0` 过滤）
- 没有新增 service 公开方法 → 触发 `cli-first-development.mdc` 红线为 **0**，本次未补 CLI

### 3.4 评估页提取后 toast 不切 Tab

主人决策 q1=`toast_only`：行内点「🎯 提取题材」 → 弹 `QMessageBox.information` 「已加入队列，去预测题材页看进度」 → 该行按钮立刻变「⌛ 已入队」灰 → 主人按需切 Tab。

### 3.5 树原生 Ctrl/Shift 多选不加 checkbox 列

主人决策 q3=`tree_multiselect`：`setSelectionMode(QTreeWidget.ExtendedSelection)`，保留树原本视觉清爽；批量删除时 `selectedItems()` → 过滤顶层 `_KIND_REPORT` 节点 → 按是否含真实报告分级弹确认框。

### 3.6 含真实报告时强提示二次确认

- 全回测 → 普通 `QMessageBox.question` 一次确认
- 含 N 份真实 → 第一道 `QMessageBox.question` 显示「含 N 份真实报告」 + 第二道 `QInputDialog.getText` 必须输入「我确认删除」4 个字才放行（与现有「单删真实报告」按钮要输入 id 末 4 位的强度对齐）

### 3.7 队列删除前置拦截

`has_active_for_path(report_path)` 帮评估页批量删除做前置：选中含正在抽题材（PENDING / RUNNING）的报告就拦截，让主人先到预测题材页删队列任务。避免 worker 跑完后 `INSERT INTO theme_predictions` 找不到对应 ai_reports 行。

## 六、主人使用提示

### 场景 1：清理满屏「无题材」回测报告

1. 评估页筛选「最近 3 天 / 仅回测」
2. 点表头「⚡ 全部提取（未抽题材）」→ 弹「将提取 N 份…」确认 → toast「已入队 N 个任务」
3. 切到「🎯 预测题材」页 → 右栏队列开始跑（默认 16 并发，~3 min 全部跑完）
4. 切回评估页 → 「🔄 刷新」→ 原灰按钮变「⚡ 初次打分」可点

### 场景 2：批量删除误生成的回测

1. 评估页树里 Ctrl+点 / Shift+范围 多选 N 行
2. 点表头「🗑 批量删除」→ 全回测则单次确认 / 含真实则强提示 + 输入「我确认删除」
3. 表自动刷新

### 场景 3：连点抽取多份报告

1. 预测题材页手选 .md A → 点「🚀 开始抽取并入库」→ 任务 1 入队 + 立即跑
2. 不等任务 1 完成，连点 5 次 → 5 个任务排队
3. 右栏队列实时显示进度，可拖并发数实时调（默认 16 路）

### 场景 4：失败任务怎么重试

题材抽取失败行回到评估页会变回「🎯 提取题材」可点击 → 直接再次点击即可重试（一期不做"重试"专用按钮）。

## 七、留待后续观察

1. **批量删除**当前是 GUI 线程同步串行调 `delete_report`：实测 10~50 行删除 < 5s 主人能等；若主人后续反馈卡顿再改异步 worker
2. **任务点行联动主区域**：预测题材页下半区是「已入库题材」库视图，与回测产物视图（流式 / md / 题材）不同，第一期不做点行联动；如主人有需求再加
3. **任务持久化**：当前关 GUI 队列清空，与手动回测一致；若主人想要"重启 GUI 后看历史任务"，需要起 SQLite 表落库
4. **重试按钮**：失败任务需主人切到评估页再点；若高频出现可在队列面板加专用「↻ 重试」按钮
