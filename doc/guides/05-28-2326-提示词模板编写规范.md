# 提示词模板编写规范（analysis 类目）

> 适用范围：`prompts/analysis/` 目录下的 `.md` 模板文件。
>
> 本文档既是辉夜与主人手写模板的硬性约束，也是**喂给 AI 让其自动生成模板**的 spec。
> 严格遵守每一条，否则 `core/prompt_loader.py::PromptLoader` 会在 `validate_all()` 时抛错，
> 或者 `core/ai_news_analyzer.py::AINewsAnalyzer.build_user_prompt` 渲染时抛 `KeyError`。

---

## 一、文件位置与命名

- 路径：`prompts/analysis/{prompt_id}.md`
- `prompt_id` 必须满足正则 `[A-Za-z0-9_\-]+`
- `prompt_id` **必须与 frontmatter 的 `id` 字段完全一致**（不一致 `validate_all` 会列错）
- 文件名以 `_` 开头的会被 `list_category()` 当作隐藏文件忽略（用作草稿/调试时可以利用）

---

## 二、文件骨架（强制三段式）

```markdown
---
<YAML frontmatter>
---

## SYSTEM

<system prompt 正文>

## USER

<user prompt 正文，含占位符>
```

硬性要求：

1. **首行必须是 `---`**（YAML frontmatter 起始），否则 `_split_frontmatter` 直接抛 `PromptParseError`
2. **必须出现 `## USER` 二级标题**（analysis 类目下 `## SYSTEM` 也必须有；
   不写 SYSTEM 会让 build_user_prompt 拿到空字符串，导致 LLM 失去角色定位）
3. 两个标题必须是**严格的二级标题** `^##\s+SYSTEM\s*$` / `^##\s+USER\s*$`，
   不能写成 `###`、不能加冒号、不能加 emoji 前缀

---

## 三、Frontmatter 字段规范

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `id` | ✅ | string | 与文件名一致，纯英文/数字/下划线，引号可省 |
| `name` | ✅ | string | 中文展示名，**含中文/空格必须加单引号或双引号** |
| `category` | ✅ | string | 固定写 `analysis`（除非新建别的类目） |
| `version` | 推荐 | string | 默认 `'1.0'`，**必须加引号否则会被解析成 float 1.0** |
| `description` | 推荐 | string | 一句话简介（GUI 列表会显示） |
| `provider_default` | 可选 | string | 默认推荐 provider（`deepseek` / `qwen` / `openai` / `zhipu`） |
| `model_default` | 可选 | string | 默认推荐模型名 |
| `temperature_default` | 可选 | float | 默认温度，0.0~2.0 |

⚠️ frontmatter 解析器是手写的 YAML 子集（`core/prompt_loader.py::_parse_yaml_frontmatter`），
**只支持顶层 K-V 和顶层 K-list**，不支持嵌套 dict、`[a, b]` 流式列表、anchors、tags。别炫技。

### 合法示例

```yaml
---
id: aggressive
name: '激进策略'
category: analysis
version: '1.0'
description: '专注高成长 / 高弹性 / 短期催化的机会挖掘'
provider_default: deepseek
model_default: deepseek-v4-pro
temperature_default: 0.7
---
```

## 四、占位符规则（重点 · 容易踩雷）

系统在 `build_user_prompt` 里用 Python `str.format()` 渲染 USER 段。规则如下：

### 4.1 仅支持的两个占位符（USER 段）

| 占位符 | 行为 |
|---|---|
| `{max_sectors}` | 按调用方传入值替换；传 `'auto'` 时替换为「根据新闻数据的实际情况自动确定（建议3-10个）」 |
| `{stocks_per_sector}` | 同上，描述每板块股票数 |

### 4.2 ⚠️ 不要在模板里写 `{news_data}` 和 `{market_summary}`

虽然 `build_user_prompt` 在 `format()` 时会把这两个 key 兜底成空字符串（不会报错），
但**系统会强制把真实数据追加到 prompt 末尾**，模板里写了反而留下空白割裂感。

正确做法：**完全不写**这两个占位符，把模板正文写完整即可。
系统会在末尾自动追加：

```
---

【盘后总结】
<实际 market_summary 文本，若不为空才追加>

---

【新闻数据】
<实际 news_data 文本>
```

这套设计是为了 **Prompt Cache 友好策略** —— DeepSeek/Qwen/OpenAI 按 prompt **前缀**命中缓存，
命中部分计费降至 1/10。把易变数据统一追加到末尾，可以让模板前半段（含 `{max_sectors}` 等渲染结果）
最大化命中缓存，无需用户手动改模板。

### 4.3 踩雷清单

- ❌ **正文里出现裸露的 `{` 或 `}`**（如 JSON 示例、Latex 公式、Python dict）→
  `str.format` 直接抛 KeyError。**必须转义成 `{{` 和 `}}`**
- ❌ 自创占位符如 `{date}` / `{stock_pool}` / `{template_name}` → `KeyError`，没人会帮你注入
- ❌ 在 SYSTEM 段写 `{max_sectors}` / `{stocks_per_sector}` → 不会被替换（format 只对 USER 段生效）
- ❌ 预留 `{news_data}` 或 `{market_summary}` 占位符（见 §4.2，写了等于空字符串）
- ✅ 只在 USER 段内提到「最多 {max_sectors} 个板块、每板块 {stocks_per_sector} 只」这类自然描述

## 五、复用片段 `{{include:NAME}}`

需要复用公共片段（比如新闻分级标准、输出格式约束），放到 `prompts/_shared/{name}.md`，
正文里写 `{{include:name}}` 即可。

规则：

- 共享文件**不需要 frontmatter / SYSTEM / USER**，整个文件内容即结果
- 即便共享文件带了 frontmatter 也会被自动剥离
- 最大嵌套深度 8 层，循环引用会抛 `CircularIncludeError`
- 仅允许引用 `_shared/`，不允许跨类目相互引用
- include 名称必须匹配 `[A-Za-z0-9_\-]+`

## 六、内容硬性约定

### 6.1 引用新闻必须用 Markdown 锚点

- ✅ `[新闻86](#新闻86)`
- ❌ `[新闻86,94,98](#新闻86,94,98)` —— 多新闻必须分开写
- ❌ `[新闻86](#新闻86) [新闻94](#新闻94)` —— 应该用括号包起来：`（[新闻86](#新闻86), [新闻94](#新闻94)）`

每个锚点链接**只能包含一条新闻**。GUI / 报告渲染层会扫描这些锚点做新闻跳转，
合并写法会让链接死掉。

### 6.2 SYSTEM 段必含

- 角色定位（你是谁、什么风格）
- 关注重点 / 信息分级（推荐用「🔴 重点 / 🟡 一般」一类的视觉分级）
- 输出风格约束（结构、口吻、长度倾向）

### 6.3 USER 段必含

- 分析任务的明确目标（一句话）
- **分析流程或分析框架**（分步骤指令，否则 DeepSeek 会自由发挥东拉西扯）
- 每个板块/题材的输出字段清单（让 LLM 知道每段必须包含哪些维度）
- 末尾 `【重要格式要求】` 章节，至少包含锚点格式约束

## 七、最小骨架模板（可直接套用）

把下面这份给 AI，让它在每个 `<...>` 占位处填内容，再核对一遍 §四 / §六 即可使用：

```markdown
---
id: <prompt_id 必须与文件名一致>
name: '<中文展示名，含中文必须加引号>'
category: analysis
version: '1.0'
description: '<一句话简介>'
---

## SYSTEM

你是一位<角色定位>分析师，专注于<核心关注点>。

【新闻重要性分级】：
🔴 **<高优先级类目名>**（主要关注）：
1. **<类型1>**：<描述>
2. **<类型2>**：<描述>
3. **<类型3>**：<描述>
4. **<类型4>**：<描述>

🟡 **<低优先级类目名>**：<描述>

你的特点：
- <特点1>
- <特点2>
- <特点3>
- <特点4>

输出风格：
- <风格要求1>
- <风格要求2>
- <风格要求3>

## USER

请基于以上盘后总结与新闻数据，分析<分析目标>。

【分析流程】

**第一步：<筛选/识别步骤名>**
<具体动作描述>

**第二步：板块机会分析**
基于<新闻类目>和盘后总结，识别 {max_sectors} 个<板块特征描述>的板块。

每个板块需包含：
1. **核心催化剂**（来自<新闻类目>，使用"[新闻X](#新闻X)"格式）
2. **<逻辑名>**（<为何成立>）
3. **{stocks_per_sector} 只<标的特征>**
4. **<进场时机字段>**
5. **<涨幅目标字段>**
6. **<新闻权重说明字段>**

**第三步：交易策略**
- 优先级排序（按<排序依据>）
- <操作窗口字段>
- <止盈止损字段>

【重要格式要求】：
- 引用新闻时必须使用 Markdown 锚点链接格式：[新闻X](#新闻X)
- 每个锚点链接只能引用一条新闻，禁止合并写成 [新闻1,2,3](#新闻1,2,3)
- 优先引用<高优先级类目>，<低优先级类目>作为辅助
```

> 注意 USER 段开头是「请基于以上盘后总结与新闻数据」—— 因为系统会**自动在 prompt 末尾**追加盘后总结和新闻数据，
> 写「以下」会让 LLM 找不到数据。这里要写「以上」或者「基于附录中的」。

## 八、写完后的自检流程（必须跑一遍）

1. 文件存为 `prompts/analysis/{id}.md`（**UTF-8 无 BOM**，Windows 记事本默认会加 BOM，别用）
2. 跑命令行自检：

   ```powershell
   python -m core.prompt_loader
   ```

   会列出所有模板并跑 `validate_all`，任何 frontmatter 错误 / SYSTEM 缺失 /
   include 死链 / 文件名不一致都会列出来
3. 跑一次小样本渲染（在 GUI「AI 分析」Tab 选你的模板，用 1 个时间段的真实新闻试跑）
4. 如果加了 `{{include:xxx}}`，确认 `prompts/_shared/xxx.md` 存在

## 九、调用链一览（背景知识，写模板时无需关心）

```
GUI / CLI
  → AnalysisService.analyze(template_id=...)
      → AINewsAnalyzer.analyze(template_name=...)
          → AIConfig.get_prompt_template(template_id)
              → PromptLoader.get('analysis', template_id)
                  ├─ _parse_file()              读 frontmatter + 切 SYSTEM/USER
                  └─ _expand_includes()         展开 {{include:xxx}}
          → build_user_prompt(news_data, max_sectors, stocks_per_sector, market_summary)
              ├─ template.format(...)           渲染 {max_sectors}/{stocks_per_sector}
              │                                 顺手把 {news_data}/{market_summary} 置空
              └─ 末尾追加「---\n【盘后总结】...\n---\n【新闻数据】...」
          → _stream_chat(system_prompt, user_prompt)
              → LLM API
```

关键代码位置：

- `core/prompt_loader.py` —— 模板加载与 frontmatter 解析
- `core/ai_news_analyzer.py::build_user_prompt` —— 占位符渲染与末尾数据追加
- `core/ai_config.py::get_prompt_template` —— 模板路由
- `services/analysis_service.py::AnalysisService.analyze` —— GUI / CLI 入口

## 十、常见问题 Q&A

**Q1：我能不能在 SYSTEM 段用 `{max_sectors}`？**
不能。`format()` 只对 USER 段生效，SYSTEM 里写 `{max_sectors}` 不会被替换，
最后会原样发给 LLM 让它困惑。如果你确实想在 SYSTEM 里描述板块数约束，
要么写死数字（如「最多 6 个板块」），要么完全不写，由 USER 段控制。

**Q2：模板里需要写「请基于以下新闻数据」吗？**
不需要写「以下」。系统把数据追加到 **prompt 末尾**，写「以下」会指向空气。
推荐写「请基于以上盘后总结与新闻数据」，或者干脆「请基于附录中的数据」。

**Q3：可以在模板里展示 JSON Schema / Python dict 示例吗？**
可以，但必须把 `{` 和 `}` 转义成 `{{` 和 `}}`。否则 `format()` 会把它们当成占位符报 KeyError。

**Q4：能否依赖模板自带的 `provider_default` / `model_default` / `temperature_default` 字段？**
当前 GUI / CLI **不会自动应用**这些字段（参考 `services/analysis_service.py` 的实际调用链），
它们只作为模板自描述的元数据写在 frontmatter 里供未来扩展用。
真正生效的是用户在 GUI 选择的 provider 和 `core/ai_config.py` 里的 model 配置。

**Q5：模板版本如何管理？**
直接改 `version` 字段即可（`'1.0'` → `'1.1'`）。**不要**用 `xxxv2.md` / `xxx_v3.md` 这种命名，
违反主仓库「禁止 v1 / v2 命名」规约（详见 `.cursor/rules/huiye-persona.mdc`）。
重大重写直接覆盖旧文件，git 历史会保留旧版本。
