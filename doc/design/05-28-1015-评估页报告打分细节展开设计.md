## 一、是什么

**在「模板评估面板」上加 2 层下钻视角**，让主人能从"模板汇总 → 报告明细 → **题材打分明细 → 标的逐日涨跌**"一路看到最底层。

一句话：现在评估页只能看到"某份报告下 14 个题材的 D+1~D+5 平均"，主人想点开它看到**这 14 个题材每个的具体表现**，再点开某个题材就能看到**它名下每只股票每天的涨跌**。

```
当前布局（2 段）                改造后布局（4 段）
┌──────────────────┐          ┌──────────────────────┐
│ 控制条             │          │ 控制条                 │
├──────────────────┤          ├──────────────────────┤
│ 上：模板汇总        │          │ 上：模板汇总            │
│   按 prompt_id     │          │   按 prompt_id        │
├──────────────────┤          ├──────────────────────┤
│ 下：报告明细        │          │ 中上：报告明细          │
│   按 ai_reports.id │          │   按 ai_reports.id    │
└──────────────────┘          ├──────────────────────┤
                              │ 中下：题材打分明细🆕     │
                              │   选中报告下 N 个题材    │
                              │   D+1~D+5 / α / 命中率  │
                              ├──────────────────────┤
                              │ 下：标的逐日涨跌🆕       │
                              │   选中题材下 K 只股票    │
                              │   逐日 % / 是否命中     │
                              └──────────────────────┘
```

## 二、为什么做（用户情景）

主人现在的实际痛点：

1. **看到某份报告 D+1 大涨 5%、D+5 暴跌 -8%，想知道是哪些题材在涨/跌？** —— 现在得双击跳「题材预测库」页，再手动选日期、选模板、肉眼对照，**断层 3 步**。
2. **看到某个题材的 D+3 -10% 异常，想知道是它名下的股票全跌还是个别股票拖累？** —— 现在 GUI 完全看不到，**得开 SQLite 查 `theme_stock_scores` 才能知道**。
3. **复盘 prompt 模板效果时，需要"模板均值 → 单报告均值 → 单题材表现 → 单股表现"四级链条** —— 评估的本质是**找到"为啥某个模板/某天表现好"的可解释因子**，少一级链条就少一份洞察。

不做的代价：评估页停留在"宏观均值"维度，复盘要靠 SQL/CLI/跨页跳转拼凑，效率低。

## 三、具体要求

### 3.1 必须包含

- **第 3 段（题材明细表，全量 11 列）**：选中第 2 段某份报告时联动刷新
  - 题材名 / 强度等级 / 板块代码 / D+1~D+5 加权 % / α / 命中率 / 方向准确 / AI 评语 / 持续性 / 板块涨跌幅
  - 每行 1 个题材（聚合所有 score_date，取 D+1~D+5 透视）
- **第 4 段（标的明细表，4 段联动）**：单击第 3 段某行题材时联动刷新
  - 标的名 / 标的代码 / 角色 / 逐日涨跌（D+1~D+5 各 1 列）/ 是否命中
  - 每行 1 只股票
- **染色规则**：D+N / α / 命中率沿用现有红涨绿跌；命中标记加底色
- **空态处理**：报告未打分 → 第 3 段显示"该报告下题材未打分，去上方点「打分」按钮"；题材无标的 → 第 4 段显示"该题材未抽到具体标的"

### 3.2 必须排除

- ❌ **不**改第 1/2 段现有逻辑、不动「打分/删除」按钮列
- ❌ **不**复用第 4 段做"标的层级再下钻"（不再深入）
- ❌ **不**接入 AI 评语生成（Phase 7 才有，本期占位 "—"）
- ❌ **不**做 4 段间筛选条联动以外的"全局过滤"，时间范围/真假回测仍由控制条统一管

### 3.3 性能约束

- 单份报告下题材一般 5~20 个，标的一般 3~8 只/题材 → 数据量 < 200 行/段，**单次查询 < 100ms**
- splitter 默认上下比例 `2 : 3 : 3 : 2`（主人可拖动调整），保证 4 段都看得见
- 第 3、4 段查询都是按 ID 单值查询（命中现有索引），不引入新索引

### 3.4 CLI 化

按 `cli-first-development.mdc` 红线，新增 service 方法**必须**配 CLI：

- `tools/query_eval.py --by theme_in_report --report-id 1234`
- `tools/query_eval.py --by stocks_in_theme --theme-id 5678`
- 输出与 service 返回的 dataclass 字段一致（未来 API 响应体雏形）

## 四、预期效果

主人打开评估页后：

1. 选个模板（第 1 段）→ 第 2 段刷新出该模板下所有报告
2. 点选某份"D+1 +5% / D+5 -8%"的奇葩报告（第 2 段）→ **第 3 段立刻刷出 14 个题材的逐题材打分**
3. 主人扫一眼第 3 段，发现「人形机器人 D+3 -12% / 命中率 0%」最拖后腿 → **单击该行题材**
4. 第 4 段立刻刷出该题材下 6 只股票的逐日涨跌 → 主人秒懂"原来是 XX 龙头那天炸板拖累全题材"
5. 整个排查链 < 3 次点击，**不再需要跳页/打开 SQLite**

## 六、Q&A（预想主人会问）

**Q1：4 段会不会挤得每段都很矮？**  
A：splitter 可拖动，默认比例 `2:3:3:2`。1080P 屏下每段约 150~200px，能看 5~10 行；主人可把不关心的段拖小、关心的拖大。

**Q2：现有「双击跳题材预测库」signal 还要保留吗？**  
A：保留，作为"看上下文（标的代码 / 新闻锚点 / 板块走势 Tab）"的入口；本期新增的"单击下钻"是更轻量的"只看打分"视角。两条路并存。

**Q3：标的明细的 D+N 是涨跌幅还是是否命中？**  
A：**两个都展示**——5 列涨跌幅（红涨绿跌）+ 1 列命中标记（✓/✗ + 底色）。`theme_stock_scores` 表已有 `pct_chg` + `is_hit` 字段，零改造。

**Q4：报告未打分时第 3 段显示啥？**  
A：保持表格但所有 D+N / α / 命中率显示 "—"，并在 status 标签提示"该报告未打分，请先去上方点「打分」按钮"。

**Q5：会不会影响第 1/2 段的现有交互？**  
A：完全不会。第 3/4 段是**新增**且**只读**于第 1/2 段的选中状态，不反向影响。

**Q6：导出 CSV 要不要带新两段？**  
A：**带**。CSV 加 `[题材打分明细]` 和 `[标的逐日涨跌]` 两节，与现有「[模板汇总]」「[报告明细]」并列。

**Q7：工期预估？**  
A：约半天。主要工作量是 GUI 的 splitter 拆分 + 2 个 service 方法 + 2 个 CLI 子模式 + 4~5 个回归用例。
