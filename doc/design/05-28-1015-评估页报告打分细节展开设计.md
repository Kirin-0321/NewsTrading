## 一、是什么

**把现有"报告明细表"升级成可逐级展开的 3 级树**，让主人能从"模板汇总 → 报告（点 ▶ 展开）→ 题材（点 ▶ 展开）→ 股票"一路看到最底层。

一句话：现在评估页只能看到"某份报告下 14 个题材的 D+1~D+5 平均"，主人点 **▶** 一级一级展开，就能看到**这 14 个题材每个的具体表现**，再点 **▶** 就能看到**它名下每只股票每天的涨跌**。

```
当前布局（2 段 = 模板汇总 + 报告明细表）       改造后布局（仍 2 段，但下表升级为树）
┌──────────────────────────────────┐         ┌──────────────────────────────────────────┐
│ 控制条                              │         │ 控制条                                      │
├──────────────────────────────────┤         ├──────────────────────────────────────────┤
│ 段 1：模板汇总                      │         │ 段 1：模板汇总（保持现状）                    │
├──────────────────────────────────┤         ├──────────────────────────────────────────┤
│ 段 2：报告明细表（QTableWidget）    │         │ 段 2：报告树（QTreeWidget，3 级展开）         │
```

## 二、为什么做（用户情景）

主人现在的实际痛点：

1. **看到某份报告 D+1 大涨 5%、D+5 暴跌 -8%，想知道是哪些题材在涨/跌？** —— 现在得双击跳「题材预测库」页，再手动选日期、选模板、肉眼对照，**断层 3 步**。
2. **看到某个题材的 D+3 -10% 异常，想知道是它名下的股票全跌还是个别股票拖累？** —— 现在 GUI 完全看不到，**得开 SQLite 查 `theme_stock_scores` 才能知道**。
3. **复盘 prompt 模板效果时，需要"模板均值 → 单报告均值 → 单题材表现 → 单股表现"四级链条** —— 评估的本质是**找到"为啥某个模板/某天表现好"的可解释因子**，少一级链条就少一份洞察。

不做的代价：评估页停留在"宏观均值"维度，复盘要靠 SQL/CLI/跨页跳转拼凑，效率低。

## 三、具体要求

### 3.1 必须包含

#### 3 级树形结构

| 层级 | 图标 | 节点含义 | 行为 |
|------|------|----------|------|
| 1（顶层）| 📄 | 一份 ai_reports | 点 ▶ 展开题材子节点；行尾保留「⚡ 打分」「🗑 删除」按钮 |
| 2（中层）| 🎯 | 一个 theme_predictions | 点 ▶ 展开标的子节点 |
| 3（叶子）| 📈 | 一只 theme_stocks | 不可展开 |

#### 列共享（约 13 列，跨 3 级语义对齐）

| 列序 | 报告级（📄）| 题材级（🎯）| 标的级（📈）|
|------|-------------|-------------|-------------|
| 0 名称 | 报告日期 + 真/回测 | 题材名 | 标的名 |
| 1 类型/等级/角色 | 模板名 | 强度等级 | 角色（核心/辐射）|
| 2 辅助 | 版本 | 板块代码 | 标准化代码 |
| 3 子项数/排名 | 题材数 | 排名 | — |
| 4 进度/分数 | 打分进度（X/Y）| 强度分 | — |
| 5~9 D+1~D+5 | 报告级均值 % | 题材加权 % | 个股 pct_chg % |
| 10 α | 报告级均值 | 题材级均值 | — |
| 11 命中率/命中 | 报告级均值 | 题材命中率 | 命中 ✓/✗（is_hit）|
| 12 文件名/AI评语/理由 | 文件名 | AI 评语（暂占位 —）| 理由 |

> 同一列在不同层级语义对齐（D+N 都是涨跌幅 %，红涨绿跌染色统一）；当某层不适用时显示空字符串。

#### 排序（**仅限最外层报告级**，主人新增要求）

- 顶层报告级支持点击表头排序的列：**报告日期 / 题材数 / 打分进度 / D+1~D+5 / α / 命中率**
  - 数值列按数值大小排（不是字典序）
  - NULL 值排在末尾
- **题材级、标的级保持插入顺序**（按 theme_id ASC / theme_stock_id ASC，与库一致）
- 排序行为：点击表头 → 重排顶层 📄 节点；已展开的子树**保持展开状态**，子节点顺序**不变**
- UI 提示：可排序的列在表头标 ⇅ 图标（hover 时显示）

#### 懒加载

- 默认只渲染顶层 📄（占位子节点用空 QTreeWidgetItem 让 ▶ 可见）
- 主人点 ▶ 展开 📄 → 才查 `theme_predictions WHERE report_path=?` 填题材子节点
- 主人点 ▶ 展开 🎯 → 才查 `theme_stocks` + `theme_stock_scores` 填股票孙节点
- 已展开的节点**不重复查 DB**（缓存在 QTreeWidgetItem.data(Qt.UserRole) 中）；主人点「🔄 刷新」时清缓存

#### 染色规则

- D+N / α / 命中率：沿用现有红涨绿跌
- 命中标记列：✓ 浅红底 / ✗ 浅绿底（题材级 / 标的级）
- 未打分行：D+N 列显示 "—"，行整体淡灰色

#### 现有功能保留

- 「⚡ 打分」「🗑 删除」按钮：**只放报告级（📄）行的尾部**，子级行不放
- 双击 📄 行：仍 emit `theme_drilldown_requested(report_date, prompt_id)` 跳「题材预测库」页（保留作为"看上下文"的入口）
- 单击 🎯 / 📈 行：仅选中高亮，不触发跳页（避免误触）

### 3.2 必须排除

- ❌ **不**改第 1 段（模板汇总表）的逻辑、列、按钮
- ❌ **不**改控制条的筛选逻辑（时间维度 / 时间范围 / 真/回测筛选 / 忽略版本）
- ❌ **不**接入 AI 评语生成（Phase 7 才有，本期占位 "—"）
- ❌ **不**做题材级 / 标的级排序（只做顶层报告级排序）
- ❌ **不**新建数据库表 / 不加索引（现有索引足够）

### 3.3 性能约束

- 顶层 📄 节点：100 份报告以内 → 一次性 fetch + 渲染 < 500ms
- 单次展开 📄→🎯：5~20 个题材 → < 100ms
- 单次展开 🎯→📈：3~8 只股票 + 5 行打分 → < 50ms
- 内存占用：典型 30 天数据 ~30 报告 × 14 题材 × 5 股票 = 2100 节点 < 5MB

### 3.4 CLI 化（按 `cli-first-development.mdc` 红线）

新增 service 方法**必须**配 CLI：

- `tools/query_eval.py --by theme_in_report --report-id 1234`
  - 输出：该报告下所有题材的聚合打分（11 列）
- `tools/query_eval.py --by stocks_in_theme --theme-id 5678`
  - 输出：该题材下所有标的的逐日涨跌（D+1~D+5 + 命中标记）

输出字段与 service 返回的 dataclass 字段完全一致（未来 API 响应体雏形）。

## 四、预期效果

主人打开评估页后：

1. 选个模板（段 1）→ 段 2 树展示该模板下所有报告（折叠态，只看顶层 📄 行）
2. **点击表头「D+5」列** → 按 D+5 升序排序，最差的报告排最上
3. 点击最差那份报告的 ▶ → 展开 14 个题材，扫一眼发现「人形机器人 D+5 -12% / 命中率 0%」最拖后腿
4. **点击「人形机器人」的 ▶** → 展开 6 只股票，发现"原来是 XX 龙头那天炸板拖累全题材"
5. 整个排查链 < 4 次点击，**不再需要跳页/打开 SQLite**

## 六、Q&A（预想主人会问）

**Q1：3 级树会不会因为列太多每列都很窄？**  
A：13 列 + 1080P 屏宽 1920px → 每列平均 145px，足够放下数值。名称列（列 0）会更宽（~250px），辅助列窄（~80px）。主人可拖动表头调列宽。

**Q2：排序时已展开的子树会被收起吗？**  
A：**不会**。Qt 内部排序会保留 expanded 状态，主人正在看的子节点不会突然折叠。

**Q3：懒加载会不会让排序失效？**  
A：不会。排序只看顶层 📄 节点的列值；子节点是否加载与排序无关。但**未展开的报告**也能参与排序（顶层数据已经在 `get_report_eval` 一次性拉到了）。

**Q4：题材子节点怎么排序？**  
A：**默认按 theme_id ASC（与库插入顺序一致）**，本期不做排序。主人若以后想加可以再扩展。

**Q5：删除报告后子节点会自动消失吗？**  
A：会。删除走现有 `DeleteReportWorker`（CASCADE 删 theme_predictions / theme_stocks / scores），删完触发 `refresh()` 重建整棵树。

**Q6：现有「双击跳题材预测库」要不要去掉？**  
A：**保留**。双击 📄 行仍跳「题材预测库」（看新闻锚点 / 板块走势 Tab）；新增的"行内展开"是另一条更轻量的路径。两条路并存。

**Q7：导出 CSV 怎么处理树结构？**  
A：CSV 加 3 节：`[报告级]` `[题材级]` `[标的级]`，每节用扁平格式（带 `report_id` / `theme_id` 关联列）。主人可在 Excel 里用透视表自己重组。

**Q8：工期预估？**  
A：约半天（4~6 小时）：
- service 层 2 个新 API + CLI：1.5h
- GUI 段 2 改 QTreeWidget + 排序 + 懒加载：3h
- 回归测试 + 文档：1h
