## 三、模块拆分 / 接口签名

### P1.1 数据管理页修目录 + Markdown 渲染（纯 GUI，无 service）

- `data_page.py`
  - 行 251：`"data/analysis"` → `"data/AI_analysis"`
  - `_refresh_md_files` 改为递归扫描（`os.walk`），`name` 列显示相对子路径（如 `5月28日/xxx.md`）以区分同名文件
  - `_view_md_file`：`setPlainText(content[:50000])` → `setMarkdown(content)`（移除截断）

### P1.2 弱匹配阈值对齐（纯 GUI，无 service）

- 统一阈值常量 `SECTOR_WEAK_MATCH_CONF = 0.5`（与评估页/打分语义对齐，<0.5 才"仅供参考"）
- `theme_prediction_page.py:886`：`< 0.7` → `< SECTOR_WEAK_MATCH_CONF`
- 决策：常量就近放各页模块级（两处各定义同值 0.5）即可，**不强行抽公共模块**（KISS，避免为 1 个常量造 utils）；在两处注释里互相指明"与评估页对齐 0.5"

### P1.3 AI 分析页页内 Markdown 预览（纯 GUI，无 service）

- `ai_analysis_page.py`
  - `_build_result_group`：把单一 `result_browser` 包进 `QTabWidget`，两 Tab：
    - 「📡 实时流式」= 现有 `result_browser`（保持 `insertPlainText` 行为不变）
    - 「📄 成品报告」= 新增 `md_browser`（`QTextBrowser` + `setMarkdown`）
  - 新增 `_render_md(report_path)`：**照搬** `manual_backtest_page._render_md`（`get_project_root` 拼绝对路径 → `read_text` → `setMarkdown`）
  - `_refresh_for_selected_task`：SUCCESS 且有 `report_file` 时调 `self._render_md(report_file)`；非 SUCCESS / 切任务时 `md_browser.clear()`
  - `open_report` 外部打开按钮**保留**（页内预览是补充不是替代）

### P1.4 题材表补板块中文名列（GUI + 轻量 service + CLI）

- **新增 service**：`services/market/sector_daily_query.py` 加
  ```
  def get_sector_names(ts_codes: list[str]) -> dict[str, str]:
      """批量反查 dim_sector 中文名。返回 {ts_code: name}，缺失键不放。"""
  ```
  （单次 `SELECT ts_code, name FROM dim_sector WHERE ts_code IN (...)`，readonly）
- **新增 CLI**（CLI-first 强制）：在 `tools/sector_daily_query.py` 加子命令或新增 `--names` 模式，入参 `--ts-codes a,b,c`，stdout JSON `{ts_code: name}`
- `theme_prediction_page.py`
  - `_THEME_TABLE_COLS`：第 4 列「板块代码」标题改「板块」，列宽 90→150
  - `_render_theme_table`：渲染前收集本批 `sector_ts_code` 调 `get_sector_names` 拿映射，单元格文案 `板块名 (代码 conf)`；查不到名退回 `代码 (conf)`（保持旧行为兜底）
  - 弱匹配橙色判定（P1.2 改后的 `< 0.5`）逻辑不变

### P2.1 题材页「打分明细」Tab 接通（GUI，复用现有 service）

- 复用 `scoring_service.get_theme_score_detail(theme_id)`（已存在，已有 CLI `tools/query_eval.py` / `score_themes.py` 覆盖，无需新增）
- `theme_prediction_page.py`
  - `score_detail_browser`（QTextBrowser）→ 改为一个**逐日明细表 + 顶部摘要**的组合 Tab（参考板块走势 Tab 的 header+table 结构），或先以 `setHtml` 渲染一张逐日表（KISS 起步）
  - `_show_theme_detail(theme)`：取 `theme["id"]`（= theme_predictions.id）调 `get_theme_score_detail`，渲染：报告日、逐日（D+offset / sector_pct / theme_pct / 命中 / 方向）、命中率、benchmark
  - 空态（未打分 / scored=0）：显示"该题材尚未打分，去评估页一键打分"提示
  - 移除占位文案

### P2.2 评估页双击携带 report_id + 题材页按单报告过滤（GUI + 可能 1 个 service 方法 + CLI）

- `prompt_eval_page.py`
  - signal `theme_drilldown_requested`：`pyqtSignal(str, str)` → `pyqtSignal(str, str, int)`（加 report_id）
  - `_on_tree_double_clicked`：emit `(rd, pid, int(data.get("report_id") or 0))`
- `gui/main_window.py`
  - `_on_eval_drilldown(report_date, prompt_id, report_id)`：保留原 date/prompt 预选；若 `report_id>0`，额外调题材页新方法按单报告过滤
- `theme_prediction_page.py`
  - 新增 `load_by_report_id(report_id: int)`：经 ai_reports.id → file_path → theme_predictions.report_path 取该报告题材并渲染
- **service 支撑**：题材按 `ai_reports.id` 精确取——
  - 优先复用：`ai_reports_store` 拿 file_path + `theme_store.get_by_report(report_id_str)`（注意 `get_by_report` 入参是 string report_id，需核对其语义是否 = 文件名）
  - 若现有接口拼不出，则在 `theme_store` 加 `get_by_ai_report_id(report_id: int)`（JOIN ai_reports）+ 配 CLI（`tools/` 下补 `--by-report-id`）
  - **施工时先验证复用可行性，能复用就不新增**
