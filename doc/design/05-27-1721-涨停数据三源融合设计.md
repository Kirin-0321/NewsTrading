## 一、是什么

把"获取每日涨停股数据"从**两条腿**升级到**三条腿**走路：

```
当前 (2 条腿):           升级后 (3 条腿，互补):
┌─────────────────┐      ┌─────────────────┐
│  东财·限价股清单  │      │  东财·限价股清单  │——延迟 / 弱
│  (limit_list_d) │  →   │  (limit_list_d) │
├─────────────────┤      ├─────────────────┤
│  开盘啦·涨停题材  │      │  开盘啦·涨停题材  │——题材担当
│  (kpl_list)     │      │  (kpl_list)     │
└─────────────────┘      ├─────────────────┤
                          │ 同花顺·涨跌停榜单 │——⭐ 新增主源
                          │ (limit_list_ths)│
                          └─────────────────┘
```

一句话：**让"涨停连扳"这块数据从盘后第二天才出，提前到当日 16 点就能看见，且字段比现在更丰富。**

## 二、为什么做（用户情景）

### 痛点 1：T 日空窗（今天就在发生）

> 2026-05-27 17:06 主人打开 GUI，"涨停 & 连板"Tab 四个桶（首板 / 2 连板 / 3 连板 / 4 连板及以上）**全是 0**。

原因：东财 + 开盘啦两个数据源**当日 16:00~24:00 普遍延迟**，要等到 T+1（次日早上）才出昨天涨停股。今天的涨停股，今天看不到。

→ AI 分析模板拿不到当日涨停名单 → 盘后总结质量直接崩盘。

### 痛点 2：长期漏算 28% 涨停股（隐性历史 bug）

实测 2026-05-26 三接口对比：

| 接口 | 实测涨停股数 |
|------|-------------|
| 东财（当前主源）| **46 只** ⚠️ |
| 开盘啦 | 64 只 |
| 同花顺 | 64 只 |

→ 东财接口长期**少算 18 只涨停股（28%）**，三方交集恰好是东财的 46 只——东财就是个"残缺子集"。

主人之前看到的统计、AI 分析里的"今日 46 只涨停"……**都是错的**。

### 痛点 3：题材标签太粗 → AI 分析吃不饱

同一只股的两个字段对照：

| 股票 | 现有 `theme`（开盘啦）| 新增 `lu_desc`（同花顺）|
|------|----------------------|------------------------|
| 声迅股份 | 安防、数字经济 | 摘帽+智能安防+智慧停车+低空经济 |
| 华塑控股 | 工业母机、绿色电力 | 拟定增+PCB钻针+CCER+湖北国资 |
| 新金路 | 金属钨、化工 | 石英砂+锡钨钽铌+氯碱龙头 |

→ `theme` 是"产业类别"（适合分桶）；`lu_desc` 是"今日盘面具体催化剂"（适合做明牌六字段、给 AI 找龙头）。**两者非冲突，是互补**。

### 痛点 4：缺失"冲刺涨停 / 连扳池"两个独家泳池

同花顺还有两个其他渠道完全没有的数据切片：

| 泳池 | 5/26 行数 | 业务价值 |
|------|----------|---------|
| **冲刺涨停** | 17 | 盘中接近涨停未封住，**情绪温度计** |
| **连扳池** | 28 | 单独高度榜，含 `12天10板` 极端梯队 |

## 三、具体要求

### 必须做到

1. **当日 16 点后**，"涨停 & 连板"Tab **不再为空**（哪怕东财/开盘啦都未出数据）。
2. **每天的涨停股总数对得齐**（以同花顺/开盘啦的 64 为准，不再被东财的 46 锚定）。
3. **新增"涨停原因"字段**展示在 ladder Tab，每只涨停股都能看到具体催化剂。
4. **新增"一年封板率"字段**（同花顺独家）—— 主人看龙头时一眼判别"老主线 vs 新打板"。
5. **历史数据稳定**：T+1 后开盘啦数据出齐，不能把同花顺独家字段（`lu_desc` / `limit_up_suc_rate`）覆盖掉。

### 必须避免

1. **三源对账冲突**：同一只股 close / pct_chg 在三源都有，不能各显示各的。
2. **数据漂移**：T 日先入库 ths 数据，T+1 force-refresh 后字段被覆盖反而变差。
3. **API 调用爆炸**：现在每天 ~16 次 Tushare 调用，新增不能翻倍。

### 可以放弃

- `limit_list_d`（东财）独家的 `industry`（申万行业）+ `total_mv`（总市值）—— 业务里几乎没用，主人决定要不要保留即可。

## 六、Q&A

**Q1：同花顺接口自己也会延迟吗？**  
A：按 Tushare 文档「**增量每天 16 点左右更新**」。今天 17:06 实测同花顺有 61 行涨停数据 + 25 行连扳数据，证明**当日盘后实时性是三个接口里最好的**。

**Q2：历史数据范围够吗？**  
A：同花顺接口历史从 **20231101 起**，覆盖 30 天回填窗口绰绰有余。

**Q3：三个接口的涨停定义会不一样吗？**  
A：实测 5/26 三接口的涨停股集合是「东财 ⊂ (开盘啦 = 同花顺)」，**开盘啦和同花顺完全一致 64 只**，东财少 18 只是接口实现 bug。融合后以「开盘啦 ∪ 同花顺」为准（其实就等于同花顺 64 只）。

**Q4：科创板/创业板 20% 涨幅的"涨停"会被三方都识别吗？**  
A：实测中科创板 `688585.SH 上纬新材` 涨幅 18.18%（科创板涨停近门槛）出现在同花顺"冲刺涨停"池里，证明同花顺**正确识别科创板 20% 涨停**。东财接口的涨停判定较窄，这也是它漏 18 只的原因之一。

**Q5：主人 Tushare 账号是哪种级别？**  
A：辉夜不知道，可以从配置文件里查 token，但权限要主人去 Tushare 后台看。同花顺接口要求 8000 积分以上 = Tushare 高级会员（年付）。

**Q6：施工要多久？**  
A：等主人确认决策点后辉夜估工期，初步看半天到一天（含三源合并 + GUI 展示 + 历史回填）。
