## 二、技术选型

### 2.1 任务队列模式：复用 vs 新造

**结论：新造 `ThemeExtractTaskManager` + `ThemeExtractTask`，但完全照抄 `manual_backtest_manager.py` 的并发池 / 状态机 / 信号设计。**

理由：
- `BacktestTask` 字段强耦合回测语义（`trade_date / news_start_dt / news_end_dt / news_status / dry_run / overwrite`），强行复用会逼新任务塞一堆 None；
- 题材抽取任务字段：`report_path / provider / model / report_id（抽完拿到）/ themes_count / stocks_count / news_count`，与回测完全不同；
- 5 态机 / 并发池 / 信号 / 计时器等**纯通用**逻辑直接照抄，可读性比抽公共基类高。

### 2.2 跨页通信：MainWindow 持有 Manager 单例

**结论：`MainWindow.__init__` 里 `self.theme_extract_manager = ThemeExtractTaskManager(self)`，评估页与预测题材页通过 `self.window().theme_extract_manager` 反向访问。**

理由：
- 手动回测页的 manager 是 page 私有（`self.manager = BacktestTaskManager(self)`），未跨页；
- 题材抽取要跨 2 个页面，必须提一级；
- MainWindow 是天然的容器，QApplication 单例 / 全局变量都太污染。

### 2.3 服务层 / CLI

**结论：本次改动 0 新增 CLI、0 新增 service 接口。**

理由：
- 题材抽取本体接口 `core.theme_extractor.ThemeExtractor.extract_from_file` 已稳定，本次只在它外层套队列调度；
- 「批量删除」复用现有 `services.scoring.scoring_service.delete_report`（loop 调用）；
- 「未抽题材报告查询」复用现有 `get_report_eval`（前端 `themes_count == 0` 过滤即可）；
- 没有新增 service 公开方法 → 触发 `cli-first-development.mdc` 红线为 0，不需要补 CLI。

### 2.4 删除真实报告的内核绕行

**结论：批量删除调用 `delete_report(rid, allow_real=True, delete_md=True)`，但调用前由 GUI 弹「含 N 份真实报告」二次确认。**

理由：
- 内容文档 §5.3 明确：批量场景允许删真实，与单点删除（默认 `allow_real=False`）有意不一致；
- 安全防线下沉到 GUI 二次确认，service 接口本身已有 `allow_real` 开关，不需要改 service。

## 三、模块拆分 / 任务对象 / 接口签名

### 3.1 新增模块

#### `gui/workers/theme_extract_manager.py`（**新建**）

完全镜像 `manual_backtest_manager.py` 结构。核心导出：

```python
class TaskStatus(str, Enum):  # PENDING/RUNNING/SUCCESS/SKIPPED/FAILED
    ...

STATUS_LABEL = {...}  # 与回测同款 emoji+中文
STATUS_COLOR = {...}  # 与回测同款颜色

@dataclass
class ThemeExtractTask:
    task_id: int
    report_path: str           # 绝对路径
    report_basename: str       # 仅文件名（UI 列展示用）
    provider: Optional[str]
    model: Optional[str]

    status: TaskStatus = TaskStatus.PENDING
    enqueued_at: datetime
    started_at: Optional[datetime] = None
    finished_at: Optional[datetime] = None

    # 跑完后回填（成功时）
    report_id: Optional[str] = None
    themes_count: Optional[int] = None
    stocks_count: Optional[int] = None
    news_count: Optional[int] = None

    error_message: Optional[str] = None    # 失败时填
    skip_reason: Optional[str] = None      # 跳过时填（一期一般不会跳过）

    # 内部状态（manager 维护）
    worker: Optional[ThemeExtractWorker] = None

class ThemeExtractTaskManager(QObject):
    """题材抽取任务队列管理器（与手动回测同款 5 态机 + 并发池）。"""

    MAX_CONCURRENT_HARD_CAP = 64
    DEFAULT_CONCURRENT = 16

    # 信号（与手动回测同款语义）
    task_added = pyqtSignal(int)
    task_started = pyqtSignal(int)
    task_progress = pyqtSignal(int, str)
    task_streaming = pyqtSignal(int, str)
    task_finished = pyqtSignal(int)
    task_removed = pyqtSignal(int)

    def enqueue(self, *, report_path: str, provider=None, model=None) -> int:
        """入队，返回 task_id。"""
    def remove(self, task_id: int) -> bool:
        """删除任务（RUNNING 拒删）。"""
    def get_task(self, task_id: int) -> Optional[ThemeExtractTask]: ...
    def all_tasks(self) -> List[ThemeExtractTask]: ...
    def get_max_concurrent(self) -> int: ...
    def set_max_concurrent(self, n: int) -> None: ...
    def shutdown(self) -> None:
        """关 GUI 时调；取消所有 PENDING，让 RUNNING 自然结束。"""
```

字段命名 / 信号语义 / 5 态机与 `BacktestTaskManager` 完全对齐，方便日后两条流水线共抽公共基类（**本次不抽**）。

### 3.2 既有模块改动

#### `gui/workers/theme_extract_worker.py`（**修改**）

加 `task_id` 字段，让 manager 能在信号里区分多任务；其它逻辑不动：

        super().__init__()

        self.report_path = report_path
        ...

### 3.3 行内按钮防选中冲突

`prompt_eval_page.py` 的树启用 ExtendedSelection 后，行内有按钮的列点击行为可能误触发选中变化。需测：
- 点行内「⚡ 打分」/「🎯 提取题材」/「🗑 删除」按钮 → 只触发按钮回调，**不切换选中态**（QPushButton 默认会 stopPropagation，但要测）；
- Ctrl + 点击空白单元格 → 选中切换正常；
- Shift + 点击空白单元格 → 范围选中正常。

如果按钮点击会误改选中，需手动给按钮加 `event.accept()` 拦截。

## 五、风险登记

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| MainWindow manager 跨页生命周期：评估页 / 预测题材页未加载时 manager 已被引用 | 中 | 任务丢失 | manager 在 `MainWindow.__init__` 创建（早于任何页面），closeEvent shutdown |
| 评估页树多选 + 行内按钮点击冲突 | 中 | 误改选中态 | Phase 3 必测；如出问题在按钮 `clicked` 槽里 `event.accept()` 拦截 |
| 16 并发 LLM 题材抽取触发 5xx 限流 | 低 | 单任务失败 | 抽取本体已有重试（22:30 hotfix 装的 `max_attempts=3`）；任务失败不污染其他 |
| 批量删除时被删报告正在队列 RUNNING 抽题材 | 中 | worker 跑完发现 ai_reports 行不存在，落库 INSERT 失败抛异常 | 删除前先扫 manager.all_tasks()，若有命中的 RUNNING 任务弹「⚠️ 该报告正在抽题材中，先取消任务再删」拦截 |
| 「全部提取」一次入队 100+ 任务 | 低 | UI 任务表行数多但仍可滚动 | 弹确认框时显示具体 N，主人自行决定；不做硬上限 |
| 批量删 .md 文件失败（权限 / 文件已被打开） | 低 | 部分行 db 删了但 md 没删 | 复用现有 `delete_report` 错误处理；汇总结果显示 `md_failed_paths` |
