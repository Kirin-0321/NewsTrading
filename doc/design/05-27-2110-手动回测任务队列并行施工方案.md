## 二、技术选型

| 关注点 | 选型 | 理由 |
|---|---|---|
| 并发模型 | 现有 `QThread` 多实例 + 队列管理器 | 沿用 `ManualBacktestWorker`，每个 worker 一个 QThread；不引入 `ThreadPoolExecutor`（PyQt 信号跨线程更适合 QThread） |
| 任务状态机 | 纯 Python `Enum` | 5 态：`PENDING / RUNNING / SUCCESS / SKIPPED / FAILED` |
| 任务对象 | `@dataclass` | 简单透明，包含 id / 参数 / 状态 / 缓冲区 / 结果 |
| 信号转发 | `QObject.pyqtSignal` | worker → manager → page 两层转发，每条信号都带 `task_id` |
| 任务列表 UI | `QTableWidget` | 跟项目其他页一致风格（评估页/抽到题材表都是它） |
| 删除按钮 | `QTableWidget` 第 6 列嵌 `QPushButton` | 沿用项目其他表的"行内动作按钮"模式 |

**禁用项**：
- ❌ `multiprocessing` —— 跨进程序列化代价大，且 SQLite 连接不能跨进程
- ❌ `asyncio` —— PyQt5 集成成本高，本次纯 IO 等待 LLM，QThread 完全够
- ❌ 复杂的优先级队列 —— FIFO 足够，主人没说要插队功能

## 四、核心数据结构

### 4.1 `TaskStatus` Enum

```text
PENDING   - 在队列等空位
RUNNING   - 已分到 worker 跑着
SUCCESS   - 跑完 ok=True 且 !skipped
SKIPPED   - 跑完 ok=True 且 skipped（无新闻 / dry-run）
FAILED    - 跑完 ok=False 或抛异常
```

UI 显示映射（emoji + 中文）：

| status | label | 颜色 |
|---|---|---|
| PENDING | ⌛ 排队 | `#8c8c8c` 灰 |
| RUNNING | ⏳ 跑中 | `#1890ff` 蓝 |
| SUCCESS | ✅ 完成 | `#52c41a` 绿 |
| SKIPPED | ⏹ 跳过 | `#faad14` 橙 |
| FAILED | ❌ 失败 | `#ff4d4f` 红 |

### 4.2 `BacktestTask` dataclass

```text
字段                类型              说明
─────────────────────────────────────────────────────────────
task_id            int               进程内自增主键（从 1 开始）
template_id        str               模板 id
template_label     str               展示用（如 "scalper"）
trade_date         str               YYYYMMDD
news_start_dt      datetime          实际生效左边界
news_end_dt        datetime          实际生效右边界
news_status        str               "curated" / ""
provider           str | None
dry_run            bool
status             TaskStatus        状态机当前值
submit_ts          float             time.time()，用于排序
start_ts           float | None      开始跑的时刻
end_ts             float | None      跑完时刻
elapsed_ms         int | None        end_ts - start_ts
stream_buffer      list[str]         LLM/题材抽取累积的 chunk
log_buffer         list[str]         阶段日志 [HH:MM:SS] msg
theme_section_marked  bool           是否已插过"题材抽取阶段"分隔
result             dict | None       finished_result 信号原样存放
error              str | None        失败时的 error 字符串
worker             QThread | None    跑中时持有，跑完置 None
```

**为什么字段全公开（非 `_` 前缀）**：辉夜的强迫症还有边界，这是 GUI 内部 dataclass，被 manager / page 直接访问，没必要做无谓封装。

### 4.3 `BacktestTaskManager(QObject)`

**职责**：单一职责——管理队列、调度 worker、转发信号到 page。

**对外接口（signal + method）**：

```text
signals:
  task_added(int task_id)
  task_started(int task_id)
  task_progress(int task_id, str msg)         # 阶段日志
  task_streaming(int task_id, str chunk)      # LLM chunk
  task_finished(int task_id)                  # 不论成功/失败/跳过
  task_removed(int task_id)                   # 被主人删了

methods:
  enqueue(task_kwargs: dict) -> int           # 返回新 task_id
  remove(task_id: int) -> bool                # 已完成才允许删；返回是否删成功
  get(task_id: int) -> BacktestTask | None
  list_tasks() -> list[BacktestTask]          # 按 submit_ts 升序
  shutdown() -> None                          # 关 GUI 时取消所有 PENDING
```

**内部字段**：

```text
_tasks: OrderedDict[int, BacktestTask]        # 主表，按 submit_ts 顺序
_pending: deque[int]                          # 排队中的 task_id
_running: set[int]                            # 跑中的 task_id
_max_concurrent: int = 3                      # 固定常量
_next_id: int = 1
```

**调度逻辑**（每次 `enqueue` / `task_finished` 触发 `_pump`）：

```text
_pump():
    while len(_running) < _max_concurrent and _pending:
        tid = _pending.popleft()
        task = _tasks[tid]
        task.status = RUNNING
        task.start_ts = time.time()
        _running.add(tid)
        创建 ManualBacktestWorker(task_id=tid, **task_kwargs)
        连接信号 → _on_worker_xxx(tid, ...)
        emit task_started(tid)
        worker.start()
```

### 4.4 改造后的 `ManualBacktestWorker.__init__`

仅加 `task_id: int` 参数。所有 emit 不带 task_id（manager 用闭包/lambda 拼上）。`run()` 内部逻辑完全不动。

### 5.3 下方三块改"按选中任务渲染"

当前 `_render_md` / `_render_themes` / `stream_browser.insertPlainText` 都直接访问 `self._last_report_path` / `self.stream_browser`，改为：

```text
新增方法：
  _refresh_for_selected_task() -> None
    tid = 当前选中 task_id
    if tid is None: 三块清空
    task = manager.get(tid)
    
    # 流式区：清空 + 回灌
    stream_browser.clear()
    for log_line in task.log_buffer: insertPlainText(log_line)
    for chunk in task.stream_buffer: insertPlainText(chunk)
    
    # md 区：
    if task.status == SUCCESS and result.report_path:
        _render_md(task.result['report_path'])
    elif task.status == FAILED:
        md_browser.setHtml(f"<错误堆栈红字>{task.error}</...>")
    elif task.status == PENDING:
        md_browser.setHtml("<i>⌛ 排队中...</i>")
    elif task.status == SKIPPED:
        md_browser.setHtml(f"<橙字>⏹ 跳过：{task.result.get('error')}</...>")
    else:  # RUNNING
        md_browser.setHtml("<i>⏳ 跑中，完成后显示报告 md</i>")
    
    # 题材区：
    if task.status == SUCCESS: _render_themes(task.result['report_path'])
    else: themes_table.setRowCount(0)
```

### 5.4 信号桥接

```text
self.manager = BacktestTaskManager(self)
self.manager.task_added.connect(self._on_task_added)
self.manager.task_started.connect(self._on_task_started)
self.manager.task_progress.connect(self._on_task_progress)
self.manager.task_streaming.connect(self._on_task_streaming)
self.manager.task_finished.connect(self._on_task_finished)
self.manager.task_removed.connect(self._on_task_removed)
```

各槽函数：
- `_on_task_added(tid)`：在表头插一行，**自动选中这行**（实现"默认选最新提交"）
- `_on_task_started(tid)`：更新该行状态列 + start_ts
- `_on_task_progress(tid, msg)`：写入 task.log_buffer；如果是当前选中任务，append 到 stream_browser
- `_on_task_streaming(tid, chunk)`：写入 task.stream_buffer；如果是当前选中任务，append
- `_on_task_finished(tid)`：状态列染色 + 用时列定格；如果是当前选中任务，重渲 md + themes
- `_on_task_removed(tid)`：从表里删行

## 七、风险登记

| 风险 | 等级 | 应对 |
|---|---|---|
| QThread 在 Python 主线程被 GC 提前回收 | 高 | manager 持有 worker 强引用（在 `_running` task 的 `worker` 字段） |
| 3 并发同时写 ai_inference.db 冲突 | 低 | 已开 WAL；CLI workers=4 实测过；保留观察 |
| LLM provider 限流（429） | 低 | 固定 3，DeepSeek 60req/min 阈值远高于 3×2=6req/min |
| 信号槽线程：worker 在子线程发信号，槽在主线程 | 低 | Qt 默认 `QueuedConnection`，跨线程安全 |
| 主人狂点跑按钮 30 次造成内存暴涨 | 低 | 每个 task 的 stream_buffer 上限 ~ 50KB（DeepSeek 一次回复约 5K~20K 字符），30 个 ≈ 1.5MB，可接受 |
| 删除运行中任务导致 worker 悬空 | 中 | 删除前检查 status==RUNNING → 拒绝；UI 上"删除"按钮在 RUNNING 时灰化 |
| `_render_themes` 查 ai_inference.db 阻塞 GUI | 低 | 仅 SELECT 几行，<10ms；保留现状 |
| QTimer 在 GUI 卡顿时累积事件 | 低 | 用 `Qt.CoarseTimer` 精度，掉一两次 tick 无所谓 |

## 十二、施工顺序铁律

1. **P1 → P2 → P3 → P4 → P5 严格顺序**，不并行；每个 Phase 完先看 ReadLints
2. **P3 是大头**，写到一半就要先把 import / 基本 layout 跑起来用 `python main.py` 烟测一次
3. **不修无关 bug**：施工过程中如发现其他 GUI 问题，记到笔记不动手；本次只做这一件事
4. **遇到 Qt 信号槽 thread affinity 报错**：第一反应检查 manager 是不是 page 的子对象（`BacktestTaskManager(self)` 而非 `BacktestTaskManager()`）
