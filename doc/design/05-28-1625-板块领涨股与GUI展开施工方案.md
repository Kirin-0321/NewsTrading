## 一、目标

1. 把当前 markdown 报告 / GUI 板块表里几乎全空的「龙头股 Top3」列，改成基于**板块成员实际涨幅**的「领涨股 Top3」（板块成员当日涨幅 DESC 前 3）
2. 跌幅榜（Bottom）末列同样填「领跌股 Top3」（成员涨幅 ASC 前 3，含跌停股）
3. GUI split 模式（Top 30 + Bottom 15）每行板块**点击可展开**，展开看该板块**全部成员**（按当日涨幅 DESC 排）

## 二、技术选型

### 2.1 数据来源

- **Tushare `dc_member` 接口**：入参 `ts_code` + `trade_date`，返回 `con_code` / `name`
- 实测白酒板块 BK0896.DC 在 20260527 返回 47 只成员
- ths 源板块（.TI 后缀）不在 dc_member 范围 → 走 grouped 视图的 **dc fallback**（取同组 dc 板块的成员）

### 2.2 新建表 schema

```sql
CREATE TABLE dim_sector_stock (
    sector_ts_code TEXT NOT NULL,    -- 板块代码 BK0896.DC
    stock_ts_code  TEXT NOT NULL,    -- 成员股代码 600519.SH
    stock_name     TEXT,             -- 成员股名（冗余，避 JOIN）
    updated_at     TEXT NOT NULL,    -- 最后同步时间
    PRIMARY KEY (sector_ts_code, stock_ts_code)
);
CREATE INDEX idx_secstock_stock ON dim_sector_stock(stock_ts_code);
```

### 2.3 同步策略

- **首次全量**：CLI `tools/dim_sector_stock_sync.py` 跑 1013 个 dc 板块 → 1013 次 dc_member API（约 5-8 分钟，单线程顺序）
- **周更**：每周日跑一次同 CLI，全量覆盖（成员变化慢，无需做差分）
- **不做日级 trade_date 拆分**：dim_sector_stock 只存"最新"快照，节省 80% 数据量；如未来需要历史成员可加新表

### 2.4 领涨股 Top3 计算

```sql
-- 给定 sector_ts_code + trade_date 查 Top3 涨幅成员
SELECT d.stock_ts_code, d.stock_name, s.pct_chg, s.close
FROM dim_sector_stock d
JOIN fact_stock_daily s 
  ON s.ts_code = d.stock_ts_code AND s.trade_date = ?
WHERE d.sector_ts_code = ?
  AND s.pct_chg IS NOT NULL
ORDER BY s.pct_chg DESC
LIMIT 3
```

ths 板块（中位代表是 .TI）→ 用同组任一 dc 板块的 sector_ts_code 兜底（grouped 视图已有 dc_fallback 逻辑）

## 四、Phase 拆解（工期 ~5-6h）

### Phase A：schema 迁移（0.5h）

新建 `009_dim_sector_stock.sql`，跑 migrate runner。

**验收**：`PRAGMA table_info(dim_sector_stock)` 含 4 字段 + 索引。

### Phase B：fetcher + CLI 全量同步（2h）

- `tushare_fetcher.py` 加 `fetch_dim_sector_stock_full()`：遍历 `dim_sector` 里 src='dc' 的板块，每个调 dc_member 入库
- `tools/dim_sector_stock_sync.py` CLI：
  - `--idx-type 概念板块/行业板块/地域板块/all`（默认 all）
  - `--force-refresh`：先 TRUNCATE 再灌
  - 输出 progress：每 50 个板块打一行

**验收**：跑 `python tools/dim_sector_stock_sync.py` → dim_sector_stock 行数 ≈ 5 万-10 万（1013 板块 × 平均 50 成员）；白酒 BK0896.DC 47 行命中。

### Phase C：领涨股 Top3 查询 + service 接入（1h）

- `sector_grouping.py` 加 `compute_sector_leaders(conn, sector_ts_code, trade_date, *, limit=3, ascending=False)` 函数
- `service._read_sectors_top` / `_read_sectors_bottom` 内部循环：
  - 拿 `ts_code` 给中位代表板块
  - 若 ts_code.endswith(".TI") → 走 group_id 找同组 dc 板块的 ts_code
  - 调 `compute_sector_leaders(...)` 取 Top3 leaders / laggards
- 旧 `_derive_sector_leaders` 保留为 fallback（dc 板块没成员关联数据时）

**验收**：Top 30 板块行至少 80% 有 leaders 数据（dc 源板块 + grouped 视图 ths 板块靠 fallback）

### Phase D：renderer 改表头 + 填 Top3（0.5h）

- 涨幅榜：列名「龙头股 Top3」→「领涨股」，cells 渲染从 `f"{name}({status})"` 改成 `f"{name} +{pct:.1f}%"`
- 跌幅榜：列名「领跌」→「领跌股」，cells 同款（`-{pct:.1f}%`）

**验收**：重渲染 20260527，markdown 出现具体股票名+涨幅，如「`贵州茅台 +2.31%`」

### Phase E：GUI sector_table 升级为 QTreeWidget（1.5h）

- `sector_table` / `sector_table_bottom` 改为 `QTreeWidget`（保持 12 列结构）
- `_fill_sector_table` → `_fill_sector_tree_compact`：每个板块作为顶层 item，可展开
- 展开时**懒加载**调 `query_sector_members(sector_ts_code, trade_date)` 填子级（成员股名 / 当日涨幅 / 收盘价 / 涨停状态）
- 子级行结构（少列）：`# / 股票（代码） / 涨幅 / 收盘 / 状态`
- 单击行已绑定 `userRole=ts_code`（保留），双击不变

**验收**：GUI 启动 → 板块行有展开三角；点击展开 → 看到该板块成员股（白酒 BK0896.DC 展开 47 行）

### Phase F：CLI / 回归测试 / 上线（0.5h）

## 五、风险登记

| # | 风险 | 缓解 |
|---|---|---|
| R1 | dc_member 1013 次 API 中部分接口抖动失败 | 单板块失败不阻塞，落 warnings；CLI 提供 `--retry-failed` |
| R2 | dim_sector_stock 表数据量大（~10 万行）影响其他查询 | 加 `idx_secstock_stock`；JOIN fact_stock_daily 用 SQL 子查询 LIMIT 3 性能可控 |
| R3 | QTreeWidget 替换 QTableWidget 破坏现有事件绑定（双击复制代码等） | 改前先看现有 connect；QTreeWidget 同样支持 itemDoubleClicked |
| R4 | ths 板块（约 1/3 行）成员关联缺失 | 走 grouped 视图的 dc_fallback：取同组 dc 板块的成员 |
| R5 | 板块成员当日 fact_stock_daily 数据缺失 | LEFT JOIN，pct_chg NULL 时不进 Top3 |
| R6 | 现有 QTableWidget 用户点击习惯改变 | 升级为 QTreeWidget 后单击行为不变，只是多了展开三角 |
