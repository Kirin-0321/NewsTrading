## 一、目标

把"报告级评分"的 D+N 数值口径，从**纯板块涨幅 sector_pct** 改为
**「板块涨幅 0.6 + 题材内标的均值涨幅 0.4」的加权合成涨幅**；
当题材当日 stock_avg_pct 缺失（标的全 NULL 或题材无标的）时，
直接退回 **1.0 × sector_pct**（不打折，与 v2 旧口径等价的兜底）。

主人 5 项决策点（已锁）：

| Q | 决策 |
|---|---|
| Q1 作用层 | **仅改报告级 `get_report_eval`** —— 题材级第 2 层（`get_theme_eval_for_report`）/ 模板级第 1 层（`get_template_eval`）保持 sector_pct 口径不变 |
| Q2 实现路径 | **A 方案：新增 `theme_pct` 字段 + 迁移 + 重打分** |
| Q3 无标的兜底 | `stock_avg_pct IS NULL` → `theme_pct = sector_pct`（系数 1.0） |
| Q4 alpha 口径 | `alpha = theme_pct - benchmark_pct`（统一新口径，所有层都受益） |
| Q5 存量数据 | 30 天回填重打分 |

公式：

```
若 sector_pct IS NULL                       → theme_pct = NULL
若 stock_avg_pct IS NULL（无标的有效数据）  → theme_pct = sector_pct
否则                                          → theme_pct = sector_pct * 0.6 + stock_avg_pct * 0.4

alpha = theme_pct - benchmark_pct（替换原 stock_weighted_pct - benchmark_pct）
```

## 二、技术选型

- 新增字段而非内联 SQL 表达式：好处是题材详情 Tab `get_theme_score_detail` 直接看到合成值；后续若再调权重，只需改一处算法 + 重打分一次，不必到 3 个聚合 SQL 同步改公式
- 复用现有迁移机制 `services/storage/ai_inference_db.py` 自动 apply
- 重打分复用现有 `tools/score_themes.py` CLI（`--rescore-range`）

## 四、Phase 拆解（工期 ~1.5h）

### Phase 1（10min）数据库迁移

- 新建 `services/storage/ai_migrations/002_add_theme_pct.sql`
- 走 `python services/storage/ai_inference_db.py` 自检触发 apply

### Phase 2（30min）算法层

- `script_scorer.py`：
  - 加 `_compute_theme_pct` 私有函数（纯函数无副作用）
  - `ThemeDailyScore` dataclass 加 `theme_pct` 字段
  - `score_theme_on_date` 中：
    1. `theme_pct = _compute_theme_pct(sector_pct, stock_avg_pct)`
    2. `alpha = theme_pct - benchmark_pct`（替换原 `stock_weighted_pct - benchmark_pct`）
  - `_UPSERT_TPS` 加 `theme_pct` 列（INSERT 列表 + ON CONFLICT 更新列表都加）

### Phase 3（10min）聚合层

- `scoring_service.py`：
  - `get_report_eval` 函数的 `per_theme` CTE 中：
    - `MAX(CASE WHEN tps.days_offset=N THEN tps.sector_pct END)` →
      `MAX(CASE WHEN tps.days_offset=N THEN tps.theme_pct END)`
  - 其他 SQL 一概不动
  - 顶部 docstring 把"报告级 D+N = sector_pct 加权"改为"theme_pct 加权"

### Phase 4（30min）测试用例

- 加 3 个 case_11/12/13 验证 theme_pct 三种分支 + alpha 新口径
- 改 case_22 夹具与期望：原 `stock_weighted_pct=99` 不再被读，新增 `stock_avg_pct` 字段；
  期望值需用新公式手算
- case_24（全看空场景）维持 NULL 兜底，但 stock_avg_pct 也补真值（不影响断言）

### Phase 5（5min）回归

- `python tools/test_script_scorer.py` → 13/13 全绿
- `python tools/test_scoring_eval.py` → 24/24 全绿

### Phase 6（10min）30 天回填

- `python tools/score_themes.py --rescore-range --start 30天前 --end 今天`

### Phase 7（5min）文档同步

- 写 `doc/updates/05-28-17NN-报告评分加权改造上线.md`
- 更新 `.huiye/README.md` 顶部进度行

## 五、风险登记

| 风险 | 概率 | 缓解 |
|------|------|------|
| 迁移失败导致 ai_inference.db 损坏 | 低 | ensure_schema 内置 pre-migration 备份；回滚直接拷回 .bak |
| 旧打分行 theme_pct 全 NULL 导致 GUI 报告级 D+N 突然全空 | 中 | Phase 6 全量重打分；过渡期 UI 不报错（`_fmt_pct(None)` 已支持） |
| 标的数据完整度不一 → theme_pct 跳跃 | 低 | 这是正确反映"加权口径下数据稀疏度"的语义，不是 bug |
| alpha 字段语义变化未告知主人 | 低 | 上线日志显式说明；Q4 已确认 |
