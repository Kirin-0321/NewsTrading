## 一、是什么

> **一句话**：把评估页"打分"从「**标的当日涨跌的算术平均**」改成「**题材绑定板块的当日涨跌**」；同时把报告级从「**题材等权平均**」改成「**按题材强度加权平均**」。

**前置工程**：当前 60% 的题材绑定的板块缺行情数据（行业板块从未拉过），要先把数据底料补齐，下游算法改造才走得通。

**类比**：
- 现状像"**用 5 个学生的平均分代表班级水平**"（题材里抽的 5 只标的代表整个题材）
- 目标像"**直接看班级整体平均分**"（直接看板块当日涨跌幅）+「**重点班权重大，普通班权重小**」（按题材强度加权）

---

## 二、为什么做（用户情景）

### 痛点 1：题材级数据失真

当前题材级 D+N = **题材内 AI 抽出来的几只标的的算术平均**。

**问题**：AI 抽的标的只是"代表"，不是题材的全部——比如「半导体」题材 AI 只抽了 3 只龙头，但板块里有 200 多只股票。**3 只龙头一齐冲高 8%，但 200 多只板块成员平均只涨 1.5%**——题材级显示 +8% 严重高估了真实题材表现。

### 痛点 2：报告级"小题材绑架大题材"

当前报告级 = **该报告下所有题材 D+N 的算术平均**，**所有题材一视同仁**。

**问题**：AI 给每个题材打了 strength_score（-100~+100，"看好程度"），但报告级把强度 90 的"硬科技核心题材"和强度 30 的"次要题材"同等权重——主人看到的报告平均分被边缘题材稀释，模板的"主要观点"反而被淹没。

### 痛点 3：行业板块行情数据从未抓过（**前置 bug**）

截图主人已经看到："半导体（BK1036.DC）板块在 dim_sector 字典里有名字，但 fact_sector_daily 没数据"。

**根因**：现有的板块行情接口（Tushare `moneyflow_ind_dc`）调用时**只拉了 content_type="概念"**——行业板块（如稀土/钴/镍/被动元件/半导体）从未拉过。

**影响范围**：
- `dim_sector` 字典里有 **496 个行业板块** + **31 个地域板块**——全部没行情
- **150 个题材（占已绑板块题材的 39.5%）绑到了行业板块**——这些题材即使改用 sector_pct 也是空

## 三、具体要求

### 要求 1：先修数据，再改算法

**不允许"算法和数据并行改"**——数据不补齐，算法切过去就是 40% 题材显示空，主人要骂人。改造分 3 个 Phase 严格串行：

```
Phase A: 补行业板块行情数据
   ↓ 验收：fact_sector_daily 覆盖 dim_sector ≥ 95%
Phase B: 改算法 + 落库新口径
   ↓ 验收：评估页 D+N 数字按新口径展示，单元测试全绿
Phase C: GUI 显示 + 文档同步
   ↓ 验收：评估页有"算法说明"提示，主人能一眼看懂数字含义
```

### 要求 2：保留标的级展示

**不删除当前标的级（树形第 3 层）**——AI 抽的"具体看好哪几只股"是有独立分析价值的，跟板块整体表现是两件事。
- 题材级 D+N → 板块涨跌幅（**新口径**）
- 标的级 D+N → 个股涨跌幅（**保持现状**，仍来自 fact_stock_daily）

### 要求 3：边界情况要明确

| 情况 | 处理 |
|------|------|
| 题材没绑 sector_ts_code（67 个，15%）| 题材级 D+N 显示 — + 角标"⚠ 未绑板块" |
| 板块绑了但 fact_sector_daily 没数据（Phase A 后应≈0）| 同上 |
| 报告下所有题材都没板块数据 | 报告级 D+N 显示 — |

### 要求 4：报告级加权后必须 100% 透明

主人必须能在评估页**清楚看到**：
- 这份报告的 D+1=+5.39% 是**怎么算出来的**——把每个题材的 strength_score 和 D+1 列在题材级行里，主人手算能验证。

## 四、预期效果

### 效果 1：题材级 D+N 表达"题材整体走势"

- **现状**："MLCC/被动元件" D+1=+8.53%（2 只 AI 抽的标的均值）
- **改后**："MLCC/被动元件" D+1=+2.1%（被动元件板块当日涨跌幅，反映板块 50+ 只成分股整体表现）

### 效果 2：报告级 D+N 反映"模板主要观点"

假设报告 X 有 4 个题材：
- 半导体（强度 +90）D+1=+3% 
- AI 算力（强度 +80）D+1=+2%
- 大消费（强度 +20）D+1=-1%
- 银行（强度 -10）D+1=-0.5%

| 算法 | D+1 |
|------|-----|
| **现状**（题材等权）| (3+2-1-0.5)/4 = **+0.875%** |
| **改后**（按 \|strength\| 加权）| (3×90+2×80-1×20-0.5×10)/(90+80+20+10) = **+2.125%** |

主人一眼看到：模板**重点看好的硬科技确实涨了**，被边缘题材稀释的问题消失。

### 效果 3：60% → 95%+ 板块覆盖率

- **现状**：dim_sector 里 1033 个板块只有 506 个有行情（49%）
- **改后**：补完行业板块后预期 ≥ 1002/1033 ≈ **97%**（地域板块如有需要再补）

## 五、决策点（请主人勾选）

> ⚠️ 这部分必须主人逐项勾选确认后辉夜才写施工方案。**未确认就开工 = 返工**。

### 决策点 1：行业板块行情数据接入哪个数据源？

| 选项 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **A**（辉夜推荐）| 复用现有 `moneyflow_ind_dc` 接口 + `content_type="行业"`/`"地域"` | 同源、零新依赖、字典 ts_code（.DC 后缀）天然对齐 | 仅东财分类 |
| B | 新接同花顺 `moneyflow_ind_ths` | 行业更细 | 需要新建 dim_sector ts_code（.THS 后缀），matcher 字典改 |
| C | 新接申万 `moneyflow_ind_sw` | 申万分类标准（券商常用）| 同 B，需要建立 .SW 字典 |
| D | A + B 双源 | 互为补充 | 双倍 API + 数据 dedup 复杂 |

**辉夜建议 A**：截图里"半导体（BK1036.DC）"已经存在 dim_sector，说明历史拉过 dc_index 接口（行业板块字典已建），只是 moneyflow_ind_dc 调用时漏了 content_type="行业"。**这是补漏，不是新接源**——最稳妥。

**主人选**：☐ A  ☐ B  ☐ C  ☐ D  ☐ 其他

---

### 决策点 2：题材没绑板块（67 个，15%）怎么处理？

| 选项 | 说明 |
|------|------|
| **A**（辉夜推荐）| 题材级 D+N 显示 — + 行尾角标"⚠ 未绑板块"，**不 fallback** |
| B | fallback 到当前算法（标的均值），保证有数据 |
| C | fallback 到"按题材关键词模糊匹配最强相关板块" |

**辉夜建议 A**：fallback 会掩盖 matcher 不命中的问题，让主人发现不了"AI 题材抽的板块名字根本不在字典里"这种 bug。显示 — + 角标更诚实。

**主人选**：☐ A  ☐ B  ☐ C  ☐ 其他

---

### 决策点 3：报告级加权平均的权重选哪个？

| 选项 | 权重 | 说明 |
|------|------|------|
| **A**（辉夜推荐）| `\|strength_score\|` | 强度绝对值，反映"AI 看好/看空程度"。利空题材也参与（看空就该看空，跌得越多 direction_correct=1）|
| B | `priority_rank` 反向（rank=1 权重 N, rank=N 权重 1）| 用 AI 给的优先级排名 |
| C | 题材内标的数 | 大题材权重大 |
| D | 主流标的数（仅 role="核心"）| 排除"辐射/受益"小标的 |

**辉夜建议 A**：strength_score 是 AI 给的最直接的"看好程度"，且 schema 里已经统一为 -100~+100 有符号字段。绝对值加权语义清晰，不分模板都能用。

**注意**：A 在"全部题材 strength_score=0"的边界下需要 fallback 到等权——这种情况按主人示意决策。

**主人选**：☐ A  ☐ B  ☐ C  ☐ D  ☐ 其他

### 决策点 4：旧打分数据怎么办？

之前 447 个题材 × ~5 天 = 大约 2200 行 `theme_prediction_scores` 都是按"标的均值"口径打出来的。

| 选项 | 说明 |
|------|------|
| **A**（辉夜推荐）| `theme_prediction_scores` 表加新字段 `sector_pct`（已有）+ `weighted_pct_v2`（新加），保留旧字段。GUI 切换显示 v2 字段。**老数据不动**，新打分双写 | 
| B | 全量重打分（清空 scores 表，按新口径重算 380 个题材 × 5 天）| 
| C | 新加表 `theme_prediction_scores_v2`，老表保留只读 |

**辉夜建议 A**：`theme_prediction_scores.sector_pct` 字段**早就存在**（看 script_scorer.py），现在评估页只是没用它显示而已。改 GUI SQL 就够，不动数据。但需要确认 sector_pct 字段历史是否一直在写——如果有空缺需要 backfill。

**主人选**：☐ A  ☐ B  ☐ C  ☐ 其他

## 六、Q&A

### Q1：改了之后单股票打分还有意义吗？

**有**。标的级保留，是 AI 抽的"具体看好哪几只"的实战参考。题材级看板块、标的级看具体票，两个数据维度都保留。

### Q2：α 和命中率列要不要跟着改？

**可以分批讨论**。本次改造只动 D+N 那 5 列。α / 命中率 / direction_correct 现在的语义是"基于标的"的，改动空间另开议题。

### Q3：改造工期估计？

待主人勾选决策点后辉夜在施工方案里给精确估算。粗估：
- Phase A（数据接入）：0.5 天
- Phase B（算法）：1 天
- Phase C（GUI + 文档）：0.5 天
- 合计 **2 天**

### Q4：风险点？

1. Tushare `moneyflow_ind_dc(content_type="行业")` 接口能否正常返回数据——施工方案里第一步就是 smoke test
2. 历史回填行业板块数据要拉多少天——一期建议只拉**评估期 30 天**，避免一次性把 API 配额打爆
3. 加权平均的 fallback（strength_score 全 0）边界——施工方案里写明
