## 二、技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| Schema 改动 | **无破坏性 DDL**——字段不增不删，仅切换语义 | `is_hit` / `direction_correct` 字段名保留；新公式直接复用现有列 |
| `direction_correct` 累计算法 | **二阶段写入**：先 INSERT 当前行（direction_correct = NULL）→ 读取 D+1..D+N 全部 theme_pct → 累乘判定 → UPDATE 当前行 | 避免循环依赖；SQLite 单连接事务内安全 |
| 利空过滤位置 | **打分入口直接 raise `SkippedTheme` 异常**，service 层捕获不计入失败 | 干净分离"业务跳过" vs "技术失败"；service 层无需特殊知识 |
| `pct_chg − zz1000` 取值 | 复用 `theme_prediction_scores.benchmark_zz1000_pct` 已有列 | 标的级 `is_hit` 判定时从 tps 父行读 zz1000，避免重复查 `fact_index_daily` |
| GUI 标的级命中标记 | 复用现有 `d1_hit ~ d5_hit` 字段（位于 `get_stock_scores_for_theme` 返回），染色 + 文本符号 ✓/✗ 双轨展示 | 不增列宽，最小侵入 |
| 历史数据清空 | CLI 一次性脚本（不在调度器触发） | 主人手动执行，符合"不自动操作敏感数据"原则 |

### 3.2 `script_scorer.py` 改动详情

**新增异常**：

```python
class SkippedTheme(Exception):
    """题材被业务规则跳过（非技术失败）。
    
    当前触发场景：strength_score ≤ 0（利空 + 中性），打分阶段直接跳过。
    """
```

**`score_theme_on_date` 入口加守卫**：

```python
def score_theme_on_date(theme_id, score_date, *, ...):
    ...
    theme = _load_theme(conn, theme_id)
    strength = theme["strength_score"]
    if strength is None or strength <= 0:
        raise SkippedTheme(
            f"theme_id={theme_id} strength_score={strength} ≤ 0，"
            f"利空/中性题材不参与打分"
        )
    ...
```

**`is_hit` 计算改造**（在 `score_theme_on_date` 内、`stock_score_rows` 构造前）：

```python
# 原逻辑（一刀切 3%）：
# is_hit = 1 if float(pct) >= hit_threshold_pct else 0

# 新逻辑（α 自适应阈值）：
alpha_threshold = float(strength) / 20.0  # 单位 %
# benchmark_zz1000_pct 此时已查好
zz = benchmark_zz1000_pct  # 当日 zz1000 涨跌
for r in stock_rows:
    pct = r["pct_chg"]
    if pct is None or zz is None:
        is_hit = None
    else:
        alpha = float(pct) - zz
        is_hit = 1 if alpha > alpha_threshold else 0
```

**题材级 `hit_rate` 切换为"当日有效标的命中比"**（语义微调，公式同改）：

```python
# 分母 = 当日 pct_chg 非 None 且 zz 非 None 的标的数（不再含缺数据标的）
# 分子 = 同分母条件下 alpha > 阈值 的标的数
valid_pcts = [p for p in pcts if p is not None]  # 既有
hit_count = sum(1 for p in valid_pcts if (p - zz) > alpha_threshold) if zz is not None else 0
total_count = len(valid_pcts)  # 改：原来是 len(stock_rows)
hit_rate = (hit_count / total_count) if total_count > 0 else 0.0
```

**`direction_correct` 累乘累计判定**（写库之后二阶段 UPDATE）：

```python
def _compute_cumulative_direction(
    conn: sqlite3.Connection,
    theme_id: int,
    current_score_date: str,
) -> Optional[int]:
    """读取 D+1..D+N 所有 theme_pct，累乘判 > 1。"""
    rows = conn.execute(
        "SELECT days_offset, theme_pct FROM theme_prediction_scores "
        "WHERE theme_id = ? AND score_date <= ? "
        "ORDER BY days_offset ASC",
        (theme_id, current_score_date),
    ).fetchall()
    if not rows:
        return None
    product = 1.0
    for r in rows:
        pct = r["theme_pct"]
        if pct is None:
            continue  # 主人规则：缺失日按 0 处理 → 因子 = 1（即 *1）
        product *= (1.0 + float(pct) / 100.0)
    return 1 if product > 1.0 else 0
```

`_write_scores` 改造为先 INSERT 主表（direction_correct 占位 NULL），再调上述函数取累计判定，再 UPDATE 当前行：

```python
def _write_scores(conn, result):
    # Step 1: INSERT 主表（direction_correct 先填 None）
    result.direction_correct = None  # 占位
    conn.execute(_UPSERT_TPS, (... 现有参数, None, now))
    # Step 2: INSERT 子表（不变）
    if result.stock_rows: conn.executemany(_UPSERT_TSS, ...)
    # Step 3: 计算累计方向并 UPDATE 当前行
    cum_dir = _compute_cumulative_direction(conn, result.theme_id, result.score_date)
    if cum_dir is not None:
        conn.execute(
            "UPDATE theme_prediction_scores SET direction_correct = ? "
            "WHERE theme_id = ? AND score_date = ?",
            (cum_dir, result.theme_id, result.score_date),
        )
        result.direction_correct = cum_dir  # 回写 dataclass 供调用方观察
```

**移除 `_compute_direction` 函数**（旧"strength × sector 同号"逻辑作废，直接删）。

### 3.3 `scoring_service.py` 4 处 SQL 改动详情

**所有 4 处共性**：

- 利空过滤已经在打分阶段完成，DB 里没有 strength_score ≤ 0 的打分行
- SQL 层 `WHERE strength_score > 0` 保留为**防御性**（防止未来旁路写入老数据）
- `hit_rate_avg` 字段语义切换：从 `AVG(tps.hit_rate)` 改为"标的级累计命中率均值"

**a) `get_template_eval`**：

- `per_theme` CTE 加新字段：
  - `hit_rate_new`：从 `theme_stock_scores` 现推 = `AVG(SUM(is_hit)/COUNT(*) per stock)`
  - `direction_cum`：取 `MAX(CASE WHEN days_offset = 5 THEN direction_correct END)`，没有 D+5 则取最大 days_offset 行的值
- `per_report`：`SUM(hit_rate_new * ABS(strength_score)) / SUM(ABS(strength_score))` 加权
- `tpl_basics`：`AVG(hit_rate_new)` 跨题材 + `direction_correct_rate = AVG(direction_cum)` 跨题材

**b) `get_report_eval`**：同 a) 结构

**c) `get_theme_eval_for_report`**（**关键改动**）：

- 加 `WHERE tp.strength_score > 0` 过滤利空（GUI 第 2 层不再看到利空题材）
- `hit_rate_avg`：标的级累计命中率均值（从 `theme_stock_scores` 现推）
- `direction_correct`：题材级 5 天累计判定（取 D+5 行的 `direction_correct`）
- `ORDER BY tp.strength_score DESC, tp.priority_rank ASC NULLS LAST, tp.id ASC`

**d) `get_stock_scores_for_theme`**：

- 新增字段 `stock_hit_rate`：`SUM(is_hit) / COUNT(*) FILTER (WHERE is_hit IS NOT NULL)`
- 新增字段 `valid_days`：`COUNT(*) FILTER (WHERE is_hit IS NOT NULL)`
- d1_hit ~ d5_hit 已有，无需新增

## 五、风险登记

| # | 风险 | 触发场景 | 缓解 |
|---|------|---------|------|
| 1 | `_compute_cumulative_direction` SELECT 自己刚 INSERT 的行 | SQLite 默认事务隔离应该可读，但 sqlite3 模块默认 autocommit + isolation_level=None 时行为需验证 | Phase 1 加 case_22 显式验证"先 INSERT 后 SELECT 同事务内能读到"，若失败改用预先收集再 INSERT 一步 |
| 2 | `benchmark_zz1000_pct` 当日缺数据（节假日 / 数据未抓） | `is_hit` 全部 None | 测试用例覆盖（test_script_scorer case_15 已有，复用） |
| 3 | 累乘公式遇到 -100% 涨跌幅（理论上跌停 +ST 极端） | 累计因子 = 0，剩余天数无论如何累计 = 0 | 业务上不存在（A 股 -10% 是单日极限），不特殊处理 |
| 4 | GUI 已展开题材列表后改了 strength_score | 列表显示顺序与最新 SQL 不一致 | 主人点「刷新」按钮重查即可，不做实时监听 |
| 5 | 主人没跑 `purge_scoring_data` 就触发了新代码打分 | 旧口径行与新口径行混在 DB 里，聚合结果错乱 | Phase 5 上线日志明确"先跑 purge"步骤；调度器跑前先检查 `theme_prediction_scores` 是否有"非累计 direction_correct" 老行（暂不实现，仅文档警告） |
| 6 | `delete _compute_direction` 后某处遗留调用 | ImportError | `rg "_compute_direction"` 全仓搜确认没有其他引用 |
| 7 | `SkippedTheme` 异常被 service 层当 ScoringError 吞掉 | 利空题材打分会被计入 errors 列表（误报） | service 层 try/except 改为先 catch SkippedTheme 静默通过，再 catch ScoringError 计入 errors |
