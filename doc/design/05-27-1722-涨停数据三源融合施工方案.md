## 二、技术选型

### 2.1 新增 Tushare 接口

| 接口 | 用途 | 调用次数/天 |
|------|------|-------------|
| `limit_list_ths(limit_type='涨停池')` | 主源（数据最全 + lu_desc）| 1 |
| `limit_list_ths(limit_type='连扳池')` | 高度榜独立泳池（tag 更全：`7天5板` 这种间断梯队）| 1 |
| `limit_list_ths(limit_type='炸板池')` | 炸板池补全（比 limit_list_d.Z 多 6 只）| 1 |
| `limit_list_ths(limit_type='跌停池')` | 跌停池补全（比 limit_list_d.D 多 18 只）| 1 |
| `limit_list_ths(limit_type='冲刺涨停')` | 独立表存 17 只盘中准涨停股 | 1 |

**新增 5 次 API/天**（同花顺接口共享 8000 积分配额，每分钟 500 次，无压力）。

### 2.2 三源融合优先级（COALESCE 顺序）

| 字段 | 优先级 | 备注 |
|------|--------|------|
| `close` | ths > d | kpl 的 close 永远 NULL |
| `pct_chg` | ths > d | 同上 |
| `fd_amount_yi` | ths.limit_amount > kpl.limit_order > d.fd_amount | 三源数值一致，取最高优先 |
| `limit_up_time` | kpl.lu_time（带冒号，可读）> d.first_time（无冒号）| ths 默认不返回此字段 |
| `open_times` | d.limit_times（100% 覆盖）> ths.open_num（56%）| kpl 永远 NULL |
| `status`（"3连板"）| kpl.status > parse(ths.tag) | ths.status="换手板" 是形态非高度 |
| `cons_nums` | parse(kpl.status) > parse(ths.tag) > 历史递归推算 | 已有 v2 fallback |
| `theme` | kpl 独家 | 不冲突 |
| **`lu_desc`** | **ths 独家** | 新增字段 |
| **`limit_up_suc_rate`** | **ths 独家** | 新增字段 |
| **`market_type`** | **ths 独家** | 新增字段（HS/GEM/STAR）|
| **`tag`** | ths 独家（"7天5板"）| kpl.tag 是 "涨停"，无信息 |
| `free_float` | ths > kpl | 实际流通市值 |
| `industry` | d 独家 | 保留（D4-A 决策）|
| `total_mv` | d 独家 | 保留（D4-A 决策）|

### 2.3 表设计：扩列 vs 新表

| 数据 | 选择 | 原因 |
|------|------|------|
| 涨停池（U）/ 炸板池（Z）/ 跌停池（D）| **扩 `fact_limit_stock` 列** | 主键 (trade_date, ts_code, limit_type) 已能容纳，无需新表 |
| 连扳池 | **复用 `fact_limit_stock`（U + cons_nums>=2）** | 是涨停池子集，不重复存 |
| 冲刺涨停 | **新表 `fact_limit_sprint`** | 不属于涨停股（pct<10%），独立泳池 |

## 三、模块拆分 / 表结构 / 接口签名

### 3.1 数据库迁移：`services/market/migrations/006_three_source_limit.sql`

```sql
-- 006_three_source_limit.sql  涨停数据三源融合
-- ==========================================================
-- 1. fact_limit_stock 扩列（同花顺 lu_desc / limit_up_suc_rate /
--    market_type / tag / free_float / industry / total_mv / source）
-- 2. 新增 fact_limit_sprint（冲刺涨停池，独立表）
-- ==========================================================

-- SQLite ALTER 不支持一次加多列，逐条加（已存在则 IF NOT EXISTS 保护写在 migration runner）
ALTER TABLE fact_limit_stock ADD COLUMN lu_desc            TEXT;
ALTER TABLE fact_limit_stock ADD COLUMN limit_up_suc_rate  REAL;
ALTER TABLE fact_limit_stock ADD COLUMN market_type        TEXT;       -- HS / GEM / STAR
ALTER TABLE fact_limit_stock ADD COLUMN tag                TEXT;       -- "7天5板" 等高度
ALTER TABLE fact_limit_stock ADD COLUMN free_float         REAL;       -- 实际流通市值（元）
ALTER TABLE fact_limit_stock ADD COLUMN industry           TEXT;       -- 申万行业（来自 d）
ALTER TABLE fact_limit_stock ADD COLUMN total_mv           REAL;       -- 总市值（元，来自 d）
ALTER TABLE fact_limit_stock ADD COLUMN source             TEXT;       -- "d+kpl+ths"/"kpl+ths"/...

-- 冲刺涨停池（独立表，不是涨停股）
CREATE TABLE IF NOT EXISTS fact_limit_sprint (
    trade_date        TEXT NOT NULL,
    ts_code           TEXT NOT NULL,
    name              TEXT,
    close             REAL,         -- price
    pct_chg           REAL,
    rise_rate         REAL,         -- 涨速
    turnover_rate     REAL,
    turnover          REAL,
    free_float        REAL,
    lu_desc           TEXT,         -- 涨停原因
    market_type       TEXT,
    raw_json          TEXT,
    PRIMARY KEY(trade_date, ts_code)
);
CREATE INDEX IF NOT EXISTS idx_sprint_pct
    ON fact_limit_sprint(trade_date, pct_chg DESC);
```

### 3.2 fetcher：`services/market/tushare_fetcher.py`

#### 3.2.1 调用链顺序（修改 `fetch.steps` 列表）

```
原: ... → limit_list_d × 3 → kpl_list 今日 → kpl_list 昨日 → ...

新: ... → limit_list_d × 3       (保留，最先入库，作为骨架)
        → kpl_list 今日           (合并 status/cons_nums/theme/lu_time)
        → limit_list_ths × 4      (主源：涨停池/连扳池/炸板池/跌停池

                                   /market_type/free_float)
        → limit_list_ths 冲刺涨停  (独立表 fact_limit_sprint)
        → kpl_list 昨日           (不变，仅内存)
        → ...
```

def _format_ladder_item(it):
    name  = it.get('name') or ''
    theme = it.get('theme') or ''
    desc  = it.get('lu_desc') or ''
    rate  = it.get('limit_up_suc_rate')
    parts = [name]
    if theme: parts.append(theme)
    if desc and desc != theme: parts.append(desc)
    if rate is not None: parts.append(f"封板率{rate*100:.0f}%")
    return f"{parts[0]}（{'/'.join(parts[1:])}）" if len(parts)>1 else name

## 五、风险登记

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| **R1**：ths 接口当日延迟（同花顺也偶尔慢）| 低 | 当日 ladder 仍可能空 | 已有 v2 历史递归 fallback，d/kpl 任一活就能撑住 |
| **R2**：科创板 20% 涨停的 pct_chg 在 schema validator 的 `pct_chg_range` 已是 22.0，无需调 | 低 | 无 | 验证现有 range 即可 |
| **R3**：fact_limit_stock 主键含 limit_type，ths 涨停池新增的 18 只股要写 `limit_type='U'` | 中 | 主键冲突 | 用 `INSERT OR IGNORE` + 后续 UPDATE 合并 |
| **R4**：lu_desc 含特殊字符（`+` 号）渲染到 markdown 表格时不需转义 | 低 | 显示乱 | 渲染时不进表格，进列表 |
| **R5**：连扳池 ts_code 集合 ≠ 涨停池 cons_nums>=2 集合（同花顺口径差异）| 中 | 数据对账冲突 | 以涨停池为准；连扳池仅取 tag 字段合并；差异写 warnings |
| **R6**：历史 7 天数据没补 lu_desc → 旧报告无 lu_desc 字段 | 中 | AI 报告新旧不一致 | D6-A 仅回填 5/27；7 天回填若主人需要再开一轮（可选）|
| **R7**：market_type 字段已有 dim_stock.market 字段（"主板/创业板"），命名冲突 | 低 | 易混淆 | 改名 `ths_market_type`，备注独立来源；不污染 dim_stock |
| **R8**：cons_nums 解析 ths.tag（"7天5板"）逻辑要新增 | 中 | 解析失败 fallback | metrics.parse_cons_nums 已支持多格式，加正则 `^(\d+)天(\d+)板$` 取后者；失败回退 v2 历史递归 |
