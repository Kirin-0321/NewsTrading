## 需求背景

主人 2026-05-26 提出「目前的 GUI 显示的还不够全面」。

第六轮 review 配套扫描发现：**后端 `MarketSummary` JSON 有大量字段没渲染到 GUI 上**——`Renderer` 的 Markdown 版本完整、`merger` 产出的 `conflicts` / `field_sources` 完全没显示、龙头股 / 涨跌家数 / 完整度分层 / regulation Tab 全部缺失，部分指数卡片甚至是**始终为空的死键**（`sci` / `cybs`）。

简单说：**功能在后端跑得没问题，但 GUI 只露了一半**。

---

## 设计目标

1. **零后端改动**：本方案只动 `gui/pages/market_summary_page.py`（以及必要的 `gui/workers/`）。`services/market/*` 完全不动。
2. **分层交付**：A / B / C 三档，主人可独立勾选任意组合；A 是必做（修 bug + 补现有字段），B 是建议（新增 Tab），C 是选做（深度交互）。
3. **不引新依赖**：所有可视化在不引入 `matplotlib` / `pyqtgraph` 的前提下完成（除非主人勾 B4 图表）。
4. **保持现有视觉风格**：沿用 `gui/utils/styles.py` 的 BUTTON_STYLE / TABLE_STYLE / COMBOBOX_STYLE。
5. **可验证**：每一项都给出"做完后应该看到什么"，避免再出现"打勾打半天结果什么都没做"的悲剧。

## 风险与取舍

| 风险 | 影响 | 对策 |
|------|:---:|------|
| A1 修指数键名后旧缓存 summary 渲染异常 | 低 | indices 取数用 `.get(key, {})`，缺失走 "—" 路径 |
| A3 龙头股列宽抢占催化列空间 | 中 | 提供两种布局方案，主人选 |
| A4-α 直查 DB 增加 GUI 耦合 | 中 | 把 DB 查询封到 `gui/utils/market_db_helper.py` 隔离 |
| A4-β 动后端违背"零改动"原则 | 中 | 仅加一个字段，单元测试覆盖 |
