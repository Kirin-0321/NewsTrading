# 功能设计·主人通读版：评估页「提取题材 / 批量提取 / 批量删除」+ 预测题材页「任务队列」

> 本文档**只谈"是什么 / 为什么 / 用户情景"，不含技术栈、表结构、函数签名**。
> 主人审过后，再开施工方案文档定技术细节。

---

## 一、是什么（一句话 + 类比）

把评估页从「只能看 / 只能单点删」升级为「能看、能批量删、能直接发起题材提取」；同时在预测题材页给现有的「单文件抽取 UI」**新增一块任务队列面板**——评估页扔过来的批量提取任务，统一在这条队列里排队跑。

类比：现在评估页像一个**只读的报告清单**，主人发现某份报告没题材时只能切到预测题材页手选 .md 再点提取，一份份处理；改造后评估页本身就是**调度台**，看见就能下单（提取 / 删除），下完单切到预测题材页看任务进度即可。

---

## 二、为什么做（用户情景）

### 主人当前痛点（已经发生的真实场景）

1. **评估页里 5 月 26 日 / 27 日满屏的"✗ 无题材"灰色按钮无法点击**（截图主人发的）：
   - 这些回测报告生成时题材抽取失败 / 跳过，只能切到预测题材页**一份份手选 .md 重抽**——14 份未抽报告 = 14 次点击 + 14 次等待
2. **没有批量删除**：误生成的回测报告（同一模板同一天跑了 12 次……）当前只能一行一行点「✕ 删除」按钮，14 行 = 14 次确认弹窗
3. **预测题材页的「手动抽取」是单线程串行**：连点 N 次抽取按钮会被「抽取正在进行中」拒绝，而手动回测页早就有「连点排队 + 8 并发」的体验，对比之下预测题材页落后一截

### 不做会怎样

- 14 份未抽报告 = 14 次切页 + 14 次手选 .md 文件 + 14 次手动等待，估算 30+ 分钟主人时间；批量删除同理
- 预测题材页「手选 .md 抽取」永远是单文件单线程，主人想跑十几份历史回测的题材抽取就只能眼巴巴等

## 三、具体要求（主人已决策的硬约束）

### 3.1 评估页的 3 个新增动作

#### A. 行内「✗ 无题材」按钮 → 改为可点击的「🎯 提取题材」按钮

- 位置：下方树形表「文件名/理由/按钮」列，每行最右侧
- 触发后行为（**主人决策 q1 = toast_only**）：
  - **不切 Tab**——主人当前可能正在评估页对照其他报告；
  - 仅弹一条短提示「✅ 已加入队列，去预测题材页看进度」；
  - 该行的按钮立刻变「⌛ 已入队」灰色，禁用，避免重复点击；
  - 真正的进度展示由主人自己切到预测题材页看队列。

#### B. 表头「⚡ 全部提取（未抽题材）」按钮

- 位置：表头控制条（与现有「🔁 重打分」「⚡ 一键打分未完成」按钮并列）
- 范围（**主人决策 q2 = current_filter**）：仅当前筛选范围内（受【时间维度 / 最近 N 天 / 回测过滤】影响）的 `themes_count = 0` 报告
- 行为：弹确认框「将批量提取 N 份未抽题材的报告（最近 X 天，含回测/真实），全部入队到预测题材页？」点确认后批量入队 + toast 提示

#### C. 表头「🗑 批量删除」按钮 + 树多选

- **多选方式**（**主人决策 q3 = tree_multiselect**）：树启用 Ctrl+点（增减单行）/ Shift+点（范围）多选，**不加 checkbox 列**（保持表头清爽）
- **删除规则**（**主人决策 q4 = allow_with_modal**）：
  - 选中的报告里若**全是回测**，直接弹「将删除 N 份回测报告（含 .md 文件 + 数据库行 CASCADE），不可恢复」
  - 若**含 N 份真实报告**，弹更醒目的二次确认「⚠️ 选中含 N 份真实分析报告。真实报告通常是历史决策记录，删除后无法重生。是否继续？」
  - 用户最终点「确认」才执行；批量删 = 逐行调用现有「单报告删除」服务，统一一份汇总结果
- **删 .md 文件**：与「单报告删除」对齐，默认删（保留 db 行 CASCADE 的现有语义）

### 3.2 预测题材页新增「任务队列」面板

#### A. 位置（**主人决策 q5 = 列表放在右上角的空白区域**）

预测题材页当前上半区是「📥 手动抽取题材」分组，里面纵向堆着：文件选择行 / 抽取按钮 / 日志 / AI 流式预览，**整块都靠左占满**。改造后：

- 上半区改为**左右两栏**布局；
- **左栏**保留原内容（文件选择 / 抽取按钮 / 日志 / 流式预览）原样不动；
- **右栏**就是新增的「任务队列」面板——这就是主人说的"右上角空白区域"。
- 下半区「📊 已入库题材」**完全不动**。

#### B. 队列面板的内容（参考手动回测页·精简版）

| # | 报告名 | 状态 / 用时 | 删除 |
|---|---|---|---|
| 12 | 5月26日_0时00分_盘后总结分析报告_speculator_scalper.md | ⏳ 跑中 / 00:42 | （RUNNING 不可删） |
| 11 | 5月26日_0时00分_盘后总结分析报告_value.md | ✅ 完成 / 01:18 | 🗑 |
| 10 | 5月26日_0时00分_盘后总结分析报告_aggressive.md | ⌛ 排队 / — | 🗑 |
| 9 | 5月25日_..._comprehensive.md | ❌ 失败 / 00:08 | 🗑 |

- 5 态机与手动回测一致：⌛ 排队 / ⏳ 跑中 / ✅ 完成 / ⏹ 跳过 / ❌ 失败
- 顶部一栏：并发数微调器（**主人决策 q6 = 默认 16，范围 1~64**）+ 「全部清掉已完成」小按钮
- 点击行的预期：**第二期再做**（手动回测页是点行联动下方流式 / md / 题材，但预测题材页下半区是「已入库题材库」，强行联动会破坏现有体验，第一期先不做点行联动，只显示状态）

#### C. 任务来源（3 个入口都汇入这一条队列）

1. 评估页「🎯 提取题材」（单行）→ 入队 1 个任务
2. 评估页「⚡ 全部提取」→ 批量入队 N 个任务
3. 预测题材页原有「🚀 开始抽取并入库」按钮 → **行为切换**：原来是直接调线程跑，改造后改为入队 + 立刻切到右栏队列看进度（保持 UI 入口熟悉）

### 3.3 不做的事（避免过度设计）

- ❌ 不在评估页预测题材页之间做"自动切 Tab"（主人选了 toast）
- ❌ 不在评估页树加 checkbox 列（主人选了 Ctrl/Shift 多选）
- ❌ 不做点击队列任务联动主区域的「点行联动」（一期不做，预测题材页下半区是库视图不是回测产物视图）
- ❌ 不做任务持久化（关 GUI 队列清空，与手动回测一致）
- ❌ 不重构核心抽取算法（`ThemeExtractor` / `ThemeStore` / 落库逻辑全部不动，只是把外层调度从单线程升级为队列）

## 四、预期效果（做完之后主人能怎么用）

### 场景 1：清理 5 月 26 日的 12 份未抽题材回测报告

1. 主人在评估页筛选「最近 3 天 / 仅回测」，看见 12 行「✗ 无题材」
2. 点表头「⚡ 全部提取」→ 弹「将提取 12 份报告，进入预测题材页队列？」→ 确认
3. toast 提示「✅ 12 个任务已入队」
4. 主人切到预测题材页，右上角队列开始跑（默认 16 并发，但只有 12 个 → 全部并行跑）
5. ~3 分钟后 12 行全部 ✅ 完成，主人切回评估页「🔄 刷新」，原 12 行的「✗ 无题材」变成「⚡ 打分」可点击按钮 + 题材数显示

### 场景 2：批量清理误生成的回测报告

1. 主人在评估页用 Ctrl+点 / Shift+范围 选了 8 行（含 6 回测 + 2 真实）
2. 点「🗑 批量删除」→ 弹「⚠️ 选中含 2 份真实分析报告，真实报告通常是历史决策记录…是否继续？」
3. 主人确认 → 8 份报告 + 8 个 .md 文件全部删除，CASCADE 清掉关联题材 / 标的 / 打分行
4. 表格自动刷新，剩下的行重新整齐

### 场景 3：预测题材页连点抽取多份报告

1. 主人手选 .md A → 点「🚀 开始抽取并入库」→ 任务 1 入队 + 立即开跑
2. 不等任务 1 完成，再选 .md B → 点 → 任务 2 入队
3. 连点 5 次共 5 个任务，前 N 个并发跑，后面排队
4. 右栏队列实时显示进度

## 五、与现有体系的关系（潜在冲突点）

### 5.1 与「评估页·一键打分未完成」按钮的区别

- 「⚡ 一键打分未完成」：补齐已抽题材但未跑完 D+1~D+5 打分的报告
- 「⚡ 全部提取（未抽题材）」：补齐**根本没题材**的报告（前置条件）
- 两个按钮**互补**，并列展示，不冲突

### 5.2 与「手动回测·并行队列」的差异

- 手动回测：跑完整一次报告生成（时间窗 + 模板 + LLM 分析 → 落 ai_reports 行 + 写 .md）
- 题材抽取：基于已存在的 .md 报告，调 LLM 抽取题材结构（不写 .md，落 ai_inference 主表）
- 两条流水线独立，**互不干扰**，但 UI 层面共享同一个队列设计语言（5 态机 / 状态色 / 用时计时器 / 删除按钮）

### 5.3 删除真实报告的安全防线

主人选了 q4 = `allow_with_modal`（允许删真实但弹二次确认）。这与现有「单报告删除」按钮的 `allow_real=False` 默认行为**不同**——单点删除默认拒删真实，批量删除允许但弹强提示。施工方案里要明确这一不一致，避免主人疑惑。

## 六、决策结论（已与主人在问答中确认）

| 决策项 | 主人选择 |
|---|---|
| 评估页提取后是否切 Tab | ❌ 不切，只 toast |
| 「全部提取」作用范围 | 仅当前筛选范围内的 `themes_count=0` 报告 |
| 批量删除多选方式 | 树原生 Ctrl/Shift 多选（不加 checkbox 列） |
| 是否允许批量删真实报告 | ✅ 允许，但弹「含 N 份真实」二次确认 |
| 队列面板位置 | 预测题材页上半区改左右两栏，右栏放队列 |
| 队列默认并发 / 范围 | 默认 16，范围 1~64 |

## 七、给主人审核的 Q&A

**Q1：右栏队列只占右半，会不会挤压左栏的 AI 流式预览？**
A：左栏现有内容总高度约 260px，左右切分后**横向**变窄（原 100% → 50%），但纵向不动；流式 JSON 预览本来字号小（12px monospace），50% 宽度仍可读。如果主人觉得挤，可以把 splitter 设为可拖（参考手动回测页同款）。

**Q2：14 份任务并发跑会不会触发 LLM 限流？**
A：默认 16 并发与 DeepSeek V4 Pro 的 60+ req/min 阈值是匹配的（手动回测同款实测稳定）；若真发生 5xx，单个任务失败不影响其他，主人重试即可。如果想保守，主人可以把并发数手动调小到 4~8。

**Q3：如果主人正在预测题材页用「手选 .md 抽取」，评估页又点了「全部提取」，两边的任务会不会打架？**
A：不会。所有任务都进同一条队列、同一个并发池；手选 .md 抽取也走"入队 + 跑队头"的逻辑，只是一次只入 1 个；评估页批量入队 N 个；都按入队顺序串成一条队列，并发池统一调度。

**Q4：失败任务能否重试？**
A：第一期不做"重试"按钮——主人切到评估页对该报告再次点「🎯 提取题材」就是事实上的重试。第二期再考虑加。

**Q5：内容文档审过之后下一步？**
A：辉夜写**施工方案文档**：选技术栈（复用 `BacktestTaskManager` 还是新造一个 `ThemeExtractTaskManager`）/ 任务对象字段 / 评估页与预测题材页之间怎么传递任务（信号 / 单例管理器）/ Phase 拆解 / 测试 checklist。施工方案再过主人一次（重大功能），最终落地。
