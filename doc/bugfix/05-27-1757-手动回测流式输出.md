# 手动回测流式输出 + AnalysisService 题材抽取 callback 漏传修复

> 类型：bugfix / 增强  
> 时间：2026-05-27 17:57  
> 受影响页面：`gui/pages/manual_backtest_page.py`、`gui/pages/ai_analysis_page.py`（间接受益）  
> 相关链：见 [题材抽取打分完整流程](../design/05-27-1025-题材抽取打分完整流程.md) Phase 6

---

## 一、问题描述

主人在「🎛️ 手动回测」页点「🚀 正式跑回测」后，GUI 30~60s 内**完全静止**：
- 上方「⏱ 时间边界预览」是跑**前**预览，跑期间不变
- 下方「📄 报告 md 预览」要等回测**完成**才填充
- 状态栏 `status_label` 只切换粗粒度阶段文本（"重建快照..." / "LLM 调用完成"）

观感像"假死"，主人无从知道当前进度，更看不到 LLM 在写什么。

---

## 二、根因分析

底层 LLM 早已 `stream=True`（见 `core/ai_news_analyzer.py:_stream_chat` 和 `core/theme_extractor.py:_call_llm`），AI 分析页 / 题材抽取页都已实现了 `streaming` 信号桥接，但**回测路径上三处断链**：

| 断点 | 文件:行号 | 性质 |
|------|----------|------|
| ❌ `_maybe_extract_themes()` 调 `extract_from_file` 没传 `progress_callback` | `services/analysis_service.py:383` | **存量 bug**：连 AI 分析页跑题材抽取也看不到流式 |
| ❌ `backtest_one()` / `_run_analyze_and_mark_backtest()` 无 `progress_callback` 参数 | `tools/backtest_prompt.py:133, 293` | callback 无法穿透到 `AnalysisService.analyze` |
| ❌ `ManualBacktestWorker` 仅 `stage`，无 `progress` / `streaming` 信号 | `gui/workers/manual_backtest_worker.py:35-37` | QThread→GUI 桥不存在 |
| ❌ `ManualBacktestPage` 没有流式预览控件 | `gui/pages/manual_backtest_page.py:_build_md_group` | UI 缺位 |

---

## 三、修复方案

### 调用链贯穿 `progress_callback`

```
ManualBacktestWorker.run()
  ├─ 构造 progress_callback(msg, is_streaming=False)
  │     ├─ is_streaming=True  → self.streaming.emit(msg)
  │     └─ is_streaming=False → self.progress.emit(msg)
  └─ backtest_one(progress_callback=...)
        └─ _run_analyze_and_mark_backtest(progress_callback=...)
              └─ AnalysisService.analyze(progress_callback=...)
                    ├─ AINewsAnalyzer._stream_chat(progress_callback)   # 分析 chunk
                    └─ _maybe_extract_themes(progress_callback)
                          └─ ThemeExtractor.extract_from_file(
                                progress_callback=progress_callback     # ← 本次新加
                             )
                                └─ ThemeExtractor._call_llm(progress_callback)  # 题材 chunk
```

### GUI 改造（`ManualBacktestPage`）

`_build_md_group` 内部加垂直 `QSplitter`：

```
┌── toolbar：status_label + 📂 打开 md ───┐
├── QSplitter(Qt.Vertical) ───────────────┤
│   上：🤖 AI 实时输出（流式 chunk 粘连）  │
│   下：📄 完成后报告 md 预览              │
└─────────────────────────────────────────┘
```

- `stream_browser` 双阶段复用：LLM 分析 → 题材抽取（出现"题材"关键词时插一行分隔线 `────── 题材抽取阶段 ──────`）
- `progress` 信号 → `_append_progress` 带 `[HH:MM:SS]` 时间戳追加
- `streaming` 信号 → `_append_stream` 直接 `insertPlainText` 粘连

### CLI 增强（`tools/backtest_prompt.py`）

新增 `--verbose` 选项：
- 阶段日志整行打印 `  [stage] xxx`
- LLM chunk 每 64 个累计打印一个 `.`
- `workers>1` 时输出会交错，主人按需关闭

## 四、影响范围

| 模块 | 行数 | 类型 |
|------|------|------|
| `services/analysis_service.py` | +1 行 | **存量 bug 修复**（AI 分析页也受益） |
| `tools/backtest_prompt.py` | +30 行 | 参数 + 阶段日志 + CLI `--verbose` |
| `gui/workers/manual_backtest_worker.py` | +20 行（含 docstring） | 双信号 + callback 桥 |
| `gui/pages/manual_backtest_page.py` | +50 行 | `stream_browser` + splitter + 信号绑定 |

兼容性：
- `backtest_one()` 的 `progress_callback` 为 `Optional`，默认 `None`，**所有现存调用方零改动**
- CLI 默认不开 `--verbose`，输出与历史一致
- `ManualBacktestWorker` 新增的 `progress` / `streaming` 信号是叠加，旧 `stage` 信号保留并继续 emit

### 正式跑（待主人手工验证）

主人在 GUI「🎛️ 手动回测」页：
1. 选模板 + 历史交易日（建议选已有 backtest 的日期 + 勾「已存在则覆盖」）
