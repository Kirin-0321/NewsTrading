# bugfix · 2026-05-27 18:30 · 报告日期协议错位 + 回测产物命名重构

## 一、症状

主人在评估页点报告级表格的「单报告打分」按钮（截图）：

```
rescore 线程异常: ValueError: 日期格式应为 YYYYMMDD，得到 '2026-05-22'
  File "services/scoring/scoring_service.py", line 688, in rescore_one_report
    score_dates = _eligible_score_dates(...)
  File "services/scoring/scoring_service.py", line 278, in _eligible_score_dates
    sd = next_trade_date(report_date, n)
  File "services/market/trade_date.py", line 172, in next_trade_date
    _ensure_yyyymmdd(date_str)
ValueError: 日期格式应为 YYYYMMDD，得到 '2026-05-22'
```

主人同时观察到回测产物的**文件名错乱**：

```
data/AI_analysis/5月27日/5月27日_18时12分_盘后总结分析报告_backtest_20260522.md
```

——明明是 5 月 22 日的模拟回测，前缀却是「5月27日_18时12分」即真实生成时间，
后缀 `_backtest_20260522` 才是模拟交易日。

## 二、根因（两条相互纠缠的债）

### 债 #1：schema 协议被违反

| 处 | schema 注释 | 实际入库 |
|---|---|---|
| `ai_reports.report_date` | `YYYYMMDD` | `YYYY-MM-DD` |
| `theme_predictions.report_date` | `YYYYMMDD` | `YYYY-MM-DD` |
| `theme_prediction_scores.report_date` | `YYYYMMDD` | （新表暂空） |
| `theme_stock_scores.report_date` | `YYYYMMDD` | （新表暂空） |

源头有两处 `datetime.now().strftime("%Y-%m-%d")`：

- `core/theme_extractor.py::parse_report_meta` — 走 mtime/now 推 `report_date`
- `services/analysis_service.py::_record_ai_report` — 给 `ai_reports.report_date` 用

施工方案文档 `.huiye/_construction_backtest_v3_1.md` line 607 早就明确：

> `report_date` 字段格式：v5 统一 YYYYMMDD（在 theme_extractor 入口已规范化，本算法直接用）

但实现一直没对齐，于是积下 16 行错误格式的数据（1 条 ai_reports + 15 条 theme_predictions）。

### 债 #2：回测产物事后 rename + UPDATE 链路脆弱

旧链路 `tools/backtest_prompt.py::_run_analyze_and_mark_backtest`：

1. 调 `AnalysisService.analyze()` 用真实时间命名文件，比如 `5月27日_18时12分_..._.md`
2. 入库 `ai_reports.report_date = today (YYYY-MM-DD)`
3. 调 `_rename_to_backtest` 物理重命名加 `_backtest_{trade_date}` 后缀
4. 显式 UPDATE `ai_reports / theme_predictions SET report_date = 'YYYY-MM-DD'`（模拟交易日）

这条链路有 4 个问题：

- 文件名前缀仍是真实生成时间，对人和程序都误导
- UPDATE 把 `report_date` 强制覆盖为 `'2026-05-22'`（dash 格式），打分链路下游
  调用 `next_trade_date('2026-05-22')` → `_ensure_yyyymmdd` 报错
- 链路太长，rename + UPDATE 任何一步失败都会留半成品
- `_has_existing_backtest` / `_delete_existing_backtest` 也必须把 YYYYMMDD 转 dash 才能匹配，重复绕路

### 隐藏 P1 bug（连带顺手治）

`rescore_range`（GUI「区间重打分」按钮）的 SQL：

```sql
SELECT id, report_date FROM theme_predictions
WHERE report_date BETWEEN ? AND ?
```

传入参数是 `YYYYMMDD`（如 `'20260520'`），表里实际是 `'2026-05-22'`（dash）。
字典序比较时 `'-' (0x2D) < '0' (0x30)`，区间**永远查不到 0 条**，
区间重打分按钮**一直在静默跑空**——但没人报告，因为没报错。

## 三、修方案（治本）

### 命名规则统一

| 场景 | 文件名 | 入库 report_date | is_backtest |
|---|---|---|---|
| AI 分析页生成 | `5月27日/5月27日_18时12分_盘后总结分析报告.md` | `20260527` | 0 |
| 回测 CLI 生成 | `5月22日/5月22日_0时00分_盘后总结分析报告_backtest.md` | `20260522` | 1 |

### 改造点（按调用链）

| 文件 | 改动 |
|---|---|
| `core/ai_news_analyzer.py` | `save_report` / `analyze` 新增 `naming_dt` + `backtest_suffix` 参数；命名时间由调用方驱动 |
| `services/analysis_service.py` | `analyze` 新增 `simulated_trade_date: Optional[str]`；驱动 `naming_dt` + `_record_ai_report` 入库 `is_backtest=1` + `report_date=该日期` + `_maybe_extract_themes` 入库 theme 时同步覆盖 |
| `core/theme_extractor.py` | `parse_report_meta` 优先从文件名前缀正则 `^(\d+)月(\d+)日_(\d+)时(\d+)分_` 解析月日时分；年份从 mtime 兜底；返回 `report_date` 统一 YYYYMMDD |
| `tools/backtest_prompt.py` | **删 `_rename_to_backtest` 函数**；`_run_analyze_and_mark_backtest` 从 80 行 → 30 行薄壳（一行 `svc.analyze(simulated_trade_date=trade_date)`）；`_has_existing_backtest` / `_delete_existing_backtest` 去 dash 转换直接用 YYYYMMDD |
| `services/storage/theme_store.py` | `save_themes` 入口加 `_ensure_yyyymmdd(report_date)` 防御 |
| `services/storage/ai_reports_store.py` | `AIReportsStore.record` 入口同样防御 |
| `services/scoring/scoring_service.py` | `_eligible_score_dates` 入口加 `_ensure_yyyymmdd`；`get_template_eval / get_report_eval` 的 `cutoff_dash` → `cutoff_compact` |

### GUI 显示侧适配

`services/` 层返回 raw YYYYMMDD，`gui/` 层用 helper 转 dash 显示，避免协议
被显示语义污染：

| 文件 | 用途 |
|---|---|
| `gui/utils/date_format.py`（**新建**） | `format_yyyymmdd_to_dash()` / `dash_to_yyyymmdd()` |
| `gui/pages/prompt_eval_page.py` | 上表「最近报告日」/ 下表「报告日期」/ 删除确认弹窗「日期」/ CSV 导出 2 处 |
| `gui/pages/theme_prediction_page.py` | 日期 combo 显示文本（`itemData` 仍是 YYYYMMDD） |

|---|---|
| `tools/test_backtest_e2e.py` 大部分断言基于旧链路（事后 rename / UPDATE / dash 格式），与新链路不一致 | 头部 docstring 加 `.. warning::` 注明；最小化适配让 `_seed_fake_report` 不触发入口防御；**等主人择期重写** |
