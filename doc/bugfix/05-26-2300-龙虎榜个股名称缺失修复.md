# 05-26 23:00 — 龙虎榜个股表「名称」列只有「—」修复

## 现象

GUI「🐉 龙虎榜」Tab → 上方「龙虎榜个股」表：
- 代码列正常（002185.SZ / 600172.SH / ...）
- **名称列全部 `—`** ← 主人截图反馈

## 根因

### 根因 1：`dim_stock` 维度表整体 0 行

```text
> dim_stock 表总行数: 0
> 002185.SZ 直查 dim_stock: (not found)
```

`dim_stock` 在 `migrations/001_initial.sql` 中定义存在，但**整个代码库
没有任何 `INSERT INTO dim_stock` 语句**——既没有 Tushare `stock_basic`
接口的 fetcher，也没有任何 backfill 工具往里写数据。

### 根因 2：`service.py._read_dragon_tiger` 写死 `name=None`

第 949~953 行：
```python
stocks.append({
    "ts_code": str(r["ts_code"]),
    "name": None,                  # M2 阶段 join dim_stock   ← TODO 未兑现
    "net_amount_yi": _round(r["net_yi"], 2),
    ...
})
```

跟 ladder 的 leaders 字段一样，写了「M2 阶段 join dim_stock」就再没人回填。

### 根因 3：GUI 兜底 `query_stock_names` 也查 `dim_stock`

之前为了补这个空，我在 `gui/utils/market_db_helper.py` 加了 `query_stock_names`
helper，但它也查 `dim_stock` → 0 行表 → 永远返回空 dict → GUI 显示 `—`。

## 改动

### 修改（service.py）
- `_read_dragon_tiger` SQL 改为：
  ```sql
  COALESCE(d.name, MIN(json_extract(t.raw_json, '$.name'))) AS stock_name
  ```
  优先级：`dim_stock`（未来补全时）→ `fact_top_list.raw_json.name`（top_list
  接口已经返回了名字，这字段一直都在 raw_json 里没被用）
- `stocks.append` 写入：`"name": str(r["stock_name"] or "")` 代替 `None`

### 数据
- 20260526 单日 force-refresh（45s），龙虎榜个股 name 字段从 None →
  完整名称（93/93 全覆盖）

## 长期遗留：dim_stock 表仍是 0 行

虽然龙虎榜的 name 通过 raw_json 兜底解决了，但 `dim_stock` 长期空表导致：

| 影响场景 | 当前状态 |
|---|---|
| 龙虎榜个股名称 | ✅ 已兜底（raw_json） |
| 板块龙头股 leaders 派生 | ✅ 已兜底（fact_limit_stock.raw_json） |
| ladder 涨停股名称 | ✅ 已兜底（同上） |
| **未来 / 其他场景**（按 ts_code 反查行业、上市日期等） | ❌ 没数据 |


成本：
- 代码：~30 行（一个 fetcher 函数 + 一个 CLI 入口）
