## 二、修复内容

### 2.1 Bug 1 + Bug 2：跌幅榜表头（同一段代码）

`services/market/renderer.py` 第 286-294 行（`_render_sectors` 函数 Bottom 表）：

**修改前**：

```python
lines.append(
    "| # | 板块 | 成员 | 跌幅 | 5日累计 | "
    "主力净流出(亿) | 跌停数 | 笨蛋 |"           # ← typo
)
lines.append(
    "|---|------|------|------|--------|"
    "--------------|------|------|------|"      # ← 9 列分隔符，多 1 个
)
```

**修改后**：

```python
lines.append(
    "| # | 板块 | 成员 | 跌幅 | 5日累计 | "
    "主力净流出(亿) | 跌停数 | 领跌 |"           # ← 「笨蛋」→「领跌」
)
lines.append(
    "|---|------|------|------|--------|"
    "--------------|------|------|"             # ← 8 列分隔符对齐 8 列表头
)
```

### 2.2 Bug 3：全市场主力净流入口径

`services/market/service.py` 第 770-810 行（`_read_capital_flow` 函数）：

**核心 SQL 变化**：

```sql
-- 修改前（v2 改造后炸了）
SELECT SUM(main_net_yi) AS s, COUNT(*) AS n
FROM fact_sector_daily WHERE trade_date = ?

-- 修改后
SELECT SUM(s.main_net_yi) AS s, COUNT(*) AS n
FROM fact_sector_daily s
JOIN dim_sector d ON d.ts_code = s.ts_code
WHERE s.trade_date = ?
  AND d.idx_type = '概念板块'
  AND d.src = 'dc'
```

`main_net_source` 字段也同步更新文案：`sum_sector_daily(n=1489;...)` → `sum_dc_concept_sector(n=486;...)`。

## 三、修复效果对比（20260527 实测）

| 维度 | 修复前 | 修复后 |
|---|---|---|

| markdown 渲染 | 部分解析器列错位 | 严格对齐 |

### 3.2 数据层（Bug 3）

执行 `SELECT (src, idx_type) → SUM(main_net_yi)` 拆分查询：

| src | idx_type | n | SUM(main_net_yi) 亿 |
|---|---|---:|---:|
| dc | 地域板块 | 31 | -987.02 |
| **dc** | **概念板块** | **486** | **-22115.63** ← 新口径 |
| dc | 行业板块 | 496 | -3005.46 |
| ths | 同花顺概念 | 386 | -22378.00 |
| ths | 同花顺行业 | 90 | -1244.00 |
| **合计** | **（旧错口径）** | **1489** | **-49730.11** ← 旧 bug |

修复后：**-49730 亿 → -22115 亿**，回到 v1 物理合理范围。

> ⚠️ 注意：-22115 亿对当日总成交 3.24 万亿仍偏大，原因是 **dc 概念板块本身就含「同股属多概念」的重复**（一只股可能属 3-5 个概念），所以这个值仅作宏观风向指标，**不等于个股层主力净流入合计**。彻底无重复升级（如锁定 dc 东财一级行业 31 个的 SUM）是 P1 设计要谈的事，本次 hotfix 不动设计。
