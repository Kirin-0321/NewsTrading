# Bugfix：盘后数据「逐表幂等」缓存修复

> 日期：2026-05-27 19:20
> 影响范围：`services/market/tushare_fetcher.py` + `services/market/service.py` + `config/market_summary_schema.json`
> 关联设计：[内容文档](../design/05-27-1850-盘后数据逐表幂等缓存设计.md) / [施工方案](../design/05-27-1900-盘后数据逐表幂等缓存施工方案.md)

## 一、症状

主人在 2026-05-27 18:36 反映：
- 点了「获取/重新获取」按钮（hybrid 模式 + 强制重拉）
- 状态栏显示「完整度 95.6%」看起来正常
- 但「全部个股」Tab 显示「**共 0 只**」

## 二、根因（双层早退）

### 第 1 层：`MarketSummaryService.build()` 缓存命中早退

旧逻辑（`service.py:243-250`）：

```python
if not force_refresh:
    cached = self.get(td)
    if cached.ok:
        cached.from_cache = True
        return cached    # ← 直接 return，绕过 fetcher
```

`market_summaries` 表里有当天的 `summary_md` → 整个流程 short-circuit，fetcher 14 步全不跑。

### 第 2 层：`TushareMarketFetcher.fetch()` 早退

旧逻辑（`tushare_fetcher.py:161-170`）：

```python
elif self._has_index_data(trade_date):
    result.skipped.append("all")
    return result    # ← 14 步全 skip
```

只要 `fact_index_daily` 有 7 行就整批跳 14 步。

### 第 3 重病灶：`fact_stock_daily` 根本不在 fetcher 工作清单里

fetcher 14 步里**没有任何一步写 `fact_stock_daily`**。第 14 步 `_fetch_market_breadth` 虽然调了 `daily(trade_date)` 拿到 5506 行原始数据，**但只用来聚合涨跌家数后丢弃**，从不写明细表。

唯一能写 `fact_stock_daily` 的入口是 `services/scheduled_runner.py` 的 `stock_daily_sync` 任务类型——这是**计划任务专属**，主人没在用。

## 三、修复方案

总体语义：**缓存 = 逐表幂等**（缺啥补啥，已有的不重抓）。

### 1. fetcher 层：14 + 1 个 step 逐表自检

- **A 组（9 个独立表）**：进入函数最前面加 2 行检测，已有数据 → 加入 `skipped` 列表返回
  - step 1/3/7/9/10/11/12/13/14
- **B 组（4 个共写 `fact_limit_stock`）**：在 step 4 进入前调 `_purge_limit_stock` 清当日，5/6 顺序追写（PK 冲突 INSERT OR REPLACE 覆盖）
  - step 4 加 purge，step 5/6 自然承袭
  - **step 8 `_fetch_kpl_prev` 是「仅内存」步骤**（结果存 `result.kpl_prev_rows` 给 metrics 用，不写库），与共享表无关
- **新增 step 15**：调 `sync_stock_daily` 写 `fact_stock_daily`（复用既有幂等函数）

### 2. service 层：缓存命中改 fall-through

`market_summaries` 命中后仍调 `fetcher.fetch(force=False)` 让 14+1 个 step 自检补缺。
绝大多数情况下表都已齐 → 15 次 `COUNT(*)` 毫秒级，仍接近秒级体验。

### 3. force_refresh 全清

`_purge_trade_date` 加上 `fact_stock_daily`，确保「强制重拉」14+1 张表全部清空重写。

### 4. 完整度评分纳入

- `_build_summary_from_db` 在拼 `breadth` 节点时多查一行 `COUNT(*) FROM fact_stock_daily`
- 写入 `summary.breadth.stock_daily_rows`
- `config/market_summary_schema.json` 加 `breadth.stock_daily_rows: {layer:L1, weight:2, required:true}`
- validator schema-driven 自动生效
