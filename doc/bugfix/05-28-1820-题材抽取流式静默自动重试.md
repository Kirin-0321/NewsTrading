## 一、问题现象

主人在手动回测页跑模板时，**有时候进行到「题材抽取阶段」会卡住**——UI 上流式输出一段时间后停滞、CPU 空载、卡几十秒甚至几分钟也不报错。

```
[18:05:12] 开始：custom_1 @ 2026-05-22 ...
[18:05:14] LLM 分析完成，开始抽题材...
[18:05:18] {"themes": [{...   ← 流式输出到这里就不动了
            ...                 ↑ 卡几十秒~几分钟，主人盯着空白等
```

## 二、根因分析

### 2.1 直接根因：流式静默阈值太大（1200s）

`core/theme_extractor.py::_call_llm` 用 httpx 流式调用 LLM，超时由 `_http_timeout(self.timeout)` 控制：

```python
def _http_timeout(seconds: float):
    sec = max(float(seconds), 60.0)
    return Timeout(connect=15.0, read=sec, write=sec, pool=sec)
```

`self.timeout` 默认读 `config/ai_config.json::theme_extraction.timeout`，例配里写的 **1200**（秒）。

> httpx 在 SSE/流式场景下，`read` timeout 的语义是 **"相邻 chunk 间最大等待秒数"**——即 chunk 之间的心跳间隔阈值。

设成 1200s，意味着：
- 正常情况下 LLM 每秒会推几个 chunk，远低于 1200s
- 但当服务端 SSE 连接 **静默断流**（不主动 close，也不再推 chunk），客户端会傻等 1200s 才抛 `ReadTimeout`
- → **主人看到的"卡住"现象**

### 2.2 间接根因：完全没有重试机制

即便 1200s 后真的超时了，`extract_from_text` 当时的实现是：

```python
try:
    raw_response = self._call_llm(report_text, progress_callback)
except Exception as e:
    return [], f"调用 LLM 失败: {e}"   # 一次失败直接放弃
```

provider 偶发 5xx / 限流 / 短暂网络抖动，全部一次性失败。在手动回测页"连点 N 次排队"的场景下，单点故障率会随并发数线性放大。

### 2.3 半成品坑

本次修复开始前发现 `core/theme_extractor.py` 有一段**未提交的半成品代码**——`__init__` 已经把 `self.timeout` 字段替换成 `self.stream_idle_timeout / self.max_attempts`，docstring 也加了重试章节，但 `_call_llm` 第 256 行**还在引用已删除的 `self.timeout`**：

```python
http_timeout = self._http_timeout(self.timeout)   # ← AttributeError！
```

这意味着 hotfix 落地前这段代码**根本跑不通**——所有题材抽取调用都会在第一次入参时崩溃。但因 worker 子线程 try/except 兜底，崩溃被吞成日志，主人看到的就是"卡住"。这是另一个被掩盖的 P0。

## 三、修复方案

### 3.1 砍 httpx `read` timeout，引入"流式静默阈值"

把 `theme_extraction.timeout=1200` 重新解释，新增独立字段 `stream_idle_timeout`：

| 字段 | 默认值 | 语义 |
|---|---|---|
| `stream_idle_timeout` | **60s** | 流式 chunk 间最大静默秒数（= httpx read timeout）。正常 LLM chunk 间隔 < 5s，超 60s 视为断流/假死 |
| `max_attempts` | **3** | 含首次的最大尝试次数（首次 + 2 次重试） |
| `timeout` | 1200（保留） | 仅作向后兼容：用户旧配置没有 `stream_idle_timeout` 时，取 `min(timeout, 60)` 兜底 |

### 3.2 `extract_from_text` 包重试循环

```python
for attempt in range(1, self.max_attempts + 1):
    if attempt > 1 and progress_callback:
        progress_callback(f"⏳ 题材抽取第 {attempt}/{self.max_attempts} 次尝试（上次失败：{last_err_msg}）")
    
    self._last_finish_reason = None
    self._last_raw_response = None
    
    try:
        raw_response = self._call_llm(report_text, progress_callback)
    except Exception as e:
        last_err_msg = f"{type(e).__name__}: {e}"
        if self._is_retryable_error(e) and attempt < self.max_attempts:
            wait = min(2 ** attempt, 8)   # 2s → 4s → 8s（封顶）
            progress_callback(f"⚠️ LLM 调用失败（{last_err_msg}），{wait}s 后重试...")
            time.sleep(wait)
            continue
        return [], f"调用 LLM 失败（已尝试 {attempt} 次）: {e}"
    
    themes, parse_err = self._parse_response(raw_response)
    # ... 截断警告 ...
    
    if not themes:
        last_err_msg = parse_err or "LLM 返回为空"
        if attempt < self.max_attempts:
            wait = min(2 ** attempt, 8)
            progress_callback(f"⚠️ 题材解析失败（{last_err_msg}），{wait}s 后重试...")
            time.sleep(wait)
            continue
        # 用尽 → 落盘失败上下文
        self._dump_failure(report_text, raw_response, parse_err or "")
        return [], parse_err or "重试用尽：未抽出任何题材"
    
    # 部分或全部成功 → matcher 富化 → 返回
    enrich_themes_with_matcher(themes)
    return themes, parse_err
```

**关键设计：**

1. **重试退避**：第 1/2/3 次重试间隔 `2s/4s/8s`（指数封顶 8s），避开短时抖动
2. **每轮清状态**：`_last_finish_reason / _last_raw_response = None`，避免上次失败结果污染本次解析
3. **部分成功不重试**：4 级容错只要救出至少 1 条题材就直接返回，避免重复入库
4. **UI 反馈**：每次重试前通过 `progress_callback` 推一行红色 ⚠️ 提示，主人看得见

### 3.3 `_is_retryable_error` 判定

**可重试**（典型场景）：
- `httpx` 超时类：`ReadTimeout` / `ConnectTimeout` / `WriteTimeout`
- `httpx` 连接类：`ConnectError` / `RemoteProtocolError` / `ReadError` / `ChunkedEncodingError`
- `openai` SDK：`APITimeoutError` / `APIConnectionError` / `InternalServerError` / `RateLimitError` / `APIStatusError`
- HTTP 状态：`500/502/503/504/429`（按错误消息字符串匹配）

**不可重试**：
- `ValueError`（未配置 API Key 等）
- `AuthenticationError` / `PermissionDeniedError`（401/403）
- `BadRequestError` / `NotFoundError`（400/404，重试也是错）

判定不严格依赖 import openai/httpx 具体异常类——用类名 + 错误消息关键词覆盖三家 SDK（openai/zhipuai/httpx 内核），更稳健。

## 五、配置升级建议

**主人不动 `config/ai_config.json`** 也能享受新行为——`__init__` 内置默认值 `stream_idle_timeout=60 / max_attempts=3`。

如果主人想自定义，参考 `config/ai_config.example.json`：

```json
"theme_extraction": {
  "enabled": true,
  "auto_run": true,
  "provider": "deepseek",
  "model": "deepseek-v4-pro",
  "temperature": 0.2,
  "max_tokens": 65536,
  "stream_idle_timeout": 60,
  "max_attempts": 3,
  "timeout": 1200
}
```

调参指南：
- 报告很长 + max_tokens 拉满 + 模型偶尔卡顿 → `stream_idle_timeout` 可调到 120
- provider 偶发 5xx 严重 → `max_attempts` 调到 5
- 想更快感知断流 → `stream_idle_timeout` 调到 30
