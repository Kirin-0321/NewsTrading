# 手动回测「已存在则覆盖」语义实装

> 报告时间：2026-05-27 16:35  
> 报告人：辉夜  
> 影响版本：Phase 6 GUI 手动回测页（2026-05-27 上线）  
> 影响范围：`tools/backtest_prompt.py` + `gui/pages/manual_backtest_page.py`  
> 严重程度：**Medium**（功能阻断，主人无法重跑同参数回测）

---

## 一、问题现象

主人在 GUI「手动回测」页选定：

| 参数 | 值 |
|------|----|
| 模板 | `三位一体综合分析_2月5日 [custom_1770292858]` |
| 交易日 | 2026-05-22 |
| 新闻窗 | 2026-05-22 14:00 ~ 2026-05-25 09:00 |
| 新闻状态 | curated（精选） |

时间边界预览面板显示 **snapshot 完整 / 实际新闻数 339 / 大盘 md 5500 字符**，
点「正式跑回测」后状态栏却显示：

```
⚠ 跳过：已存在或无新闻
```

snapshot 数据明明完整，却被「跳过」拦下了。

## 二、根因定位

`tools/backtest_prompt.py` 的 `backtest_one()` 在 step 6 调
`_has_existing_backtest(template_id, trade_date)` 检查
`ai_reports` 表是否已有 `(prompt_id=custom_1770292858,
report_date='2026-05-22', is_backtest=1)`，命中后直接返回 `skipped=True`：

```python
# 6. 已存在 backtest 记录且非 overwrite → 跳过
if not overwrite and _has_existing_backtest(template_id, trade_date):
    return _make_result(
        ok=True, snap_news_count=snap.news_count, skipped=True,
    )
```

而 GUI 这边 `manual_backtest_page.py` 调 `ManualBacktestWorker` 时
**硬编码** `overwrite=False`：

```python
self.worker = ManualBacktestWorker(
    ...
    overwrite=False,    # ← 硬编码，主人没有任何开关可改
    dry_run=dry_run,
)
```

结果就是只要曾经跑过同 (template, date) 的回测，第二次永远会被拦死，
主人没法换 prompt 内部参数或修复 bug 后重跑验证。

更糟的是：**旧版** `overwrite=True` 也只是「跳过去重检查继续跑」，
**并不真删旧记录**——会出现同 `(prompt_id, report_date, is_backtest=1)`
多条 `ai_reports` 共存，污染后续打分（同一题材多份重复计入）。

## 三、修复方案

主人决策（2026-05-27 16:30 确认）：

| 决策项 | 选择 |
|--------|------|
| "参数一模一样" 判定维度 | 仅 `(template_id, trade_date)` — KISS |
| GUI 是否露开关 | 加 checkbox，**默认勾选**（既默认覆盖又留逃生口）|
| md 物理文件 | 删除（保持文件系统与 db 一致）|

### 3.1 `tools/backtest_prompt.py` 新增 `_delete_existing_backtest`

依赖 `ai_inference.db` 的 `ON DELETE CASCADE` 链：

```
DELETE theme_predictions  
   → CASCADE theme_stocks / theme_news /  
     theme_prediction_scores / theme_stock_scores
```

操作顺序（事务内）：

1. `SELECT ai_reports.id / file_path WHERE prompt_id=? AND report_date=? AND is_backtest=1`
2. `DELETE FROM theme_predictions WHERE report_path IN (paths)` — 顺手 CASCADE 子表
3. `DELETE FROM ai_reports WHERE id IN (ids)`
4. 事务外物理 `unlink()` `data/AI_analysis/...md`

返回 `{"ai_reports": n, "theme_predictions": n, "md_files": n, "paths": [...]}`，
透传到 `BacktestResult` 的 `overwritten / deleted_reports /
deleted_themes / deleted_md_files` 字段，让 CLI / GUI 都能展示清理统计。

### 3.2 `backtest_one()` step 6 重写

```python
# 6. 已存在 backtest 记录 → overwrite 则删旧重跑，否则跳过
if _has_existing_backtest(template_id, trade_date):
    if overwrite:
        stats = _delete_existing_backtest(template_id, trade_date)
        overwrite_stats.update(...)   # 记到 BacktestResult
        _log.info("overwrite: 清理旧 backtest 记录 ...")
    else:
        return _make_result(
            ok=True, snap_news_count=snap.news_count, skipped=True,
            error="已存在同 (template, date) 的 backtest 记录，"
                  "传 --overwrite 删旧重跑",
        )
```

**注意**：CLI 的 `--overwrite` 默认仍是 `False`，保留批量
`backfill_backtest_samples.py` 不浪费 LLM 的安全语义。

### 3.3 `gui/pages/manual_backtest_page.py` 加 checkbox

放在第 1 行精选新闻 checkbox 旁，分组语义统一为「行为开关」：

```python
self.overwrite_checkbox = QCheckBox("已存在则覆盖")
self.overwrite_checkbox.setChecked(True)   # ← 主人意图：默认覆盖
self.overwrite_checkbox.setToolTip(
    "命中同 (模板, 交易日, is_backtest=1) 时：\n"
    "  勾选 = 删除旧记录(ai_reports + theme_predictions +\n"
    "         子表 + md 文件) 后重跑，得到全新结果\n"
    "  取消 = 直接跳过，保留旧记录（避免无意中重跑浪费 LLM）"
)
```

`_current_inputs()` 增 `overwrite` key，worker 实例化时不再硬编码：

```python
overwrite=inputs["overwrite"],   # ← 读 checkbox
```

`_on_finished()` 命中覆盖时状态栏额外渲染：

```
✅ 成功  news=339 themes=8  4523 ms  
🗑 已覆盖旧记录: -ai_reports=1 -themes=8 -md=1  file=xxx_backtest_20260522.md
```

## 四、影响面 & 数据安全

| 维度 | 评估 |
|------|------|
| 历史数据 | overwrite 只动 `(prompt_id, report_date, is_backtest=1)` 精确匹配的行，**真实日常报告**（`is_backtest=0`）完全不会被误删 |
| 子表完整性 | CASCADE 链已在 `001_initial.sql` 定义且 `PRAGMA foreign_keys=ON` 启用，回归 case_08 验证 theme_predictions 删除后子表自动清理 |
| md 文件 | 仅删 ai_reports.file_path 指向的文件，不存在则跳过；删除失败仅 warn 不回滚 db（不阻断主流程）|
| 事务 | db 操作在单连接 `with adb.connect():` 中执行，异常自动 rollback；md 文件操作在事务外进行（避免 OS 异常影响 db）|
| CLI 兼容 | `tools/backtest_prompt.py --overwrite` 默认仍 False，向后兼容 |
