## 一、这个功能要解决什么问题

主人**每天盘后**要做这一步：

```
打开豆包/DeepSeek 网页 → 把 800 行的"三位一体盘后数据模板"丢进去
→ 等 5~10 分钟 → 复制粘贴到 GUI → 才能开始分析
```

烦点：
- **慢**：等网页 AI 跑模板，至少 5 分钟
- **不准**：输出经常一堆 `{n/a}`，数字偶尔编造
- **不稳定**：同一天跑两次，封板率可能给你两个数
- **不能定时**：必须主人手动点鼠标

**目标**：让电脑自动从 Tushare 把硬数据全拉下来 + AI 只补几个空缺，1~2 分钟出一份盘后总结，自动塞进分析输入框。

## 二、Tushare 10000+ 积分能拿到什么

主人这次升到 10000+ 积分了，**之前所有"高级 API 拿不到"的烦恼全部消失**。下面这张表是 V1 实施后能稳定拿到的数据：

### 🟢 完全自动化、无需 AI

| 数据 | 来自 Tushare 哪个接口 | 说明 |
|------|---------------------|------|
| 大盘指数（上证/深成/创业板/科创50/沪深300） | `index_daily` | 收盘、涨跌幅、成交额 |
| 全市场涨跌停统计 | `limit_list_d` | 涨停数、跌停数、炸板数、封单金额 |
| **完整涨停个股 + 连板高度** | `kpl_list` | 4 板/3 板/2 板/首板各有谁，封板/炸板时间 |
| **板块主力资金净流入** | `moneyflow_ind_dc` | 各板块主力净流入、超大单、大单 |
| 概念板块涨跌 + 龙头股 | `dc_index` + `dc_daily` | 1000+ 个东财板块完整快照 |
| 同花顺概念（备份用） | `ths_daily` | 跨源交叉验证 |
| 北向资金净流入 | `moneyflow_hsgt` | 沪股通/深股通 |
| 龙虎榜个股 | `top_list` | 哪些票上榜、净买入、上榜原因 |
| **龙虎榜机构席位** | `top_inst` | 知名游资营业部明细 |
| 个股行情 | `daily` + `daily_basic` | 龙头股的涨幅、成交额、换手、市值 |

### 🟡 本地计算（不调 API、瞬间出）

| 派生指标 | 怎么算 |
|---------|------|
| **封板率** | 涨停数 / (涨停数 + 炸板数) |
| **晋级率** | 今日连板成功数 / 昨日连板股总数 |
| **炸板率** | 炸板数 / (涨停数 + 炸板数) |
| **连板梯队** | 按 `kpl_list.cons_nums` 自动分组 |
| **昨日涨停今日表现** | T-1 涨停股 join T 日 daily |
| **大小盘对比** | 沪深300/中证500/1000 指数涨跌差 |

### 🟠 只剩这些需要 AI 补全（小空缺）

| 字段 | 为什么要 AI | 来源 |
|------|-----------|------|
| **游资席位别名** | `top_inst` 给的是营业部全称，要映射成"陈小群/作手新一/章盟主"等 | 本地席位字典优先 → AI 兜底 |
| **板块新闻催化（cls 未覆盖的）** | 大部分板块财联社已直接说明，仅小众板块需要 AI 推理 | 本地 `raw_news` + AI 选 |
| **逻辑类型标注**（1~6 级强度） | 定性判断 | AI 看板块名 + 涨幅 + 新闻 |
| **监管异常波动公告** | 公司公告分散在交易所 | AI 联网搜（可选关闭） |

> 💡 **2026-05-26 决策更新**：审计 Tushare 接口时发现 `cls_stock_shock.reason` 字段（财联社编辑人工写的涨停原因）质量极高、覆盖率高，**直接替代了原先「让 AI 推断每只涨停股催化」的环节**。
> 
> 因此 AI 工作量从「补全 100% 的催化字段」骤降到「仅补 10~20% cls 未覆盖的板块」。  
> 实际效果：每次 build 调 AI 不到 1 次，token 消耗 < 500，速度提升 3~5 倍。

### 🔴 永远拿不到（跟积分无关）

| 字段 | 原因 |
|------|------|
| 盘中实时封单（精确到秒） | 收盘后无法还原 |
| 个股 Level2 大单/特大单分层 | 付费数据源 |
| 首板每只票的精确涨停时刻 | 需 tick 数据 |

**这三项 V1 就明确写 N/A，不阻塞**——你的"游资跟随"策略反正不靠这些。

## 三、做完之后你的日常工作流

### 场景 1：盘后手动分析（最常用）

**之前**：
```
你 → 开浏览器豆包 → 粘 800 行模板 → 等 5~10 分钟
   → 复制结果 → GUI 粘到"盘后总结"框 → 点开始分析
```

**之后**：
```
你 → 打开 GUI → 侧栏点【📊 盘后数据】（在"数据导出"和"AI分析"之间）
   → 点【🔄 获取盘后数据】按钮
   → 等 30 秒 ~ 2 分钟（视是否调 AI 补全）
   → 在 6 个 Tab（总览/板块/涨停/龙虎榜/异动/Markdown）里人工核对一遍
   → 点【➡️ 发送到 AI 分析】→ 自动切换到 AI 分析页 + 盘后总结框已填好
   → 点开始分析
```

**变化点**：盘后数据**独立成页**，不再混在 AI 分析页里。这样可以独立查看历史日数据、对比连板梯队、手工核对游资识别，分析前心里有底。

### 场景 2：早晨上班前一键完成

```
你设置定时任务：
  16:00 自动跑爬虫 → 清洗
  16:30 自动拉盘后数据 + 出分析报告
  
第二天早晨 8:00 → 你打开 GUI 直接看昨晚的成品分析
                  题材已自动入库，回测数据也自动累积
```

### 场景 3：补跑历史某一天

```
方式 1（GUI）：盘后数据页 → 改日期 → 点【🔄 获取盘后数据】
方式 2（命令行）：python tools/market_fetch.py 20260512 hybrid

→ 系统自动从 Tushare 拉 5 月 12 日的全部数据
→ 入库到 data/market.db 的 market_summaries 表（含 7 个 Tab 全部数据）
→ GUI 改日期 → 重新点【🔄 获取盘后数据】（命中缓存 0 次 API）
→ 后续接 analyze --auto-market（M4 完成后）出报告
```

### 场景 4：网络不好或 AI 服务挂了

```
GUI 选模式 = "tushare-only（无 AI）"
  → 跳过 AI 补全步骤，只输出 Tushare 硬数据
  → 完整性大约 75%（足够看主线）
  → 游资席位别名等字段标 N/A 但不报错
  → catalysts 字段仍能从 cls_stock_shock 拿到大部分内容（cls 不依赖 AI）
```

## 四、输出长什么样

### 1. 给主人看的 Markdown（compact 模板，约 150~300 行）

```markdown
# 2026-02-12 盘后数据

## 一、市场总览
- 上证 4134.02 (+0.05%) / 深成 14283.0 (+0.86%) / 创业板 3328.06 (+1.32%)
- 两市成交 21400 亿 (↑前日 19800 亿)
- 涨跌家数 2108 / 3280
- 涨停 69 / 跌停 22 / 炸板 21

## 二、情绪指标
| 指标 | 值 | 前日 |
|------|---:|---:|
| 封板率 | 76.7% | 72.0% |
| 晋级率 | 45.5% | 41.2% |
| 炸板率 | 23.3% | 28.0% |
| 最高板 | 4 (雅博股份/电网设备) | 3 |

## 三、北向 / 主力
- 北向净流入 12.5 亿
- 主力净流入 板块前 5：电网设备 +28.5 亿 / AI算力 +21.3 亿 / ...

## 四、板块涨幅 Top 10
| 排名 | 板块 | 涨跌幅 | 5日涨幅 | 涨停数 | 龙头 | 逻辑类型 |
|---:|------|---:|---:|---:|------|------|
| 1 | 小金属 | +2.06% | +18.5% | 8 | 翔鹭钨业(5天3板) | 产业周期拐点 |
| 2 | 电网设备 | +1.85% | +12.3% | 6 | 雅博股份(4连板) | 政策催化 |
| ...

## 五、连板梯队
- 4 板：雅博股份(电网设备)
- 3 板：（无）
- 2 板：章源钨业(小金属) / ...
- 首板：xx只 ...

## 六、龙虎榜
- 英维克 净买入 +1.2 亿（涨幅偏离）
- 知名游资动向：作手新一买入 xxx / 陈小群卖出 yyy

## 七、监管警示（如有）
- 江钨装备：异常波动

## 八、数据完整性
- L1 (Tushare 硬数据): 100%
- L2 (本地派生): 100%  
- L3 (AI 补全): 80%
- 缺失项: 部分板块的"非新闻催化"未识别 (3 个)
```

### 2. 内部数据（给程序用，主人不用看）

**全部存进 `data/market.db` 一个 SQLite 文件**，14 张表分别存：
- 交易日历 / 板块字典 / 个股字典 / 游资别名（维度表）
- 指数日线 / 板块日线 / 涨停个股 / 北向资金 / 龙虎榜 / 龙虎榜机构 / CLS 个股异动 / CLS 板块异动（事实表）
- 盘后总结 / AI 补全 patch（汇总表）

跨日 SQL 查询超快（比如"拉萨天团最近 30 天买过哪些股"一条 SQL 就出），后续回测、Eval、Agent 优化全用它。

**为啥单独建 `market.db` 而不是塞 `news.db`**：行情库每年 1~3GB 增长、可重建；新闻库小且不可重建。物理隔离防止互相影响。

### 3. 怎么注入到 AI 分析

两种路径：

**手动场景**：
- 盘后数据页生成完毕 → 点【➡️ 发送到 AI 分析】→ 自动切到 AI 分析页 + 盘后总结框已填好
- 主人可在 AI 分析页二次微调后再点"开始分析"

**自动化场景**（定时任务）：
- `analyze` 流程加 `auto_market=True` 参数 → 如果 AI 分析页的"盘后总结"框是空的，自动从本地盘后数据缓存读取最新一天的 compact md 注入 `{market_summary}` 占位符
- 如果手填了内容（人工微调过），自动获取不覆盖手填值，**手填永远优先**

## 五、你可以配置的几个开关

写在 `config/ai_config.json` 新增的 `market_fetch` 段（带默认值，不配也能跑）：

```json
"market_fetch": {
  "enabled": true,                       // 总开关
  "default_mode": "hybrid",              // "hybrid"(默认) / "tushare-only" / "ai-full"
  "top_sector_n": 10,                    // Top N 板块详细分析（含 5 日涨幅）
  "ai_enrich_sectors_prompt_id": "ai_enrich_sectors",   // 板块催化补全用哪份 prompt
  "ai_enrich_traders_prompt_id": "ai_enrich_traders",   // 游资识别用哪份 prompt
  "provider": "deepseek",
  "model": "deepseek-v4-pro",
  "raw_news_crossref": true,             // 板块催化是否用本地新闻库匹配
  "search_regulation": false,            // 监管警示是否让 AI 联网搜（默认关，避免幻觉）
  "completeness_warn_threshold": 0.6,    // 低于此值在 GUI 显示黄色警告
  "completeness_block_threshold": 0.3    // 低于此值直接报错（避免分析时拿到太烂的数据）
}
```

主人**不动这些也能跑**，所有默认值都是辉夜挑过的稳妥值。

> 💡 **配套升级（V2 决策）**：AI prompt **全部拆到 `prompts/{类别}/{id}.md`** 单文件管理，原 `ai_config.json` 里 50KB 的 10 个分析模板挪到 `prompts/analysis/*.md`，每个模板能独立 git diff、独立改版本、复用公共片段（新闻分级标准、一日游警告等）。`ai_config.json` 瘦身到 1.5KB，只剩 API key 和默认配置。

## 六、失败时会发生什么（重要）

辉夜对"主流程稳如老狗"有强迫症，所以失败处理列清楚：

| 情景 | 行为 |
|------|------|
| Tushare 网络断了 | 立刻报错，告诉你"网络不可用"，不假装成功 |
| 某个 API 限频 | 自动重试 3 次（间隔 2s/4s/8s），仍失败则该字段标 N/A、继续跑其他 API |
| Tushare token 失效 | 启动时就探测，提前报错，不进流水线 |
| AI 补全服务挂了 | 自动降级到 `tushare-only`，完整性打 0.75 左右照样能用 |
| 指定日期不是交易日 | 自动找最近一个交易日（往前推），并在结果里告知"实际用的是 2026-02-11" |
| 同一天重复跑 | 命中本地缓存，不重复扣 Tushare 积分；除非显式 `--force-refresh` |
| AI 想覆盖 Tushare 的数值（比如 AI 说封板率是 80%，Tushare 说 76.7%） | **拒绝**，记录到 `conflicts` 字段；以 Tushare 为准 |
| 完整性低于 30% | 拒绝出报告，让主人手动检查（默认阈值，可配） |
| 完整性 30%~60% | 出报告但加黄色警告 |

## 七、不做什么（划清楚边界）

为了 V1 别变成"圣母功能"，明确**不做**：

- ❌ 不做盘中实时数据（这是盘后总结，不是行情软件）
- ❌ 不做个股技术指标（MACD/KDJ 等，跟新闻分析无关）
- ❌ 不做完整的 800 行 full 模板（compact 给 AI 注入足够；要 full 我可以加，但默认不开）
- ❌ 不做付费数据源（Level2 等）
- ❌ V1 不做 `eval market` 评估（属于第二批工作，先把数据跑通）
- ❌ V1 不做回测对接（属于 Phase 2，先存好数据）

## 八、施工计划与时间

按辉夜慵懒的工作效率估（兼工作/学业以外的时间）：

| 阶段 | 内容 | 主人能看到什么 | 工期 |
|------|------|---------------|------|
| **M0（Prompt 文件化）** ⭐新增 | 10 个分析模板从 ai_config.json 拆到 prompts/analysis/*.md + PromptLoader 实现 | 现有 AI 分析功能跟以前一致，但 prompt 可单独 diff/改版本 | 2 天 |
| **M1（数据库 + 数据层）** | market.db 14 张表建好 + TushareFetcher 全量入库 + 派生指标 + compact md 渲染 + CLI 调试脚本 | `python tools/market_fetch.py 20260525 tushare-only` 出完整盘后数据入库 | 4 天 |
| **M2（CLS + AI 兜底）** | CLSEnricher + AIEnricher + Validator + 游资别名表初始化 | hybrid 模式可用，板块催化用 cls、游资能识别 | 2 天 |
| **M3（GUI 独立页面）** | 新建"📊 盘后数据"页 + 7 个 Tab + 游资别名编辑器 + 数据库备份按钮 + 发送到 AI 分析联动 | 不开命令行也能用，可视化查看历史数据 | 2 天 |
| **M4（集成）** | `analyze --auto-market` + Scheduler 注册 task type + AI 报告索引表 | 定时任务可挂、AI 分析可自动接入 | 1 天 |
| 总计 | | | **11 天** |

主人觉得急的话 M0 可以先单独发布（跟盘后数据无关，纯粹是 prompt 管理升级）；M1 完成后已经能解决"800 行复制粘贴"这件事的 80%；M3 GUI 完成后即可投产，M4 是 cherry on top。

> ⏱ **比 V1（8~9 天）多 2~3 天**——M0 是一次性大整理，整个项目以后所有 prompt 维护成本骤降；M1 数据库设计给后续 Eval / 回测打底，性价比高。
