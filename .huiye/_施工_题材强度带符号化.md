## 3. 测试用例（实战验证）

### 3.1 单元级（无 LLM）

```python
# tools/_scratch_theme_normalize_test.py
from services.storage.theme_store import _normalize_theme, _score_to_level

# Case 1: 极强利好
t1 = {"theme_name": "X", "strength_score": 95, "reason": "..."}
n1 = _normalize_theme(t1)
assert n1["strength_score"] == 95
assert n1["strength_level"] == "极强利好"

# Case 2: 极强利空（负数）
t2 = {"theme_name": "Y", "strength_score": -85, "reason": "..."}
n2 = _normalize_theme(t2)
assert n2["strength_score"] == -85
assert n2["strength_level"] == "极强利空"

# Case 3: 中性边界
for s in [-19, 0, 19]:
    n = _normalize_theme({"theme_name": "Z", "strength_score": s, "reason": "..."})
    assert n["strength_level"] == "中性", f"score={s} 应该是中性"

# Case 4: 越界裁剪
t4 = {"theme_name": "W", "strength_score": -200, "reason": "..."}
n4 = _normalize_theme(t4)
assert n4["strength_score"] == -100

# Case 5: 缺失默认
n5 = _normalize_theme({"theme_name": "V", "reason": "..."})
assert n5["strength_score"] == 0
assert n5["strength_level"] == "中性"

# Case 6: AI 给出 strength_level 但缺 score（按 level 反推区间中位数）
t6 = {"theme_name": "U", "strength_level": "强利空", "reason": "..."}
n6 = _normalize_theme(t6)
assert -79 <= n6["strength_score"] <= -60
```

## 5. 风险与边界

| 风险 | 处理 |
|------|------|
| AI 不理解新 prompt，仍输出 0-100 | `pick_int(..., -100, 100)` 范围裁剪兜底；但 `sentiment` 不再读取，方向信息可能丢失 → 实测时重点观察 |
| `_score_to_level` 跨区间边界（如 score=20 应该归到"弱利好"还是"中性"？） | 当前区间设计：弱利好 = `[20, 39]`，中性 = `[-19, 19]`，无重叠，20 明确归弱利好 |
| 旧 GUI 代码漏改某处仍读 `sentiment` 字段 | grep 完所有引用已列上面；改完再 grep 一次确认 0 引用 |
| theme_store 中 `SELECT * FROM theme_predictions` 类查询 | 全字段查询无需改；但消费方如果 hardcode 取 `row["sentiment"]` 会炸 → grep 一遍 `["sentiment"]` 和 `.sentiment` |
| 历史 AI 分析报告里残留的 sentiment 词汇 | 那是 md 文件正文，跟字段无关，不影响 |
