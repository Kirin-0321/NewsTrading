# ===== 核心原则 =====

<核心原则>
* **调研充分,实现简洁**: 调研阶段不怕多花时间(全链路梳理现有代码与上下游依赖);实现阶段遵循KISS,简单可维护,不过度设计
* **禁止假设**: 禁止基于假设回答,必须先用工具检索验证
* **第一性原理**: 从最本质的角度分析问题
* **尊重事实**: 尊重事实高于尊重用户;如果用户犯错,直接指出
* **简洁+高效** = 最高优先级
* 拒绝取悦用户式开发,不合理或代价过高的需求要直接拒绝
* 规划时考虑效率、可行性、是否冲突
* 保证性能
* 注释写明输入/输出
* 不搞过度防御性编程
* 写出最优解
* 当多次出现库相关的问题,直接使用Context7查询
</核心原则>

<项目文档分类>

生成或整理 `doc/` 下文档时**必须**遵守以下要点（细节、模板见上述链接文件）：

## doc/ 目录结构
```
doc/
├── bugfix/      # Bug修复、问题排查与解决方案
├── design/      # 设计方案、架构、技术选型、接口设计
├── features/    # 功能说明、增强、实现细节
├── guides/      # 教程、手册、配置、最佳实践、FAQ
├── reports/     # 分析、测试、审查、总结、统计报告
├── updates/     # 版本更新、变更日志、迭代记录
└── 其他/        # 未归类、临时、备忘
```

## 命名格式（月-日-时-简述）
`MM-DD-TT-简述.md`：**TT = 时分**（24 小时制 `HHmm`，如 `0930`）；分类靠目录，文件名不写 bugfix/guide 等前缀

| 目录 | 示例 |
|------|------|
| bugfix/ | `05-23-1430-数据库锁定问题修复.md` |
| design/ | `05-23-0930-工作流引擎架构.md` |
| features/ | `05-23-1605-自动化报告生成.md` |
| guides/ | `05-23-1015-定时任务配置.md` |
| reports/ | `05-23-1800-系统性能分析.md` |
| updates/ | `05-23-1100-v2.1版本说明.md` |
| 其他/ | `05-23-2045-会议纪要.txt` |

同分钟重名：简述后加 `-2`、`-3`。分类冲突优先级：`bugfix > design > updates > features > guides > reports > 其他`

## AI 自动分类（关键词匹配）
| 目录 | 关键词 |
|------|--------|
| bugfix/ | 修复、bug、错误、问题、故障 |
| design/ | 设计、架构、方案、技术选型 |
| features/ | 功能、特性、新增、增强、实现 |
| guides/ | 指南、教程、手册、配置、使用 |
| reports/ | 报告、分析、统计、总结、评估 |
| updates/ | 更新、版本、变更、优化、改进 |
| 其他/ | 其他、杂项、临时、备忘 |
